Local dev setup on Linux: Docker, Tilt and ports

Linux needs no VM, so setup is short. The usual surprises are permissions, versions and ports that are not 80 or 5432.

On Linux, install Docker Engine 25 or newer with the Compose plugin 2.20.2 or newer, add Tilt, install Node 22.12 or newer, and let your user run Docker without sudo. Then run flisk doctor. There is no virtual machine to size, which makes Linux the simplest platform, apart from a few port and permission details.

Install the pieces

  1. Docker Engine and the Compose plugin. Follow the official guide for your distribution, for Ubuntu https://docs.docker.com/engine/install/ubuntu/. Use Docker's own repository rather than an old package from your distribution, because versions matter. Check with docker version and docker compose version.
  2. Start the daemon if it is not running: sudo systemctl start docker. To start it at boot, enable the service as well.
  3. Run Docker without sudo. Follow the post-install steps at https://docs.docker.com/engine/install/linux-postinstall/. They add your user to the docker group; log out and in again afterwards. Note the security trade-off: membership in that group is effectively root access on the machine.
  4. Tilt: curl -fsSL https://raw.githubusercontent.com/tilt-dev/tilt/master/scripts/install.sh | bash. Tilt 0.25 or newer is required.
  5. Node 22.12 or newer, from your preferred version manager.
  6. Flisk: curl -fsSL https://flisk.sh/install.sh | sh, or install the npm package @flisk-sh/flisk.
  7. Check: flisk doctor. It reports missing tools and versions that are too old, with the fix for each.

Omarchy and other distributions work the same way, as long as Docker Engine and the Compose plugin meet the versions above. If you prefer Podman, read Docker Desktop vs Colima vs Podman first, because this guide and Flisk's checks assume Docker.

Ports are not what you expect

A normal user cannot bind ports below 1024 by default, so Flisk does not use 80 and 443. It picks the first free port from 8080 to 8180 for HTTP and from 8443 to 8543 for HTTPS, and prints the result in the output of flisk up and in flisk networks. Services are then reached with URLs of the form http://api.myproject.localhost:8080/. The database defaults to port 15432, not 5432, which is deliberate: it avoids a clash with a Postgres you already run on the host.

If you need fixed ports, for example for a script, set FLISK_HTTP_PORT, FLISK_HTTPS_PORT or FLISK_POSTGRES_PORT. Use them also when you run two projects and want predictable numbers. Read the allocated ports from the tool instead of copying them into documents, as they can change between machines.

Verify the whole path

Start the project with flisk up, copy one URL from its output and request its health path:

curl -i http://api.myproject.localhost:8080/health

Use the port that flisk up printed. A response with status 200 means the service, its route and Docker are all working. If it fails, flisk status shows which resource is unhealthy and flisk logs --service name shows its output.

Keep it reproducible

Linux setups drift because every distribution packages things differently. Record the Docker, Compose, Tilt and Node versions that worked, in the README or in a setup script that only checks and never installs. If you want the team on one Flisk version, pinnedFliskVersion in .flisk/project.json makes a mismatch fail with the exact install command. A CI job as in checking config drift in CI then catches the rest.

Pitfalls

  • Permission denied on the Docker socket. Your user is not in the docker group yet, or you did not log out and in again.
  • Old Compose. A distribution package may ship Compose v1 or an old v2. Install the plugin from Docker's repository.
  • Port already in use. Another program holds a port in the range. Flisk picks a free one, but a fixed variable that you set yourself will fail.
  • Rootless Docker and Podman. Their behavior can differ from standard Docker Engine, and I did not test them. Run flisk doctor and read what it says.
  • Disk. flisk up stops under 5 GiB of free space. Clean images with the usual Docker prune commands before you retry.

When this is not the right setup

If you only work on services that run as local processes, you do not need Docker or Tilt at all. A service with a command in its service.json starts as a plain process, and doctor skips the Docker checks for such projects. Containers add value when you need a database, a message broker or the same runtime as production.

Next step: write the exact commands you ran into your project README, with versions, so the next developer can repeat them. The structure of that README is in document local setup in the README.

Questions people ask

Which Docker versions does it need?

Docker Engine 25 or newer, the Compose plugin 2.20.2 or newer and Tilt 0.25 or newer.

Why are my URLs on port 8080 and not 80?

A non-root user cannot bind low ports, so Flisk picks from 8080 to 8180 for HTTP and prints the number in flisk up and flisk networks.

Why does the database use port 15432?

The default Postgres port is 15432, so it does not collide with a Postgres you already run on 5432.
