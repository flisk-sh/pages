How to run Meilisearch locally with Docker for development

One container, one volume, and two curl calls give you typo-tolerant search to build against.

To run Meilisearch locally, start the getmeili/meilisearch image with MEILI_ENV=development, publish port 7700 on 127.0.0.1 and mount a volume at /meili_data. In development mode it needs no master key and serves a small dashboard at the same address. With Flisk the same container is a bring-your-own service with a few lines of service.json.

The plain Docker way

docker run -d --name dev-meili \
  -p 127.0.0.1:7700:7700 \
  -e MEILI_ENV=development \
  -e MEILI_NO_ANALYTICS=true \
  -v dev_meili_data:/meili_data \
  getmeili/meilisearch:v1.12

MEILI_ENV=development turns off the master key requirement. In production mode Meilisearch refuses to start without a master key of at least 16 bytes, so do not carry the development setting into a deployed environment. MEILI_NO_ANALYTICS stops usage telemetry. Check it is up with curl http://127.0.0.1:7700/health, which returns {"status":"available"}.

Index and search with curl

curl -X POST 'http://127.0.0.1:7700/indexes/movies/documents' \
  -H 'Content-Type: application/json' \
  --data-binary '[
    {"id": 1, "title": "The Matrix"},
    {"id": 2, "title": "Matilda"},
    {"id": 3, "title": "Metropolis"}
  ]'

curl -X POST 'http://127.0.0.1:7700/indexes/movies/search' \
  -H 'Content-Type: application/json' \
  --data-binary '{"q": "matrx"}'

The first call creates the index if it does not exist and infers id as the primary key. The second tolerates the typo and returns "The Matrix". Both write and search are plain HTTP and JSON, so any language works without a client library.

Writes are asynchronous

The document call does not return the documents. It returns a task, something like {"taskUid": 0, "status": "enqueued"}. Indexing happens in the background, and a search sent a few milliseconds later may return nothing. Poll the task before you assert on results:

curl http://127.0.0.1:7700/tasks/0

Wait until status is succeeded. If it is failed, the error field says why. This one habit explains most "my document is missing" reports, and it matters in tests: wait for the task, do not sleep for a fixed time.

The Flisk way

Meilisearch is not one of Flisk's built-in frameworks, so it is a bring-your-own resource. Create the folder with the CLI, then fill in the file:

flisk resource search --type bring-your-own --image getmeili/meilisearch:v1.12 --no-proxy --stack shop --yes

This writes services/shop/search/service.json with a port from the 4000 to 5999 range. The 1.4.57 release I tested refuses --port outside that range for this type, so set the real port by editing the file. The result:

{
  "appName": "search",
  "appType": "bring-your-own",
  "stack": "shop",
  "port": 7700,
  "image": "getmeili/meilisearch:v1.12",
  "exposeViaProxy": false,
  "healthCheck": { "port": 7700 },
  "extraPorts": [{ "port": 7700 }],
  "volumes": [{ "source": "search-data", "target": "/meili_data" }],
  "env": { "MEILI_ENV": "development", "MEILI_NO_ANALYTICS": "true" },
  "provides": { "MEILI_URL": "http://search:7700" }
}

flisk config verify accepted this file. Each piece does one job. healthCheck is a TCP probe, so Flisk waits until the port accepts connections. extraPorts publishes 7700 on 127.0.0.1 only, so you can use curl and the dashboard from your machine. volumes keeps the index across flisk down. provides hands MEILI_URL to every service that lists search in dependsOn, and the address is the Docker-network one, http://search:7700.

"appName": "api",
"dependsOn": ["search"]

Then run flisk up shop, and read logs with flisk logs --service search --tail 50 if the container does not become healthy.

Pitfalls

  • Version changes need a dump. Meilisearch data written by one release is not readable by a different one. When you change the image tag, export a dump from the old version and import it into the new one, or delete the volume and reindex from your database.
  • Primary key guessing. If your documents have no field ending in id, indexing fails until you pass primaryKey when creating the index.
  • Filtering and sorting need settings. Fields must be listed in filterableAttributes or sortableAttributes before you use them, and changing them triggers a reindex.
  • Do not publish a no-key instance. Development mode has no authentication. Keep the port on 127.0.0.1.

When not to use it

If you have a few thousand rows and need simple matching, Postgres can do the job without another service. See Postgres full-text search before a search engine.

Questions people ask

Do I need a master key to run Meilisearch locally?

Not in development mode. With MEILI_ENV=development the server starts without one. In production mode it refuses to start without a master key of at least 16 bytes.

Why does my search return nothing right after indexing?

Indexing is a background task. The write call returns a task id, and the documents appear only after that task has succeeded. Poll the task endpoint before searching.

Can I use a different port than 7700 with Flisk?

Yes. In the release I tested, the CLI only accepted 4000 to 5999 for --port on a bring-your-own resource, so edit port in the generated service.json instead.
