How to publish an HTML page for free

Three free ways to turn a local index.html into a public link: a one-command publisher, GitHub Pages and Cloudflare Pages. Pick by how much setup you want and whether you need your own domain.

The fastest way to put a single HTML file online is a publisher that takes the file and returns a link, such as npx -y @flisk-sh/pages publish page.html --wait. If you want the page to live next to your code, use GitHub Pages or Cloudflare Pages instead.

Option 1: one command, no account setup in your repo

Flisk Pages publishes an agent-built page or Markdown file to a free public link. It is public by design, so treat the content as something you would put on a blog.

npx -y @flisk-sh/pages publish page.html --wait

Use this for demos, reports, prototypes and anything an AI agent generated that you want to share in a chat message. It is not a place for a server, a database or private data.

Option 2: GitHub Pages

Push the file to a repository, then enable Pages in the repository settings and choose to deploy from a branch or from a GitHub Actions workflow. The site appears at a github.io address.

git init
git add index.html
git commit -m "first page"
git branch -M main
git remote add origin git@github.com:YOU/my-page.git
git push -u origin main

It is free for public repositories, and static only. See hosting a static site on GitHub Pages for the Actions variant.

Option 3: Cloudflare Pages

Put your files in a folder and deploy it with Wrangler. The first deploy creates the project.

npx wrangler pages deploy ./site --project-name my-page

You get a pages.dev address and a fast global CDN. The full walkthrough is in deploying a static site to Cloudflare Pages.

How to choose

  • Just sharing once: the one-command publisher.
  • A project that will change often: GitHub Pages or Cloudflare Pages, so every change is a commit.
  • Need a custom domain: either of the last two, see adding a custom domain.

A single file is enough

A page does not need a framework. One index.html with inline CSS publishes anywhere, loads fast and is easy for an agent to regenerate. If the page needs images, keep them in the same folder and use relative paths. If it needs data, embed it in the HTML as JSON rather than calling an API that may be down. Fewer moving parts means fewer ways for the link to break a month later. Keep a copy of the source in Git so you can republish after an edit.

Pitfalls

  • Absolute paths like /style.css break when a site lives under /repo-name/. Use relative paths.
  • A file called index.html must exist at the root of what you publish.
  • Everything you publish is readable by anyone with the link, and often by search engines. Read what not to publish first.

Questions people ask

Can I publish a page without creating an account?

It depends on the host. GitHub Pages and Cloudflare Pages need an account. Check the Pages site for what its publish command needs from you.

Is free hosting really free?

Static hosting on GitHub Pages and Cloudflare Pages has free tiers with usage limits. Check each provider's current limits before you rely on them for high traffic.
