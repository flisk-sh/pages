Node.js local development setup

Run TypeScript in Node.js without a build step

For local development you can skip the compile step. Node strips types itself in current releases, and tsx covers the rest.

On Node 22.18 or later (and Node 23.6 or later) you can run node src/server.ts directly. Node removes the type annotations and runs the JavaScript that is left. On older versions use tsx: npx tsx src/server.ts. In both cases, run tsc --noEmit separately, because neither runner checks your types.

What type stripping does and does not do

Node's feature is called type stripping. It erases types from the file and does nothing else: no type checking, no transforms, no reading of tsconfig.json. That keeps it fast and predictable, but it limits what syntax works.

  • Supported: type annotations, interface, type, generics, import type, as casts.
  • Not supported, because they produce runtime code: enum, namespace with values, constructor parameter properties (constructor(private x: number)).
  • Import paths must name the real file, so write import { db } from "./db.ts" with the .ts extension.
  • Type-only imports need the type keyword: import type { User } from "./types.ts". Otherwise Node tries to import a value that does not exist.
  • Files inside node_modules are not stripped, so libraries must ship JavaScript.

Older Node releases that have the feature behind a flag need node --experimental-strip-types src/server.ts. If you are unsure which behaviour your version has, run node -v and test with a one-line file.

Let TypeScript enforce the same rules

Add these options to tsconfig.json so the editor and tsc warn about anything Node cannot run:

{
  "compilerOptions": {
    "target": "esnext",
    "module": "nodenext",
    "noEmit": true,
    "erasableSyntaxOnly": true,
    "allowImportingTsExtensions": true,
    "verbatimModuleSyntax": true,
    "strict": true
  }
}

erasableSyntaxOnly (TypeScript 5.8 and later) flags enums and parameter properties. verbatimModuleSyntax forces you to write import type where needed. Then add scripts:

{
  "scripts": {
    "dev": "node --watch src/server.ts",
    "typecheck": "tsc --noEmit",
    "build": "tsc -p tsconfig.build.json"
  }
}

When to use tsx instead

Reach for tsx when your Node is older than 22.18, when the code uses enum, path aliases from tsconfig or extensionless imports, or when you need decorators. tsx watch src/server.ts gives you restarts too, and it handles both ESM and CommonJS. Another choice is Bun, which runs TypeScript natively: see Bun and Hono API.

For production, most teams still compile. A build gives you plain JavaScript, so the runtime does not depend on a flag or a loader, and it catches type errors in CI. Treat direct .ts execution as a development convenience unless you have tested it on your production Node version.

Use it in a Flisk service

For a service with a command, the command is the run script, so the choice is yours:

{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "orders-api",
  "appType": "backend",
  "command": "node --watch src/server.ts",
  "port": 4000,
  "healthCheckPath": "/health"
}

Replace the command with npx tsx watch src/server.ts on an older Node. Flisk supervises the process and passes PORT, but it does not type check or compile anything for local-process services. Add the typecheck to your pre-commit hook or CI. If you want the Docker route, Flisk generates the container configuration for its scaffolded services, which is a separate path from this one.

Pitfalls

  • "Unknown file extension .ts". Your Node is too old for stripping, or a flag is missing. Check node -v or switch to tsx.
  • Runs but behaves oddly with enums. You are probably on a runner that transforms them while your production build does not. Keep erasableSyntaxOnly on.
  • No type errors at runtime. Right, there are none. Run tsc --noEmit --watch in a second terminal, or in the editor.
  • Debugging. Stripping keeps line positions, so breakpoints line up. See debugging with --inspect.

Next step

Pin the Node version so every machine has the feature: use a different Node.js version per project.

Questions people ask

Can Node run TypeScript files directly?

Yes. Node 22.18 and later, and 23.6 and later, strip types by default, so node file.ts works for files that use only erasable syntax.

Does node file.ts check my types?

No. It only removes the annotations. Run tsc --noEmit to check types.

When do I still need tsx or a build step?

Use tsx for older Node versions or syntax Node cannot strip, such as enums. Compile for production if you want plain JavaScript and CI type checks.
