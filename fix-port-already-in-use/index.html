How to fix "port already in use" in local development

The error is always the same: something else listens on the port you asked for. Here is how to find it and what to change.

Find out what owns the port, then either stop that process or move your service to another port. On macOS and Linux, lsof -nP -iTCP:5432 -sTCP:LISTEN prints the program and its process ID. Flisk can also pick free ports for you: if 80, 443 or its Postgres port are busy, it chooses others and prints them.

Find the process that holds the port

The error means something is already listening on the address your service wants. Often it is an old copy of your own app, a database installed on the host, or a container from another project. Use the tool for your system:

# macOS and Linux
lsof -nP -iTCP:5432 -sTCP:LISTEN

# Linux, if lsof is missing
ss -ltnp | grep ':5432'

# Windows (cmd)
netstat -ano | findstr :5432

If the owner is a stale process of yours, stop it. If it is a system service such as a Postgres you installed years ago, you can either stop that service or give your project another port. If the owner is a Docker proxy, a container has published the port, so list running containers with docker ps and stop the right one. Do not kill things you cannot name.

Change the port in Compose

In a Compose file, the left side of "5432:5432" is the host port and the right side is the container port. Change only the left side:

services:
  db:
    image: postgres:17
    ports:
      - "5433:5432"

Containers on the same Compose network still reach the database on 5432, because that is the container side. Only your host tools need to use 5433. Remember to update any connection string on the host.

What Flisk does with busy ports

Flisk asks for ingress ports 80 and 443 and uses 15432 for its Postgres, so it does not collide with a host database on 5432. If its ports are taken, it picks free ones from fixed ranges and prints them: 8080 to 8180 for HTTP, 8443 to 8543 for HTTPS and 15432 to 15532 for Postgres.

To choose yourself, set an environment variable before flisk up:

FLISK_HTTP_PORT=18080 FLISK_HTTPS_PORT=18443 FLISK_POSTGRES_PORT=15500 flisk up

An explicit value is not negotiated. If the port you named is busy, Flisk stops with a message such as FLISK_HTTP_PORT=18777 is already in use. Choose a free host port and retry. and does not fall back. If the whole Postgres range is full, you get No available host port in 15432-15532 for postgres, because the ranges are fixed.

Other messages you may meet:

  • Traefik cannot bind ingress ports because another container already owns them: another container, often from a second stack, holds 80 or 443. Stop it or set the ports above.
  • Ports Flisk needs are taken from flisk doctor, with a lsof hint for the exact port.
  • The Tilt UI port, 10350, moves to the next free port by itself.

If you do not need the gateway at all, flisk doctor --no-gateway skips the 80 and 443 checks, and flisk up --no-gateway works when the project turns the gateway off in its capabilities.

Services that run as local processes

For services with a command and no Docker, Flisk checks the port before it starts anything. It refuses to run and names the process:

Port 4000 for service "api" is already in use by node (pid 48211). Stop it, or change "port" in the service.json.

It also refuses when two services declare the same port. The fix is the one the message gives: stop the process, or edit port in that service.json. See running services without Docker for the rest of that mode.

Pitfalls

  • Two container services with the same --port get no warning when you scaffold them, and the container path does not check it at flisk up either. Keep your own list when you create resources.
  • Colima. If flisk up reports UP_URL_UNREACHABLE or says nothing listens on the gateway port, the VM's port forwarder may have stalled. Run colima restart. Check port 80 with lsof -nP -iTCP:80 -sTCP:LISTEN; on Colima the listener shows as limactl.
  • Another Flisk project. Two stacks cannot both own port 80. Run one at a time, or let the second one pick from the fallback ranges.
  • Leftover networks. Docker can run out of address pools after many stacks. flisk down --prune-networks or flisk doctor --fix clears unused ones.

Once the port is free, flisk status shows which URL each service answers on. If the cause was a stack you forgot about, read how to stop and clean up a local stack so the next session starts clean.

Questions people ask

How do I see what is using a port?

On macOS and Linux run lsof -nP -iTCP:PORT -sTCP:LISTEN. On Linux ss -ltnp also works. On Windows use netstat -ano | findstr :PORT.

Why does Flisk use 15432 for Postgres?

So it does not collide with a Postgres already running on the host at 5432. If 15432 is busy, it picks another port between 15432 and 15532.

Can I set the ports Flisk uses?

Yes. Set FLISK_HTTP_PORT, FLISK_HTTPS_PORT or FLISK_POSTGRES_PORT before flisk up. An explicit value that is already in use is an error, with no fallback.
