Email and notifications in local dev

How to send email from Node.js to a local SMTP server

One transport function, driven by environment variables, is enough to send to a local inbox on your laptop and to a real provider in production.

To send email from Node.js to a local inbox, create a Nodemailer transport with the catcher's host and port (for Mailpit, localhost and 1025), turn off TLS and authentication, and read all of it from environment variables. The same code then works in production when you set the provider's values instead.

The transport

Keep the transport in one file so the rest of the app never knows where mail goes:

import nodemailer from "nodemailer";

const port = Number(process.env.SMTP_PORT ?? 1025);

export const transport = nodemailer.createTransport({
  host: process.env.SMTP_HOST ?? "localhost",
  port,
  secure: port === 465,                 // implicit TLS only on 465
  ignoreTLS: process.env.SMTP_TLS === "off",
  auth: process.env.SMTP_USER
    ? { user: process.env.SMTP_USER, pass: process.env.SMTP_PASS }
    : undefined,
});

Why these options:

  • secure: true means TLS from the first byte, which only port 465 uses. Port 587 starts plain and upgrades with STARTTLS, so secure stays false there. Mixing these up is the most common cause of a hang or an "wrong version number" error.
  • ignoreTLS: true tells Nodemailer not to try STARTTLS even if the server offers it. A default Mailpit does not offer it, so you can leave this off locally, but setting SMTP_TLS=off in your dev environment makes the intent explicit.
  • If SMTP_USER is unset, no auth block is sent. A local catcher needs no credentials.

Sending a message

await transport.sendMail({
  from: "App <no-reply@example.test>",
  to: "ada@example.test",
  subject: "Reset your password",
  text: "Open this link to reset it: http://localhost:3000/reset?token=abc",
  html: "<p>Open <a href=\"http://localhost:3000/reset?token=abc\">this link</a> to reset it.</p>",
});

Always send a plain text part next to the HTML. Mailpit shows both, and a missing text part is a real deliverability problem. Use a reserved test domain such as example.test or example.com for addresses you invent, so a misconfiguration can never mail a stranger.

Attachments work the same way: pass an attachments array with a filename and either a path or a content buffer. Open the message in the inbox and download the file to confirm that the name and type came through intact. This catches the common mistake of attaching a stream that was already read.

Run it against Mailpit

Start a catcher (see how to run Mailpit), set the variables and run your script:

SMTP_HOST=localhost SMTP_PORT=1025 node send.mjs

Open http://localhost:8025 and the message is there. If you only want to check what Nodemailer would send, without any server, the built-in jsonTransport: true option returns the message as JSON, which suits unit tests. It does not exercise a socket, so keep at least one test that talks to a real catcher.

Check the connection early

Nodemailer can test a transport before you send anything. Call it once at startup in development, so a wrong host or port is reported when the server boots and not when a user clicks "forgot password":

try {
  await transport.verify();
  console.log("SMTP ready");
} catch (err) {
  console.error("SMTP not reachable:", err.code, err.message);
}

Errors carry useful fields. err.code is ECONNECTION or ESOCKET for network problems, and err.responseCode holds the SMTP reply code when the server answered. A 4xx code means "try again later", a 5xx means the server refused the message. That distinction decides whether a retry makes sense.

With Flisk

If the Mailpit resource from the earlier article is in your stack and your API lists it in dependsOn, the API container receives SMTP_HOST and SMTP_PORT from the mail resource's provides block (the host is the resource name, mail). The transport above needs no change: it reads those variables. Create the API as usual:

flisk resource api --type backend --framework express --stack main --yes

Then add "dependsOn": ["mail"] to services/main/api/service.json. To send a one-off message from inside the running API container with its environment, use flisk run api -- <your command>; see running a one-off command in a service. If the API runs as a local process rather than a container, use localhost and the published port instead.

Pitfalls

  • Connection refused from a container. localhost is the container, not your laptop. Use the resource name.
  • Sending inside the request. An SMTP call can be slow or fail. For anything beyond a demo, queue the email and send it from a worker, as in sending email from a worker with retries.
  • Production values in .env. Do not copy a real provider key into your dev environment. See how to stop dev from emailing real users.

Questions people ask

Why does Nodemailer hang when connecting to my local server?

Usually the TLS setting does not match the port. Use secure: true only for port 465. For a plain local catcher on 1025, keep secure false.

Do I need authentication for Mailpit?

No. A default Mailpit accepts mail without a username or password. Only set auth if your client library refuses to connect without it, and then enable MP_SMTP_AUTH_ACCEPT_ANY on Mailpit.

Can I test Nodemailer without a server?

Yes, jsonTransport and streamTransport build the message without sending it. They suit unit tests, but they never open an SMTP connection.
