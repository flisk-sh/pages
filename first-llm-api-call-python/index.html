Your first LLM API call in Python, with a free local model

Call a language model from Python in ten lines, using a free local Ollama model and the OpenAI-compatible client. Learn the parts of a request and what to check.

Install Ollama, pull a small model, then point the openai Python package at http://localhost:11434/v1 with any non-empty string as the API key. The same code later works against a hosted endpoint by changing the base URL and model name.

Set up the model

Install Ollama from its website, then pull a small model. Pick a current small instruct model from the Ollama library and check its name there, since the list changes.

ollama pull llama3.2
ollama run llama3.2 "Say hello in five words"

If that answers, the model is running. Ollama serves an API on port 11434. See local LLM models for how to choose one.

The call

pip install openai

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="local")

resp = client.chat.completions.create(
    model="llama3.2",
    messages=[
        {"role": "system", "content": "You are a concise assistant."},
        {"role": "user", "content": "Explain a JWT in two sentences."},
    ],
    temperature=0,
)
print(resp.choices[0].message.content)

What each part does

  • messages: the conversation. The system message sets behaviour, user messages are the task, assistant messages are earlier replies.
  • model: the exact name your server knows.
  • temperature: lower means more repeatable. Use 0 for tests and extraction.
  • The reply: choices[0].message.content, plus resp.usage with token counts if the server reports them.

The model has no memory. If you want a follow-up, send the earlier messages again, and append the new reply to your list each time. Print resp.usage in your first week. Seeing that a long conversation costs more tokens on every turn teaches a lot about cost, and you will use that later when you tune a prompt.

Make it a little more real

Add a timeout and an error path, because networks fail and models time out. Then stream the answer so output appears as it is produced, which matters for anything a person waits on:

stream = client.chat.completions.create(
    model="llama3.2", stream=True,
    messages=[{"role": "user", "content": "List three uses of a queue."}],
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)

Next step and a hosted option

The next step is making the model return JSON you can parse. See prompts and structured outputs. If you do not want to run a model on your laptop, Flisk Inference at inference.flisk.si is a free open-beta model API with a coding-focused open model called Flisk Wolf. You sign in with GitHub, and there is a daily request limit, so treat it as a place to learn, not production. Check its page for the current setup. After this, go on to your first agent.

Questions people ask

Why does the API key not matter locally?

The client library requires a value, but a local server does not check it. Use any non-empty string and never commit a real key.

My laptop is slow. What can I do?

Use a smaller model or a more compressed variant, shorten the prompt, or use a hosted endpoint for the heavy calls.
