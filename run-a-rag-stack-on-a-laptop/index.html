RAG and vector databases locally

How to run a full RAG stack on your laptop with Docker

A RAG app is a few small services: a vector store, an embedding model, an ingestion job and an API. Here is how to start them together and check each one.

A local RAG stack has four parts: a vector database, an embedding model server, an ingestion job that fills the database, and an API that embeds a question and returns the nearest chunks. With Qdrant and Ollama, all four run on a laptop with no paid API. This article starts them together and shows how to verify each link.

The parts and how they talk

  • Vector store (Qdrant): holds chunk vectors and their text.
  • Embedding server (Ollama with nomic-embed-text): turns text into vectors, for both documents and questions.
  • Ingestion job: reads documents, chunks, embeds, upserts. Runs on demand.
  • API: receives a question, embeds it with the same model, queries the store, and returns chunks. It can then call a chat model to write the answer.

The key rule is that the document side and the question side use the same embedding model. Most broken local setups violate it.

Without Flisk

You can write a Compose file with Qdrant, Ollama and your own service, mount two volumes and add health checks and depends_on conditions, see Compose depends_on and healthchecks. That is a fine answer, and it works.

The Flisk way

Inside a Flisk project, create the pieces in one stack named rag:

flisk resource vectors --type database --framework qdrant --stack rag --yes
flisk resource embed --type inference --stack rag --yes
flisk resource api --type backend --stack rag --yes

The first command runs Qdrant with a data volume and gives its dependents QDRANT_URL. The second runs the ollama/ollama image, reachable by other services at http://embed:11434. The third is a Bun and Hono API; use --language python for a FastAPI one instead. Edit the API's service.json to wait for the other two:

{
  "appName": "api",
  "appType": "backend",
  "stack": "rag",
  "port": 4000,
  "dependsOn": ["vectors", "embed"],
  "healthCheckPath": "/health"
}

Give the Ollama resource a volume for its models, as shown in generating embeddings locally with Ollama, otherwise the model is lost whenever the container is recreated. Then:

flisk config verify
flisk up rag
flisk run embed -- ollama pull nomic-embed-text
flisk status

flisk config verify checks the files before Docker is involved. flisk status lists the services, their URLs and their health. If one is not healthy, flisk logs --service embed --tail 50 prints its recent log lines. This stack needs Docker, because Qdrant and Ollama are containers, and Flisk does not mix local processes and containers in one project yet.

Verify each link, in order

  1. Qdrant answers: open its dashboard on http://127.0.0.1:6333/dashboard.
  2. Ollama has the model: flisk run embed -- ollama list.
  3. Create the collection with the model's size (768), then run ingestion, see ingesting documents.
  4. Ask the API a question you know the answer to and read the returned chunks before you add a chat model.

The retrieval half is local and free. For the answering half you either point the same API at a chat model served by another inference resource, or call a hosted API with a key in your .env, never in service.json.

Pitfalls

  • Memory. Ollama, Qdrant and your API all need RAM. If containers get killed, raise the Docker VM memory before suspecting your code.
  • First start is slow. Images and the model download once. Do not read that as a hang.
  • Chat model on a Mac container. A container on macOS cannot use the GPU, so a large chat model is slow in it. Embeddings are fine on a CPU.

Once it works, add a quality check from testing retrieval quality, and decide if the vector store should be Qdrant at all with the comparison of Chroma, Qdrant and pgvector.

Questions people ask

What do I need to run RAG locally?

A vector database, an embedding model server, an ingestion job and an API. Qdrant plus Ollama is a common free combination that runs in Docker on a laptop.

Does the question have to use the same embedding model as the documents?

Yes. Vectors from different models are not comparable, so the API must embed questions with the model used at ingestion.

Can this run without Docker?

Qdrant and Ollama can each run as a native program on the host, but the Flisk preset for them uses containers, so this stack needs Docker.
