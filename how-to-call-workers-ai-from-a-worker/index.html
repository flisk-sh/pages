How to call Workers AI from a Worker

Add the AI binding, run a text model from your handler, return the result and keep usage under control, plus when a different model API makes more sense.

Add an [ai] binding to wrangler.toml, then call env.AI.run(model, input) from your handler. No API key is needed in your code because the binding is tied to your account.

Add the binding

[ai]
binding = "AI"

Then deploy or run wrangler dev. The AI binding calls Cloudflare's network even in local dev, so you must be logged in.

Run a text model

export default {
  async fetch(request, env) {
    const { question } = await request.json();
    const out = await env.AI.run("@cf/meta/llama-3.1-8b-instruct", {
      messages: [
        { role: "system", content: "Answer in two sentences." },
        { role: "user", content: question },
      ],
    });
    return Response.json({ answer: out.response });
  },
};

The model catalogue changes. Look up current model names in the Workers AI docs rather than trusting an old example, including this one.

Stream the answer

For chat, pass stream: true and return the stream so users see text arrive.

const stream = await env.AI.run(model, { messages, stream: true });
return new Response(stream, {
  headers: { "content-type": "text/event-stream" },
});

Guard it

  • Limit input length and require a login or a token. An open AI endpoint is an open invoice.
  • Rate limit per user or IP, for example with a KV counter or D1 table.
  • Validate model output before using it. If you ask for JSON, parse it and handle failure, see structured outputs.

Test the call locally

npx wrangler dev
curl -s -X POST http://localhost:8787 \
  -H "content-type: application/json" \
  -d '{"question":"What is a Worker?"}'

If you get an authentication error, run npx wrangler login again. If the model name is rejected, check the catalogue. Keep prompts in a constant at the top of the file so you can change and review them like code, see prompts and structured outputs.

Log token or request counts per user, so you can see who is driving usage. A simple D1 table with user, day and count is enough to enforce a daily cap in code before the model call.

When to use something else

Workers AI offers a set of open models with simple billing on your Cloudflare account. If you need a specific model or a bigger one, call another API with fetch and keep its key in a secret. For a free coding-focused model API, Flisk Inference is in open beta with a daily request limit and GitHub sign-in. It is a beta service, so do not build anything critical on it yet.

Questions people ask

Do I need an API key for Workers AI?

Not inside a Worker. The binding authorises calls through your account. For calls from outside a Worker you use the REST API with a token.

Is Workers AI free?

There is a free allowance with limits, and paid usage beyond it. Check the current pricing page.
