How it works

  1. StartYour start date is the day you received this link. The repository you submit must be new: created on or after that day.
  2. WorkDo the four exercises below and push as you go. Using an AI assistant is allowed; record what really happened.
  3. Check and sendRun the self-assessment at the bottom as often as you like. When it says Accepted, reply with your repository link.

Deadline: 23:59 UTC on the second day after your start date.

Exercises

1

First run

Run npx @flisk-sh/flisk demo twice, then once with Docker stopped.

DeliverLOG.md, heading # Lab 1: three timings and three points of friction.

2

Build

Run flisk project agent-stack, then cd flisk-agent-stack && rm -rf .git && git init so the work is your own history. Add flisk resource my-api --type backend --stack agents --yes, then flisk up.

DeliverHealthy flisk status --json under # Lab 2. A README linking flisk.sh and the Flisk repository. No hand-written container files. Pushed to your new public repository.

3

Diagnose

Introduce three faults. Find each with flisk doctor, flisk config verify or flisk logs.

DeliverA table under # Lab 3: fault, symptom, command, fix, minutes. Three rows.

4

Contribute

Open a pull request to flisk-sh/flisk, with at least one test of your own.

DeliverThe PR link under # Lab 4, and GTM.md with three numbered answers: first 100 users, three integrations, one step this week.

House rules
  • Commit with git commit -s.
  • Do not commit .env, node_modules or generated Flisk files (the starter's .gitignore already excludes them).
  • Star the Flisk repository.
