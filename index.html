Flisk candidate test

flisk.sh · github.com/flisk-sh/flisk

The rules. Do 4 labs in a public GitHub repo. Check your own score below. 100/100 is the only pass. You have 2 days: until the end of the 2nd day after you got this link (UTC). Then reply with your repo link. We read nothing else.

Start

Install Flisk, create a new public repo after you got this link, and keep two files in it: LOG.md (your notes) and GTM.md. Star flisk-sh/flisk. Commit with git commit -s. Never commit .env.

Each lab has a prompt. Paste it into Claude Code (or any AI tool) and let it help; you still run it and write down what really happened.

The labs

Lab 1: First five minutesRun npx @flisk-sh/flisk demo twice, then once with Docker stopped. In LOG.md under # Lab 1: three timings and three things that confused you.
Lab 2: Build a small systemRun flisk project agent-stack, add one resource of your own (flisk resource my-api --type backend), run flisk up and flisk status --json. Section # Lab 2: paste the healthy status. Do not hand-write container files.
Lab 3: Break it, then fix itBreak your system 3 ways (wrong port, missing env var, a service that starts too early). Find each with flisk doctor --json, flisk config verify --json or flisk logs. Section # Lab 3 with a table: fault | symptom | command | fix | minutes (at least 3 rows).
Lab 4: Make Flisk betterOpen a pull request to flisk-sh/flisk (a fix, a doc, a test, an integration). Add at least one test file in your repo for what you built. Section # Lab 4: link the PR and say why it matters.
Go-to-marketGTM.md with exactly three numbered answers: 1) how you would get the first 100 to 500 real users, 2) which 3 AI or developer tools to integrate first and why, 3) one step we can take this week.
