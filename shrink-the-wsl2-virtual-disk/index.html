How to shrink the WSL2 virtual disk (ext4.vhdx) and free C: space

The WSL2 disk file grows when you write data and does not shrink when you delete it. Here is how to get the space back.

WSL2 stores each distribution in a virtual disk file called ext4.vhdx that grows as you write and does not shrink when you delete files. To get space back on C:, free it inside Linux, run wsl --shutdown, then compact the file with diskpart, or turn on sparse mode for the distro so it shrinks by itself.

Why deleting files does not help

From Windows, the disk is one big file. Linux marks blocks free inside it, but the file keeps its size until something compacts it. Docker images, build caches, node_modules and database volumes are the usual source of growth. Docker Desktop has its own virtual disk as well, so there can be two big files to deal with.

Step 1: free space inside Linux first

Compacting only reclaims space that is already free in the guest. Remove what you do not need:

df -h /
docker system df
docker system prune
sudo apt clean

Read the prompt before you confirm a prune. docker system prune removes stopped containers, unused networks and dangling images; add --volumes only if you are sure you do not need unused volumes, because that deletes database data. The guides on Docker disk full and stopping and cleaning up a local stack go deeper.

Step 2: back up

Compacting and sparse mode both modify your only copy of the Linux filesystem. Export a backup to a drive with room:

wsl --export Ubuntu D:\backup\ubuntu.tar

Use the distro name shown by wsl -l -v. Push your repositories to a remote as well.

Step 3: find the disk file

In PowerShell, list where each distro keeps its files:

Get-ChildItem HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss | ForEach-Object { Get-ItemProperty $_.PSPath } | Select-Object DistributionName, BasePath

The ext4.vhdx file is in the BasePath folder (for a Store install it is under %LOCALAPPDATA%\Packages\...\LocalState). Docker Desktop's disk is a separate file under %LOCALAPPDATA%\Docker\wsl.

Step 4: compact it

Shut WSL down completely, then run diskpart in an administrator terminal:

wsl --shutdown
diskpart

At the DISKPART> prompt:

select vdisk file="C:\path\to\ext4.vhdx"
attach vdisk readonly
compact vdisk
detach vdisk
exit

It may take several minutes. Compare the file size before and after. If you have the Hyper-V PowerShell module (Windows Pro and up), Optimize-VHD -Path "C:\path\to\ext4.vhdx" -Mode Full does the same.

Option: sparse mode

Recent WSL versions can keep a distro's disk sparse so freed space returns to Windows automatically:

wsl --manage Ubuntu --set-sparse true

This needs a current WSL (wsl --update), and some releases flagged the feature as having risks with data loss, so take the backup first and read the current WSL release notes. If the command is not recognised, you are on an older WSL and diskpart is the way.

Where Flisk fits

flisk doctor includes a disk space check and a Docker build cache check, so it can tell you before a long flisk up that the disk is the problem. Run it inside Ubuntu, where those checks look at the Linux filesystem and your Docker daemon. They do not look at the size of the ext4.vhdx file on the Windows side, which is why the compaction above is still your job. flisk doctor --fix --dry-run lists repairs for unused Docker networks and leftover doctor probes without changing anything. It is not a disk cleaner.

flisk doctor

Pitfalls

  • Compacting while Docker or WSL runs. The file must not be in use. Quit Docker Desktop and run wsl --shutdown first.
  • Moving the repo to /mnt/c to save space. It trades disk for speed; see why WSL2 is slow on /mnt/c.
  • A maximum size. The virtual disk has a limit that is large by default. Shrinking the file does not change that limit.

Questions people ask

Why is ext4.vhdx still huge after I delete files?

The virtual disk file grows on write and does not shrink on delete. It must be compacted, or the distro put in sparse mode.

Is compacting safe?

It is routine, but it touches your only copy of the filesystem. Export a backup with wsl --export and make sure WSL and Docker are shut down first.

Does flisk doctor shrink the WSL disk?

No. It checks disk space and the Docker build cache from inside Linux. Compacting the vhdx is done from Windows.
