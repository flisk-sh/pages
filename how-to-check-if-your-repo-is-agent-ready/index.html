How to Check If Your Repo Is Ready for Coding Agents

A short checklist and two free tools to score your repository on instructions, fast checks, CI health and README quality before you hand it to a coding agent.

A repo is ready for agents when a fresh session can install, check and test it from the written instructions alone, and CI is green and trusted. You can test that by hand in ten minutes and back it with a README score and a CI health view.

The ten-minute cold-start test

Clone the repo into a clean folder and follow only what the docs say. Count how often you have to guess.

  1. Does the install command work first time?
  2. Is there one check command that returns pass or fail?
  3. Can you run a single test file?
  4. Does AGENTS.md list traps and off-limit files?
  5. Is the default branch green in CI right now?

Every no is a place an agent will lose time too.

Score the README

Agents read the README before anything else. README Score gives a GitHub README a score out of 100, lists the sections found and missing and suggests a fix for each. The same README always gets the same score and it uses no AI, so you can track it over time. It looks at the README only, not at your whole repository.

Look at the CI signal

An agent cannot tell a real failure from a flaky one. If your default branch is often red or your workflows flip between pass and fail, agents will chase ghosts. Cilytics is a public CI health dashboard for GitHub that needs no account. Open it with ?repo=owner/name to scan one public repository, and read the red workflows, flaky workflows and the AI-readiness view. It uses default-branch runs from the last 100 runs and refreshes hourly, so treat it as a trend, not a live feed.

Fix in this order

  1. Make CI green and stable on the default branch.
  2. Add the one fast check command.
  3. Write a short AGENTS.md; see how to write one.
  4. Protect sensitive paths with review rules.
  5. Polish the README and the repo map.

Green CI first, because every other improvement is judged by it.

Re-run it on a schedule

Repos drift. Repeat the cold-start test every quarter, or after a big dependency or tooling change. For the pull-request side of the story, continue with CI for agent-written pull requests.

Turning the result into a plan

After the cold-start test and the two scores, write down the three biggest gaps and give each an owner. Resist the urge to fix everything. A repo with green CI, a one-command check and a short AGENTS.md is already in much better shape than most, and the rest can follow gradually.

Measure again after a few weeks. Practical signals include how often agent pull requests pass CI on the first try, how many review comments they get about missing context, and how long a new agent session takes to produce a correct first change. These are rough, but a rising first-pass rate means the instructions are working.

Keep the checklist in the repo, for example in docs/agent-readiness.md, and update it when a new trap is found. If you work on many repositories, the org-level view in org-wide CI visibility helps you decide which repositories to fix first.

Questions people ask

Is there a single score for agent readiness?

There is no standard one. Cilytics shows an AI-readiness view and README Score rates the README, but the cold-start test is the most honest check.

Does a private repo work with these tools?

Cilytics works on public repositories and README Score works on GitHub READMEs it can read. For private code, run the cold-start test by hand.
