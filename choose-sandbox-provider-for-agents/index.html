How to choose a sandbox provider for AI agents

A checklist for picking hosted or self-run sandboxes: isolation, start time, limits, persistence, network control, pricing model and how easy it is to leave.

Choose a provider by testing your own workload against six questions: how strong is the isolation, how fast does it start, can you control the network, can state persist, how is it billed, and how hard is it to move away. A self-run Docker setup is enough for many teams. A hosted service saves work once you run many sandboxes.

Self-run or hosted

Self-run means you operate Docker, gVisor or microVMs on your machines. You control everything and pay for idle capacity and your own time. Hosted means an API creates a sandbox for you. You pay per use and give up some control. If you run fewer than a handful of sandboxes at once for a trusted team, start self-run with hardened Docker.

The checklist

QuestionWhat to look for
IsolationContainers, gVisor or microVM. Ask which one and read their docs.
Start timeMeasure cold start and resume from your region.
Network controlCan you block or allowlist egress per sandbox?
PersistenceVolumes, snapshots, or files only for the session?
LimitsMax run time, memory, CPU, concurrent sandboxes.
BillingPer second, per size, minimums, storage fees.
ExitStandard images and a thin API you can swap.

Run the same test on each

Write one small benchmark and run it on every candidate: start a sandbox, install a package, run a test suite, write a file, read it back, and stop. Record time and cost. Then try the failure cases from the other articles: an infinite loop, a memory hog and an outbound request to a blocked host. A provider that handles these cleanly is worth more than one that is slightly faster on the happy path.

Avoid lock-in

Hide the provider behind a tiny interface in your code, for example create(), run(cmd), put_file(), get_file() and destroy(). Keep the environment in a standard Dockerfile. Then switching providers means writing one adapter.

class Sandbox:
    def run(self, cmd: str, timeout: int = 30) -> dict: ...
    def put_file(self, path: str, data: bytes) -> None: ...
    def get_file(self, path: str) -> bytes: ...
    def destroy(self) -> None: ...

Start small

Do not migrate everything at once. Run one low-risk job type on the new provider for a week, compare cost, reliability and the number of support-worthy surprises, then decide. Keep the old path working until the new one has earned trust. Providers in this area are young, so expect changes to limits and prices, and re-check them when you plan your budget.

Questions people ask

Do I need a microVM provider?

Only if you run code from untrusted users or want strong isolation by default. For your own agent and reviewed workloads, hardened containers are often enough.

What matters most for coding agents?

Fast resume with the repository and dependencies already in place, plus controlled network access for package installs.
