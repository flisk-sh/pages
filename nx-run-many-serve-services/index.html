Nx run-many: how to serve several apps at the same time

nx run-many is built for builds and tests. It can start dev servers too, if you know about one default that surprises people.

Run nx run-many -t serve -p api web to start the serve target of two projects together. Nx runs at most three tasks in parallel by default, so with more than three long-running servers, raise the limit with --parallel, or the extra ones will never start.

How run-many picks projects

nx run-many runs one target across several projects. The target is the name of something in a project's configuration, such as build, test or serve. You choose projects in a few ways:

nx run-many -t serve -p api web
nx run-many -t serve --all
nx run-many -t serve --exclude=admin
nx run-many -t test build -p api

-t is short for --target and -p for --projects. For one project you do not need run-many at all: nx serve api is shorthand for nx run api:serve.

The parallel limit

By default Nx runs three tasks at once. A build finishes and frees its slot, so this is fine for builds. A dev server never finishes. If you ask for four servers, three start and the fourth waits for a slot that never opens. Set the limit explicitly:

nx run-many -t serve -p api web worker admin --parallel=4

Make it at least the number of servers you start. Recent Nx releases also let a target be marked as continuous, which tells Nx the task is a long-running process; check the Nx docs for your version, because this is a newer setting.

Dependencies between targets

If a server needs a library built first, say it in nx.json with targetDefaults:

{
  "targetDefaults": {
    "serve": { "dependsOn": ["^build"] },
    "build": { "dependsOn": ["^build"], "cache": true }
  }
}

^build means "run build for the projects this one depends on". Nx derives that graph from your imports and package.json files. You can look at it with nx graph.

What Nx does not do for servers

  • It orders tasks, not readiness. A target that depends on another waits for the first task to complete; for a server, completing is not the same as listening.
  • It does not restart a crashed server or supervise it.
  • It does not run a database or a queue. You still need Compose or another tool for those.
  • One terminal shows output from every server, which gets noisy at four or five.

Nx is stronger than most tools at what it is for: the project graph, caching and nx affected. Use it for that. See running only the changed services for the affected side.

Using Nx with Flisk

Flisk's comparison with Nx and Turborepo says they are complementary: keep Nx for builds and tests, and point each Flisk service at an Nx command. A service is a folder with a service.json:

{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "api",
  "appType": "backend",
  "command": "npx nx serve api",
  "port": 4000,
  "healthCheckPath": "/health"
}

A command runs from the service folder with PORT set to port. Flisk starts services in dependsOn order, waits until the health URL answers, restarts one that exits, and prints logs with the service name in front. Run flisk up for all of them, flisk up --only api for one. Make sure your Nx serve target reads PORT or accepts the port, otherwise Flisk waits for a port nothing listens on.

I did not run an Nx workspace through Flisk for this article. The Flisk side (command, dependsOn, --only) is documented; check your own serve target once.

Pitfalls

  • If only three of your four servers start, it is the parallel limit.
  • The Nx daemon and cache live under the workspace; do not commit them. Keep generated folders out of git.
  • Do not use --all in a large workspace for serving. It starts every project that has a serve target, including ones you never open.

For the pnpm-only route, see running several services from a pnpm workspace, and for Turborepo, the turbo dev task.

Questions people ask

Why do only three of my Nx servers start?

Nx runs three tasks in parallel by default, and a dev server never finishes, so it keeps its slot. Pass --parallel with at least the number of servers.

What is the difference between nx serve api and nx run api:serve?

Nothing. nx serve api is shorthand for nx run api:serve.

Can Nx start a database?

No. Nx runs targets of your projects. Run databases with Compose, Flisk or another tool.
