Agent frameworks on your laptop

How to keep OpenAI Agents SDK conversations across restarts

By default a conversation lives in memory and ends with the process. A session backed by a file keeps it, and one header turns it into a multi-user API.

The OpenAI Agents SDK keeps no conversation history between calls unless you hand it a session. Pass a SQLiteSession that points at a file, and the history survives a restart of your service. Add a session id from a request header and the same agent can serve many separate conversations. This article builds that service and runs it locally.

What a session does and does not do

Each call to Runner.run is independent. Without a session you must pass the earlier messages yourself. With a session, the runner loads the stored items before the call and appends the new ones afterwards, so your code only sends the new user message.

A session stores conversation history. It is not a checkpoint of a run in progress. If the process dies halfway through a tool-calling run, the session holds what was saved, and nothing resumes the interrupted run by itself. If you need that, a graph framework with checkpoints fits better; compare them in where agent frameworks keep state.

The service

Install the SDK with pip install openai-agents. SQLiteSession takes a session id and, as a second argument, a database file path. If you leave the path out it uses memory, which is the setting that loses everything on restart.

import os

from agents import Agent, Runner, SQLiteSession
from fastapi import FastAPI, Header
from pydantic import BaseModel

DB_PATH = os.environ.get("SESSIONS_DB", ".data/sessions.db")
os.makedirs(os.path.dirname(DB_PATH), exist_ok=True)

agent = Agent(name="assistant", instructions="Answer briefly.")
app = FastAPI()


class Turn(BaseModel):
    input: str


@app.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}


@app.post("/turn")
async def turn(body: Turn, x_session_id: str = Header(...)) -> dict[str, str]:
    session = SQLiteSession(x_session_id, DB_PATH)
    result = await Runner.run(agent, body.input, session=session)
    return {"reply": str(result.final_output)}

FastAPI turns the x-session-id header into the x_session_id argument. A request without it gets a 422, which is a reasonable answer for a missing session. This is the same convention the Flisk agent resource uses; the idea is covered in routing requests by session ID.

Run it with Flisk

Scaffold a Python service that runs as a local process, then replace its src/main.py with the code above and add openai-agents to pyproject.toml:

npm install -g @flisk-sh/flisk
flisk project --yes
flisk resource assistant --type backend --language python --local --stack agents --yes

Edit the generated service.json so the process gets the key and a database path that stays out of git:

"env": {
  "OPENAI_API_KEY": "${OPENAI_API_KEY}",
  "SESSIONS_DB": ".data/sessions.db"
}

Add .data/ to .gitignore. A local process runs from the service directory, so the relative path lands inside it. Install the dependencies into your active environment, run flisk up, and talk to the service on the port it prints:

curl -X POST localhost:<port>/turn -H 'x-session-id: demo' -H 'content-type: application/json' -d '{"input":"My name is Sam."}'
# stop with Ctrl+C, run flisk up again, then:
curl -X POST localhost:<port>/turn -H 'x-session-id: demo' -H 'content-type: application/json' -d '{"input":"What is my name?"}'

The second call should use the stored history, so the model can answer from the first message. A different x-session-id starts a separate conversation. Because this is a local process with no gateway, the header is read by your code and nothing routes on it; Flisk's gateway-based session routing belongs to its Docker path and the agent resource.

Pitfalls

  • A session id is a file key. Here it only picks rows in one database, but never build file paths from raw header values elsewhere. Validate the id if it comes from outside.
  • SQLite is one writer. Two turns on the same session at once can interleave their messages. Serialize turns per session if clients can send overlapping requests.
  • Turn limits. Runner.run stops with an error after a maximum number of turns. Set it deliberately; see step limits across frameworks.
  • Tracing. The SDK sends traces to OpenAI by default. Turn that off with set_tracing_disabled(True) if the conversations are private.
  • History grows. Every turn re-sends stored items to the model. Clear a session, or trim it, when conversations get long.

If the service also needs a database of its own, see giving an agent a database and a queue.

Questions people ask

Where does SQLiteSession store data if I give no path?

In memory. The history is lost when the process exits, so pass a file path as the second argument for anything you want to keep.

Can two services share one session database?

SQLite handles occasional sharing but is a poor fit for concurrent writers. Use a server database if several processes write the same sessions.

Does Flisk resume a run that was interrupted?

No. Flisk restarts a crashed process. Whether an unfinished run can continue depends on your framework, and the Agents SDK session stores history, not run progress.
