Coding agent permissions: what to allow and what to block

Decide which commands a coding agent can run without asking, how to use allowlists and sandboxes, and what to keep behind a human approval every time.

Allow read-only and local commands that are easy to undo, ask for approval on anything that sends data out or changes shared state, and block destructive commands outright. For unattended runs, put the agent in a container or a disposable VM instead of trusting prompts alone.

Three tiers

TierExamplesPolicy
SafeRead files, git status, git diff, run tests, lint, typecheckAllow
ReviewInstall packages, edit config, git commit, network callsAsk
Dangerousrm -rf, git push --force, deploy, database writes, anything with credentialsDeny, or a human does it

Use the tool's allowlist

Most coding agents let you pre-approve specific commands and deny others, through settings files or a permission prompt where you choose "always allow" for a pattern. Allow narrow patterns such as your test command, not whole programs. Allowing "any shell command" removes the point of having permissions. Check your agent's documentation for the exact settings format, since it differs between tools and versions.

Skipping prompts is for sandboxes only

Some agents have a mode that skips every approval. Use it only inside an environment where the worst case is acceptable: a container with no secrets, no access to your home directory and no or limited network. On your normal laptop, with your SSH keys and cloud credentials in reach, never. See AI sandboxes for agents for how to build one.

Protect git and secrets

  • Work on a branch, never on main. Protect main on the server so a direct push fails.
  • Keep real credentials out of the project folder. The agent can read files you can read.
  • Use a separate low-privilege token for the agent, with expiry.
  • Commit often so every step can be undone: see git habits for agents.

Watch what it reads

An agent that reads issues, web pages or dependency docs can be steered by text inside them. Treat that content as untrusted. Be cautious when a task combines reading outside content with running commands, and keep approval prompts on for network access during such tasks. More in AI security for builders.

Review your setup regularly

Permissions grow over time as you click "always allow". Once a month, read your allowlist and remove anything broader than it needs to be. Check that denied commands are still denied. Treat the list like a firewall rule set: small, explained and reviewed. When a teammate joins, share the settings file through the repository so everyone starts with the same safe defaults, and note in the instructions file why each denied command is denied.

Questions people ask

Is it fine to approve prompts quickly?

Habit makes people click yes without reading. Keep the prompt count low by allowlisting safe commands, so each prompt that remains gets real attention.

Can hooks enforce rules?

Many agents support hooks or scripts that run before a command and can block it. This is more reliable than asking the model to follow a rule. Check your tool's docs.
