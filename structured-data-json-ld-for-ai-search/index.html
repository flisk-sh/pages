Structured data and JSON-LD for AI search and rich results

Add schema.org JSON-LD to describe your product, articles and FAQs in a machine-readable way, with copy-paste examples and the mistakes that invalidate them.

Add JSON-LD in a script tag in the page head to state, in machine-readable form, what the page is: an article, a product, an FAQ or an organisation. It helps search engines and other parsers understand the page, though it does not guarantee a citation or a rich result.

What JSON-LD is

JSON-LD is a block of JSON that uses the schema.org vocabulary. It sits in the HTML, separate from the visible text, so you can add it without changing the design.

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "How to get cited by AI search",
  "datePublished": "2026-01-15",
  "author": { "@type": "Organization", "name": "Acme" }
}
</script>

Types worth adding

  • Organization on the home page: name, URL, logo, links to your profiles.
  • Article or TechArticle for guides and posts.
  • SoftwareApplication for a tool or app page.
  • FAQPage where the page truly has questions and answers.
  • BreadcrumbList to show the page hierarchy.

An FAQ example

{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "Is it free?",
    "acceptedAnswer": { "@type": "Answer", "text": "Yes, the CLI is open source under the MIT licence." }
  }]
}

Wrap it in the same script tag as above. The questions and answers must also appear on the page for readers.

Rules that keep it valid

  • The data must match the visible page. Do not mark up content users cannot see.
  • Do not invent ratings or reviews. Search engines penalise fake markup.
  • Keep dates in ISO format.
  • One main entity per page.

Validate it

Use the schema.org validator and Google's Rich Results Test to catch syntax errors and missing fields. Also check that your template does not emit the same block twice. Remember the limits: markup helps machines identify the page, but clear writing is still what makes an answer worth quoting. See writing content AI answers quote.

Generate it, do not hand-type it

Build the JSON in code from the same data that renders the page, then print it with JSON.stringify. That way the markup cannot drift from the visible text, and escaping is handled for you. Remember to escape the closing script sequence if a title could contain it. Add one test that parses every emitted block and fails on invalid JSON, since a stray comma silently turns the whole block off.

Start with Organization on the home page and Article on guides, validate them, and add other types only when a page really fits one. A few correct blocks beat many doubtful ones.

Questions people ask

Does JSON-LD make AI quote my page?

Not by itself. It helps parsers understand the page and may enable rich results, but quoting depends on the content and the product.

Where do I put the script tag?

In the head or body of the HTML. Search engines read it in either place.
