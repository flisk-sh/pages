Build your own MCP server

How to write an MCP server in Python with FastMCP

FastMCP turns ordinary Python functions into MCP tools. Here is the whole path from an empty folder to a server you can call.

Install the official MCP Python SDK, create a FastMCP object, decorate plain Python functions with @mcp.tool(), and call mcp.run(). The type hints become the input schema and the docstring becomes the tool description, so a working server is about fifteen lines. You need Python 3.10 or newer.

Set up the project

The examples use uv, but pip works the same way. The cli extra adds the mcp command you will use for development.

uv init notes-mcp
cd notes-mcp
uv add "mcp[cli]"

The package mcp contains the official SDK, and FastMCP is the high-level API inside it (from mcp.server.fastmcp import FastMCP). There is also a separate community package called fastmcp with a similar API and more features. The two look alike, so check which one a tutorial imports before you copy code. This article uses the official one.

Write the server

This server keeps notes in memory and exposes two tools. Save it as server.py.

import os
from mcp.server.fastmcp import FastMCP
from starlette.requests import Request
from starlette.responses import PlainTextResponse

mcp = FastMCP(
    "notes",
    host="127.0.0.1",
    port=int(os.environ.get("PORT", "8000")),
)

NOTES: dict[str, str] = {}

@mcp.tool()
def add_note(title: str, text: str) -> str:
    """Save a note. Use this when the user asks you to remember something."""
    NOTES[title] = text
    return f"Saved note '{title}'"

@mcp.tool()
def find_notes(query: str, limit: int = 5) -> list[str]:
    """Return titles of notes whose title or text contains the query."""
    q = query.lower()
    hits = [t for t, x in NOTES.items() if q in t.lower() or q in x.lower()]
    return hits[:limit]

@mcp.custom_route("/health", methods=["GET"])
async def health(request: Request) -> PlainTextResponse:
    return PlainTextResponse("ok")

if __name__ == "__main__":
    mcp.run(transport="streamable-http")

Three things are worth noticing. The limit: int = 5 default makes limit optional in the generated schema. The docstring is what the model reads when it chooses a tool, so write it for the model. And custom_route adds a plain HTTP route next to the MCP endpoint, which is handy for a health check. The MCP endpoint itself is served at /mcp by default.

The default transport of mcp.run() is stdio. If you want the server to be a child process of one assistant and need no port, call mcp.run() with no argument and see the stdio versus HTTP comparison before you decide.

Try it before connecting an assistant

The SDK ships a development command that starts the server and opens the MCP Inspector against it:

uv run mcp dev server.py

Or run the HTTP server and call it yourself:

uv run python server.py
curl -s http://127.0.0.1:8000/health

For stepping through calls by hand, see debugging with the MCP Inspector.

Run it with Flisk

The --type mcp scaffold in Flisk is Bun and TypeScript only: it has no --language option. A Python server does not need the scaffold, though. Flisk can run any service that declares a command as a plain local process, with no Docker. Put this service.json next to server.py:

{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "notes-mcp",
  "appType": "mcp",
  "command": "uv run python server.py",
  "port": 4000,
  "healthCheckPath": "/health"
}

Flisk passes the port to the process as PORT, which is why the server reads it from the environment. Run flisk up from the project folder, and the server starts at http://localhost:4000. Then check the protocol with Flisk's own tool:

flisk mcp check notes-mcp

That resolves the resource name to its local address plus /mcp and sends initialize, tools/list and a few malformed requests. A project can run either local processes or container stacks, not both at once. If the rest of your stack is on Docker, wrap the server in a Dockerfile and register it as a bring-your-own resource instead, as the Dockerfile recipe shows. For the no-Docker path in general, see running local services without Docker.

Pitfalls

  • Do not print() in a stdio server. Standard output carries the protocol. Log to standard error. This failure is the most common one.
  • In-memory state disappears on restart. The notes above are a toy. Use a database for anything that should survive.
  • Bind to 127.0.0.1 on your laptop. Use 0.0.0.0 only when the server runs in a container and something outside must reach it, and then add authentication.
  • Pin the SDK version. The Python SDK changes between minor releases. A lock file keeps your server from breaking on the next install.

Once the server runs, the next question is what its tools should look like to a model. Designing MCP tool names and descriptions covers that.

Questions people ask

Is FastMCP part of the official MCP Python SDK?

Yes. The mcp package contains a high-level FastMCP class in mcp.server.fastmcp. A separate community package named fastmcp exists with a similar API, so check which one you import.

Can I run a Python MCP server without Docker?

Yes. An MCP server is an ordinary process. Run it with python or uv run, or give it a command in service.json so Flisk starts it as a local process.
