AGENTS.md vs CLAUDE.md vs README: which file does what

Three files, three readers. Learn what each one is for, how to avoid duplicating content, and how to support several coding agents with one source of truth.

README.md is for humans who want to use or understand the project. AGENTS.md and CLAUDE.md are instruction files for coding agents. CLAUDE.md is what Claude Code looks for, and AGENTS.md is a tool-neutral name that several other agents read.

The three readers

FileReaderHolds
README.mdAnyone arriving at the repoWhat it is, install, usage, contributing
AGENTS.mdCoding agents, several vendorsCommands, rules, do-not-touch list
CLAUDE.mdClaude CodeThe same kind of content, in Claude's file name

A README can say "run npm test". An agent file says "run npm test before every commit and paste the result". The second is a rule, not a description.

Do not write the same thing three times

Duplicated instructions drift. Pick one source of truth and point the others at it. Two common setups:

  • Keep the content in AGENTS.md. Make CLAUDE.md a one-line file that points to it.
  • Keep the content in CLAUDE.md and symlink or copy AGENTS.md from it in a build step.

Claude Code supports importing other files into CLAUDE.md with an at-sign path. Check the current Claude Code docs for the exact syntax before you rely on it. A symlink is the lowest-tech option.

ln -s AGENTS.md CLAUDE.md

Symlinks work in git on macOS and Linux. On Windows, they need extra settings, so a short pointer file is safer there.

What stays out of the README

Do not stuff agent rules into the README. Human readers do not need "never edit generated files" on the front page, and the README grows. In return, do not hide the install steps in AGENTS.md only. The README must stand alone for a person.

A good test: can a stranger set up the project from README.md alone? Can an agent behave correctly from AGENTS.md plus the README? If yes to both, the split works.

Personal versus project rules

Some tools also read a personal instruction file in your home directory, for your own habits, such as preferred test style. Keep project facts in the repo so every contributor and every agent gets them, and keep personal taste in the personal file. Never put secrets in either.

Review the instruction files like code

Instruction files shape every change an agent makes, so changes to them deserve review. Add them to CODEOWNERS if you use it, and read the diff when someone edits a rule. An instruction such as "skip the tests" added by accident can do more harm than a bug.

A simple rule of thumb

If a fact helps a human and an agent, it goes in the README. If it only matters when a machine edits the code, it goes in AGENTS.md. For how to write that file, see What is AGENTS.md. For working with these agents day to day, see Coding agents in practice.

Questions people ask

Which file does Claude Code read?

Claude Code reads CLAUDE.md. If your repo only has AGENTS.md, point a CLAUDE.md at it or check the current docs for fallback behaviour.

Can one repo have all three?

Yes, and many do. Keep the content in one place and have the others point to it.
