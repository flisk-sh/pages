Keep your laptop fast while developing

Free disk space on a dev laptop: caches, node_modules, builds

Dev disks fill with things that can be rebuilt. The skill is knowing which ones are safe to delete and finding the big ones fast.

To free disk space on a developer laptop, find the biggest folders with du, then delete what can be rebuilt: node_modules in old projects, build output (target, dist, .next), package manager caches and Xcode build data. Never delete the source of truth: your code, .env files you cannot regenerate, and database volumes.

Find the big folders

du -sh ~/* 2>/dev/null | sort -h | tail -15
du -sh ~/Library/* 2>/dev/null | sort -h | tail -15      # macOS
du -sh ~/.[!.]* 2>/dev/null | sort -h | tail -15         # dotfolders: caches live here

Start at your projects folder and go down one level at a time. A small tool called ncdu does the same interactively if you install it. Expect the winners to be: project node_modules, Rust target folders, the Docker or Colima disk, simulators and package caches.

Project folders you can rebuild

  • node_modules: delete it in projects you are not working on, and reinstall when you come back. Each can be hundreds of MB. npx npkill scans a folder tree and lets you pick which ones to remove.
  • Rust target: cargo clean inside a project removes its target folder, often several GB. It makes the next build slow, so do it for projects you have not touched in a while.
  • Build output: dist, build, .next, .turbo, __pycache__, .venv. All regenerated by the next build or install.

To see exactly what Git ignores in a project before you delete it, run a dry run first:

git clean -ndX

-X selects only ignored files, -d includes folders and -n only lists them. Remove the n to delete. Careful: ignored files include .env and local config, which you may not be able to recreate. Read the list before you run the real command.

Caches exist to save time, so clean them when you need space, not on a schedule. If you use a monorepo store such as pnpm's, one store is shared by all projects and deleting it breaks the hard links of installed projects until you reinstall.

macOS developer folders

  • ~/Library/Developer/Xcode/DerivedData holds build products and is safe to delete; Xcode rebuilds it.
  • xcrun simctl delete unavailable removes simulators for runtimes you no longer have.
  • Old iOS device support files and archives under ~/Library/Developer can be large; remove the ones you do not need.

Containers and Flisk

The Docker disk is its own topic, covered in Docker disk full. For a Flisk project, a few facts help you pick what is safe. Services that run as local processes keep their logs under .flisk/native/logs/, a folder that ignores itself in Git, so it is safe to delete when the stack is down. flisk down stops everything and keeps named volumes. flisk down --purge also deletes the project's Docker volumes (database data), networks and images, so use it only when you want a fresh database. flisk down --prune-cache prunes Docker build cache, which is shared by all projects on the machine; the default age filter is 24h. Run flisk down --dry-run first to see what would stop. More cleanup is in stop and clean up a local stack.

Pitfalls

  • Check free space after deleting. On macOS, space freed from Time Machine local snapshots or the Trash can take a while to show.
  • Do not delete caches while a build or install runs.
  • Do not clean the Docker disk from the host side by deleting the VM image file. Use the runtime's own prune commands.
  • Keep one note of anything you deleted that took an hour to rebuild, such as a large model download, and do not delete it twice.

When memory, not disk, is what hurts, go to finding what uses your RAM.

Questions people ask

Is it safe to delete node_modules?

Yes, it is rebuilt by your package manager from the lockfile. Make sure you have a lockfile committed and do not delete it while a dev server runs.

What does git clean -ndX do?

It lists, without deleting, the ignored files and folders in the project. Check the list for .env files before you run the real command without -n.

Does flisk down delete my database?

No. flisk down keeps named volumes. Only flisk down --purge also deletes the project's Docker volumes.
