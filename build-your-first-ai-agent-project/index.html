Build your first AI agent: a tool-calling loop in 60 lines

An agent is a loop: the model asks for a tool, your code runs it, the result goes back. Build one in Python with two tools and learn where it breaks.

An agent is a loop around a model call. You send the conversation and a list of tools, the model replies with either an answer or a request to call a tool, your code runs the tool and appends the result, and you repeat until the model answers. That is all, and you can write it without a framework.

The loop

Define tools as plain functions with a JSON schema description. Send them with each request. If the reply has tool calls, run them and send results back. Stop on a plain answer or after a maximum number of steps.

import json
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11434/v1", api_key="local")

def add(a: float, b: float) -> float: return a + b
TOOLS = {"add": add}
SCHEMA = [{"type": "function", "function": {
    "name": "add", "description": "Add two numbers",
    "parameters": {"type": "object",
      "properties": {"a": {"type": "number"}, "b": {"type": "number"}},
      "required": ["a", "b"]}}}]

msgs = [{"role": "user", "content": "What is 17.5 plus 24.25?"}]
for step in range(5):
    r = client.chat.completions.create(model="llama3.2", messages=msgs, tools=SCHEMA)
    m = r.choices[0].message
    msgs.append(m)
    if not m.tool_calls:
        print(m.content); break
    for c in m.tool_calls:
        out = TOOLS[c.function.name](**json.loads(c.function.arguments))
        msgs.append({"role": "tool", "tool_call_id": c.id, "content": str(out)})

Not every local model supports tool calling well. Check that your model does, or pick one that does.

Add a useful second tool

A calculator is a toy. Add something with a side effect that matters, such as reading a file from one allowed folder, or searching your notes. Each tool needs a clear name, a one-line description and a strict schema. The description is a prompt: the model decides based on it. Say when to use the tool and when not to.

Where it breaks

  • Bad arguments. The model sends a string where a number is needed. Validate arguments and return the error text as the tool result, so the model can retry.
  • Endless loops. Keep the step cap and log every step.
  • Wrong tool. Too many similar tools confuse it. Start with two or three.
  • Dangerous tools. Never give a tool the power to delete or send without a check. See AI security for builders.

Make it a project

Pick a small job you really have: summarise today's git commits, triage a folder of notes, check a list of URLs. Run it daily for a week and keep a log of failures. That log is your next-step list. When it works, give it a process contract and run it with a database and a queue. The Flisk CLI can scaffold an agent resource next to an MCP tool server: flisk resource my-agent --type agent, then flisk up. It is a local development tool, so use it to build and test, not as a production orchestrator. More in AI agents locally.

What to learn next

Add memory and sessions, then tests. Go to learn evals first so you can tell whether a change helped, and read agent memory and context when conversations get long.

Questions people ask

Do I need LangChain or another framework?

Not to start. Writing the loop yourself teaches what frameworks do. Adopt one later if it saves real work.

Why does my agent call the same tool again and again?

Usually the tool result is unclear or the model cannot tell the task is done. Return clear results and keep a step limit.
