llms.txt explained: what it is and how to add one

llms.txt is a proposed Markdown file at your site root that points language models to your best pages. See the format, a working example and the honest limits.

llms.txt is a Markdown file served at /llms.txt on your site that gives a language model a short summary of the site and a curated list of links to the pages that matter. It is a proposal, not a web standard, and no one can promise that a given crawler or chatbot reads it.

The format

The proposal describes a simple structure: one H1 with the project name, a blockquote with a one-line summary, optional paragraphs, then H2 sections that hold lists of links, each with a short note. A section named Optional marks links that can be skipped when space is tight.

# Acme Queue

> A small job queue for Node services, backed by Postgres.

## Docs
- [Quick start](https://acme.example/docs/start.md): install and run in five minutes
- [API reference](https://acme.example/docs/api.md): every function and option

## Optional
- [Changelog](https://acme.example/changelog.md): release history

Link to Markdown, not heavy HTML

The point is to hand a model clean text. If you can, serve a .md version of each page next to the HTML one, and link to that. A page full of scripts and navigation wastes the model's context and often extracts badly.

Some projects also publish /llms-full.txt, which holds the full text of the docs in one file. That is a convention, not part of every description of the format. It suits small doc sets. For a large site it becomes too long to be useful.

How to add it

  1. Pick 10 to 30 pages: quick start, concepts, API reference, FAQ, pricing if relevant.
  2. Write one plain sentence for each link saying what the reader gets.
  3. Save the file as llms.txt in the folder your host serves at the site root.
  4. Check it loads as plain text.
curl -i https://acme.example/llms.txt

The response should be a 200 with a text or Markdown content type, not an HTML page or a redirect to one.

What it will and will not do

Be realistic. Some tools and agents fetch llms.txt, others do not, and search engines have not committed to using it for ranking. Treat it as low-cost help for agents that go looking for it, such as a coding agent reading a library's docs, not as a ranking trick.

It does not replace the basics: crawlable pages, clear titles, real text instead of text inside images, and a robots.txt that does not block the bots you want. Citable checks whether AI search tools can find, read and cite a site, which is a better test of the basics than the presence of one file.

Maintenance

Generate the file from your docs index at build time so it cannot drift. A stale link list is worse than none. For the wider picture of being readable by AI answers, see Get found by AI search.

Questions people ask

Does llms.txt improve my Google ranking?

There is no commitment from search engines that it does. Treat it as help for agents that look for it, not as an SEO tactic.

Is llms.txt the same as robots.txt?

No. robots.txt tells crawlers what they may fetch. llms.txt is a reading guide that points to useful content.

Do I need llms-full.txt too?

Not required. It helps for small doc sets where the whole text fits in one file.
