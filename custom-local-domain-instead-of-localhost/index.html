Local URLs, routing and HTTPS

How to use a custom local domain like myapp.test

localhost works until you need a name that looks like production. Choose the suffix carefully, because some are reserved and others are traps.

To use a custom local domain, pick a suffix reserved for this purpose (.test or .localhost), make the name resolve to 127.0.0.1 with an /etc/hosts line or a local DNS such as dnsmasq, and tell your reverse proxy to route that Host to your service. Do not use .dev, .app or .local.

Which suffix to use

SuffixVerdict
.localhostReserved. Current browsers and curl resolve it to loopback, so no setup is needed. Some other tools do not.
.testReserved for testing (RFC 6761). Never exists on the real internet. Needs a hosts or DNS entry.
.dev, .appReal top-level domains owned by Google, with HTTPS enforced by HSTS. Browsers force https, so plain HTTP fails.
.localUsed by mDNS (Bonjour). Lookups are slow or fail on some systems.
.exampleReserved for documentation, safe, but unusual.

Make the name resolve

The simplest way is the hosts file. On macOS and Linux edit /etc/hosts; on Windows, C:\Windows\System32\drivers\etc\hosts:

127.0.0.1  myapp.test api.myapp.test

The hosts file has no wildcards. If you add a new service name every week, run dnsmasq and send the whole suffix to loopback:

# dnsmasq.conf
address=/test/127.0.0.1

Then tell your system resolver to ask dnsmasq for .test (on macOS, a file /etc/resolver/test containing nameserver 127.0.0.1). Verify with dscacheutil -q host -a name myapp.test on macOS or getent hosts myapp.test on Linux. Browsers may cache a failed lookup, so reopen the tab.

Under WSL2, the Windows browser reads the Windows hosts file, and tools inside WSL read the Linux one. Edit the one for the program that makes the request.

Route the name

A name that resolves only gets the request to port 80 or 443 on your machine. Something there must match the Host header:

myapp.test {
  reverse_proxy localhost:3000
}

That is a Caddy site block. In nginx it is server_name myapp.test;. If a service sees an unexpected host and answers 400, add the name to its allowed hosts list.

Using it with Flisk

Flisk's own routes use *.localhost names: app.<project>.localhost for frontends and api.<project>.localhost for APIs, so for most projects you need no setup at all. If you want a custom name for the same service, the traefik object in service.json accepts a host. Flisk's bring-your-own guide documents it as an extra host name for the same route of a web UI resource:

{ "appName": "app", "appType": "bring-your-own", "port": 3000,
  "image": "mauriceboe/trek", "webUi": true,
  "traefik": { "host": "myapp.test" } }

Add myapp.test to your hosts file, run flisk config regenerate if the project is already set up, and open the name on the ingress port that flisk networks shows. The docs describe the field for web UI resources only; for other resource types, read the generated labels in the Compose file to confirm what the route does before relying on it. The field is validated: it must match a host pattern, and a value with a line break is refused.

You can also set FLISK_PUBLIC_HOST to change the host name used in the URLs Flisk prints, but that only changes the printed text and the checks Flisk makes. It does not create DNS entries or routes.

When not to bother

If the only reason is aesthetics, keep *.localhost. A custom domain adds a hosts file to maintain on every machine. It pays off when you need a cookie domain that mimics production, an OAuth provider that refuses localhost, or a name that other devices on your network can use, which needs real DNS rather than loopback.

If the name does not resolve in one tool but works in another, read why a *.localhost subdomain does not resolve. When the name resolves but the app refuses it, see Invalid Host header in local dev.

Questions people ask

Which domain suffix is safe for local development?

.test and .localhost are reserved and will never belong to a real site. Avoid .dev and .app, which force HTTPS, and .local, which clashes with mDNS.

Can /etc/hosts use wildcards?

No. Add every name, or run dnsmasq with address=/test/127.0.0.1 to send the whole suffix to loopback.

Does Flisk support custom host names?

service.json has a traefik.host field, documented as an extra host name for the same route of a bring-your-own web UI. You must still make the name resolve yourself.
