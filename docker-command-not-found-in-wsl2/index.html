Docker command not found in WSL2: turn on the integration

When docker is missing or silent inside Ubuntu, Docker Desktop is almost never broken. It just has not been told to reach that distribution.

If docker says "command not found" or "Cannot connect to the Docker daemon" inside Ubuntu on WSL2, Docker Desktop is not integrated with that distribution. Open Docker Desktop, go to Settings, Resources, WSL Integration, switch your Ubuntu distribution on, click Apply & Restart, then open a fresh Ubuntu terminal and run docker version.

What is actually going on

Docker Desktop on Windows runs the Docker engine in its own small WSL 2 distribution. Your Ubuntu distribution does not contain a Docker engine. With WSL integration on, Docker Desktop makes the docker client (and the Compose plugin) appear inside the distributions you choose, and points them at the engine over a socket. If the toggle for your distro is off, you get one of two symptoms:

  • docker: command not found, because the client was never added to that distro.
  • Cannot connect to the Docker daemon, because the client exists but the socket does not answer, usually because Docker Desktop is not running.

Fix it in five steps

  1. Start Docker Desktop on Windows and wait until it reports that the engine is running.
  2. Open Settings, Resources, WSL Integration. Tick the option for your default distribution, or switch on the specific distro in the list below it.
  3. Click Apply & Restart.
  4. Restart the Ubuntu terminal. If it still fails, run wsl --shutdown in PowerShell, start Docker Desktop again, and reopen Ubuntu.
  5. Verify inside Ubuntu:
docker version
docker compose version
docker ps

Both version commands should print a client and a server section without errors. If the server section is missing, the client cannot reach the engine, which points back to steps 1 to 3.

Check that the distro runs WSL 2

Docker Desktop's integration only works with WSL 2 distributions. In PowerShell, list what you have:

wsl -l -v

The VERSION column must say 2 for Ubuntu. If it says 1, convert it:

wsl --set-version Ubuntu 2

Use the exact name from the list, which may be Ubuntu-24.04 or similar. The conversion can take a few minutes for a large distro.

Where Flisk fits

If you use Flisk, flisk doctor run inside Ubuntu includes a check named "Docker WSL integration". It is skipped when you are not in WSL2. In WSL2 it fails with "The docker command is not available in this WSL2 distribution." when the client is missing, and with "Docker does not answer from this WSL2 distribution." when the client is there but the daemon does not reply. The fix text it prints is the same path as above: Docker Desktop, Settings, Resources, WSL Integration, turn on Ubuntu, Apply & Restart, then docker version.

flisk doctor

Running it before flisk up saves you from reading a long Tilt failure when the real cause is a toggle. Install Flisk with npm install -g @flisk-sh/flisk inside Ubuntu, not in PowerShell, if you want the container path.

Other causes to rule out

  • Two Docker setups. If you also installed Docker Engine inside Ubuntu with apt, a stale client or socket can shadow Docker Desktop's. Pick one. The Docker Engine in WSL2 guide covers the no-Desktop route.
  • Docker Desktop is set to Windows containers. Switch it to Linux containers; the WSL 2 backend only serves Linux containers.
  • Permission denied on the socket. That is a different error from "not found". It means the client reached a socket owned by another group. With Docker Desktop's integration this is rare. With a self-installed engine, add your user to the docker group and reopen the terminal.
  • PATH issues. Run which docker. A path under /mnt/c means you are calling the Windows binary through interop, which is the wrong one inside Ubuntu.

When not to bother

If your services are plain Node, Python or Go processes with no containers, you do not need Docker in WSL at all. Flisk can run services that declare a command as local processes, and native Windows can run that mode.

Next step: once docker version works, move your repository into the Linux home folder, as explained in why WSL2 is slow on /mnt/c, and read the full Windows setup guide.

Questions people ask

Why does docker work in PowerShell but not in Ubuntu?

PowerShell uses the Windows docker client. Ubuntu only gets a client when Docker Desktop's WSL integration is switched on for that distribution.

Do I need to install Docker inside Ubuntu as well?

Not with Docker Desktop. Its WSL integration provides the client inside the distro. Installing a second engine creates two setups that can conflict.

How do I know my distro uses WSL 2?

Run wsl -l -v in PowerShell and read the VERSION column. Convert a WSL 1 distro with wsl --set-version <name> 2.
