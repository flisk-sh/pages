How to add human approval to risky AI agent actions

Let the agent propose, let a person confirm. Mark which actions need approval, show exactly what will happen, and make the approval hard to bypass.

  2. Split propose from execute
  3. Show what will actually happen
  4. Make approval hard to bypass

Put a person in the loop for actions that are hard to undo: sending messages, spending money, deleting data, deploying, and changing permissions. The agent proposes an action with its exact arguments, the app shows it, and only a human click lets the tool run.

Decide which actions need approval

Sort tools by what happens if the model is wrong or fooled.

RiskExamplesPolicy
Read-onlysearch, get_orderRun freely
Reversible writecreate draft, add labelRun, log
Hard to undosend email, delete, pay, deployRequire approval

Approval everywhere trains people to click through. Reserve it for the third row.

Split propose from execute

Make the risky tool not execute at all. It records a pending action, and a separate step executes it after approval.

def send_email(to, subject, body):      # tool the model sees
    return db.insert_pending("send_email", {"to": to, "subject": subject, "body": body})

def approve(pending_id, user):          # called by a human action in the UI
    p = db.get_pending(pending_id)
    assert user.can_approve(p)
    mailer.send(**p.args)               # the real side effect
    db.mark_done(pending_id, approved_by=user.id)

The model cannot approve its own request, because approval is not a tool it can call.

Store the pending action with a status of pending, approved, denied or expired. Only the approve function moves it to approved, and it should check that the person is allowed to approve this kind of action. The agent can poll the status or be told the result on its next turn.

Show what will actually happen

Display the final arguments, not the model's description of them. If the model says "I will email the team" but the recipient is an outside address, the person must see the address. Show the recipient, the full body, the amount or the list of files to delete. Highlight values that came from untrusted content.

Make approval hard to bypass

  • Approve one action at a time. Avoid "approve all" for the risky class.
  • Bind the approval to the exact arguments, with a hash, so the action cannot change after the click.
  • Expire pending actions after a short time.
  • Do not let the agent's text claim approval already happened.

For agents running unattended, replace the click with a deterministic policy check, for example a spending limit, and send anything over the limit to a person.

Trade-offs

Approval slows work and adds fatigue. Reduce prompts by making tools narrower, see least-privilege permissions, so fewer actions are risky. Log every approval and denial in the audit log. For coding agents, the guide coding agents in practice discusses permission modes for day-to-day work.

Questions people ask

Can the agent ask for approval in chat text?

Not safely. Approval must be a separate step in your app that the agent cannot trigger. Chat text can be faked or manipulated.

How do I avoid approval fatigue?

Require approval only for hard-to-undo actions, and narrow tools so most actions are low risk and run freely.

Run it in a sandbox

Test risky agent code away from your real machine.

Run untrusted agent code in a disposable sandbox with no secrets and limited network. Fleet offers agent sandboxes behind one API key; it is in beta.
