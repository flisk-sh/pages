When the local stack breaks

Docker disk full: how to free space without losing data

Free the build cache first, then unused images. Leave volumes alone until you know what is in them.

When Docker reports no space left on device, free the build cache first, then unused images, and leave volumes for last because they can hold your data. docker system df shows where the space went, and docker builder prune is the safest first step.

See what is using the space

docker system df
docker system df -v

The first command gives four lines: images, containers, local volumes and build cache, each with a size and a "reclaimable" figure. Reclaimable is what a prune could free. Developers who rebuild images all day often find the build cache is the largest line, because every changed layer leaves an old one behind.

If you use Colima or Docker Desktop, Docker's data sits in a VM disk, not directly on the host. Check both the host (df -h) and the VM. A full host disk can also damage Docker's image store, and the repair for that deletes volumes, so act before the disk reaches zero.

Prune in this order

CommandWhat it removesRisk
docker builder prune -fBuild cacheNext build is slower
docker image prune -fDangling images (untagged)Low
docker container prune -fStopped containersLow, but you lose their filesystem
docker system prune -afAll unused images, containers, networks, cachePulls everything again
docker system prune -af --volumesThe above plus unused volumesCan delete database data

A volume that no container uses right now still counts as "unused". If your database container is stopped, its volume is a candidate for --volumes. List volumes with docker volume ls before you prune them.

Package manager caches outside Docker also take space: npm cache clean --force, bun pm cache rm and brew cleanup -s are common ones.

A habit that avoids most emergencies is to prune the build cache on a schedule you choose, for example once a week, and to remove images of projects you no longer work on. Stale images from old branches are rarely worth keeping. Check docker system df after a large dependency change too, because a new base image can double the size of the image layer list.

How Flisk helps

Before flisk up starts a Docker run, it checks free disk space. Below 5 GiB it stops with DISK_SPACE_LOW. Between 5 and 15 GiB it warns. When Docker runs in a VM such as Colima, it reads the smaller of the host and VM figures. Three environment variables adjust the limits:

  • FLISK_DISK_MIN_GIB sets the level where it stops.
  • FLISK_DISK_WARN_GIB sets the level where it warns.
  • FLISK_BUILD_CACHE_MAX_GIB sets the build cache warning limit, 20 by default. 0 turns it off.

flisk doctor reports the same numbers, along with cleanup commands and a warning when the build cache is over its limit. A trimmed example of what it prints:

⚠ 12.6 GiB free on this machine: image builds may fail below 5 GiB
  docker builder prune -f
  docker image prune -f

To clean up from the project, use flisk down with an option:

flisk down --dry-run
flisk down --prune-cache
flisk down --prune-cache --cache-until 168h
flisk down --purge
  • --dry-run shows what would happen. Use it first.
  • --prune-cache also prunes Docker build cache older than 24 hours by default. --cache-until sets another age. The cache is shared by every project on the machine, not only this one.
  • --purge removes the project's volumes, networks and images. That includes your local database data. Use it when you want a clean start, not to free space.

flisk down prints the sizes of the images and cache it keeps, so you can see what is left to prune.

Pitfalls

  • Pruning images forces a full rebuild next time. That is slow on a weak connection, so schedule it.
  • Do not delete files inside Docker's data folder by hand. Use the Docker commands.
  • A VM disk does not shrink on its own after you free space inside it. The host may still show it as full until the VM releases the blocks. How to do that depends on your VM tool, so check its documentation.
  • If you need the data in a volume, dump it first. For databases see how to reset a local database.

To catch a low disk before it breaks a build, run a readiness check as the first step of your day: check your machine before starting the stack.

Questions people ask

Is docker system prune safe?

Without extra flags it removes stopped containers, unused networks, dangling images and build cache, but not volumes. Adding -a also removes every image not used by a container, and --volumes removes unused volumes, which can delete database data.

Why is my disk full when df shows space free?

With Colima or Docker Desktop, Docker lives in a VM with its own disk. The VM can be full while the host has space. Check both.

How do I clear the Docker build cache with Flisk?

Run flisk down --prune-cache. By default it removes cache older than 24h. Use --cache-until to pick another age, such as 168h.
