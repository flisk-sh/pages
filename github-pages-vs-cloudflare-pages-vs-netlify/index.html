GitHub Pages vs Cloudflare Pages vs Netlify

A practical comparison of three free static hosts for small sites: setup, previews, build options, custom domains and where each one gets awkward.

For a plain static site, all three work. GitHub Pages is the simplest if your code is already on GitHub, Cloudflare Pages is the best fit if you will add Workers later, and Netlify has the most built-in extras like forms. Free tier limits change, so check each pricing page before you commit.

What they have in common

Each one serves static files from a CDN over HTTPS, supports custom domains, and can build from a Git repository. For an HTML page, a Vite build or a docs site, any of them is fine.

When GitHub Pages is the right answer

You already have a repo, the site is static, and you do not need previews. There is nothing new to learn and no second account. Its weak spot is that private repositories need a paid plan for Pages, and there is no server side at all.

When Cloudflare Pages wins

You want preview URLs per branch, and you expect to add an API, a database or an AI call next. The same account runs Workers, D1 and KV, so the static site and its backend sit in one place.

npx wrangler pages deploy ./dist --project-name my-site

When Netlify is worth it

You want form handling, redirect rules and split testing without writing code, and you are happy with its Git workflow. Remember that convenience features can become a lock-in cost if you rely on them heavily.

A sensible default

Start on GitHub Pages for a throwaway site. Move to Cloudflare Pages when you need previews or a backend. Because all three serve a folder of files, moving between them takes minutes if you avoid host-specific config.

One more factor is team habits. If everyone already reviews work in GitHub, a Pages workflow is the least surprising option. If your team lives in the Cloudflare dashboard, keep the site there. Pick one and write it in the README so the next person does not guess. Re-check the free tier limits once a year, because they are the part that changes most often. Finally, test the same site on all three if you are unsure. Deploy the folder to each, compare build time, preview behaviour and how easy the logs are to read, and keep the one that feels least like work. A thirty minute trial is cheaper than a migration later.

Questions people ask

Can I use my own domain on all three?

Yes, all three support custom domains with free HTTPS certificates. The DNS steps differ slightly, so follow the host's own instructions.

Which one is fastest?

For static files the difference is small and depends on your audience's location. Pick on workflow, not speed.

Try it

Put one page online in a minute.

Pages publishes an HTML or Markdown file to a free public link. It is public, so do not use it for anything private.

npx -y @flisk-sh/pages publish page.html --wait
