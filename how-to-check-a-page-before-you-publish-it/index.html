How to check a page before you publish it

A short checklist for a page you are about to put online: title, description, links, mobile layout, accessibility basics and whether AI search can read it.

Before publishing, open the page on a phone width, click every link, confirm it has a title and description, and scan it for secrets. A five-minute check catches most embarrassing problems.

The basics in the HTML

Every page needs these in the head.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Clear, specific title</title>
  <meta name="description" content="One sentence that says what the page is.">
</head>

The viewport tag is what makes a page usable on phones. Without it the page renders as a tiny desktop layout.

Links and files

Serve the folder locally and click through. A quick local server is enough.

python3 -m http.server 8000 --directory dist

Check images, CSS paths and anchors. Relative paths that work locally can break under a subpath on the host.

Mobile and accessibility

  • Resize the window to 375 pixels wide. Nothing should scroll sideways.
  • Give every image an alt attribute.
  • Use real headings in order, and one h1.
  • Make sure text has enough contrast against the background.

Can AI search read it?

Content generated by JavaScript after load is invisible to many crawlers. Put the main text in the HTML itself. The Flisk Citable tool checks whether AI search and chatbots can find, read and cite a website. See also getting found by AI search.

Test with a real device and a slow network

Desktop browsers on fast networks hide most problems. Open the page on a real phone, and use your browser's developer tools to throttle the network. A page that takes ten seconds to show text will lose readers. Check that fonts, scripts and images are not blocked by a mixed content warning, which happens when an HTTPS page loads an http:// asset. Fix by switching the asset URLs to HTTPS or hosting the file yourself.

Keep this list in the repository as a checklist file and tick it before each release. Five minutes of routine beats a public typo or a broken layout that a friend has to point out.

Safety scan

Grep the folder for keys and personal data, and look for source maps and .git. The commands are in what not to publish. Then publish with the method from publishing an HTML page for free.

Questions people ask

Do I need a robots.txt for a small page?

No. Without one, crawlers may index it. Add a robots.txt or a noindex tag only if you want to keep it out of search results.

Does a page need an Open Graph image?

It is optional, but it makes link previews in chats and social sites look better. Use og:title, og:description and og:image.

Try it

Put one page online in a minute.

Pages publishes an HTML or Markdown file to a free public link. It is public, so do not use it for anything private.

npx -y @flisk-sh/pages publish page.html --wait
