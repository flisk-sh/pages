Build a SaaS app locally

How to resolve the tenant from a subdomain in local development

Many SaaS products put each customer on its own subdomain. You can build and test that routing on your laptop without a domain or a hosts file entry.

Read the Host header, remove the port, remove your base domain (localhost in development), and what remains is the tenant slug. Browsers such as Chrome and Firefox send acme.localhost to your own machine, so you can test acme.localhost:3000 and globex.localhost:3000 with no DNS setup.

The resolution function

Keep it small, pure and tested. The base domain comes from configuration, so production uses yourapp.com and development uses localhost:

const BASE = process.env.BASE_DOMAIN ?? "localhost";
const RESERVED = new Set(["www", "app", "api", "admin", "static"]);

export function tenantSlugFromHost(hostHeader) {
  const host = (hostHeader ?? "").toLowerCase().split(":")[0];
  if (host === BASE) return null;                 // marketing site, no tenant
  if (!host.endsWith("." + BASE)) return null;    // unknown domain
  const slug = host.slice(0, -(BASE.length + 1));
  if (slug.includes(".") || RESERVED.has(slug)) return null;
  return /^[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$/.test(slug) ? slug : null;
}

Then look the slug up in the tenants table and return a 404 for an unknown tenant. A 404 is safer than a redirect, because it does not confirm which names exist beyond what the page already shows.

Testing without a browser

You do not need a wildcard DNS record. Send the header yourself:

curl -H "Host: acme.localhost:3000" http://localhost:3000/api/projects
curl -H "Host: globex.localhost:3000" http://localhost:3000/api/projects

Write the same two calls as an automated test, because the tenant lookup is exactly the kind of code that breaks quietly. In a browser, open http://acme.localhost:3000. If it does not resolve, for example in Safari or on some Linux setups, see why a *.localhost subdomain does not resolve.

Behind a proxy

When a proxy or gateway sits in front of your app, the Host header may carry the proxy's name, and the original host arrives in X-Forwarded-Host. Trust that header only when the request comes from your own proxy. If the app is reachable directly, any client can send a forged X-Forwarded-Host and pick the tenant. Configure your framework's trusted proxy setting, and let nothing else override the host.

Cookies and CORS

  • Do not set a Domain attribute on session cookies. A host-only cookie for acme.localhost is never sent to globex.localhost, which is the isolation you want.
  • If a front end on one subdomain calls an API on another, you need explicit CORS and credentials settings. The rules are in using *.localhost URLs instead of port numbers and the front end guides.
  • A user who belongs to two tenants has two separate sessions, one per subdomain. Decide whether that is acceptable or whether you need a central login that redirects.

Where Flisk fits

When your services run as local processes, Flisk prints a plain http://localhost:<port> for each one. Your browser will accept acme.localhost with that port in front of the same process, and the app does the tenant parsing described above. Set the base domain as an environment variable on the service:

{
  "schemaVersion": 1,
  "appName": "web",
  "appType": "frontend",
  "command": "node server.js",
  "port": 3000,
  "env": { "BASE_DOMAIN": "localhost" }
}

On the container path, Flisk routes services through a gateway on *.localhost names. That gateway's host names belong to Flisk's own routing, so check what flisk networks prints for your project before you build tenant logic on top of them, and decide whether tenants sit under your service host or in front of it. The tenant parsing itself stays in your code either way.

Tests worth writing

  • A pure unit test of tenantSlugFromHost with the awkward inputs: an uppercase host, a host with a port, the bare base domain, a nested name such as a.b.localhost, a reserved name and an invalid character.
  • An integration test that calls two tenants with the Host header and checks the responses differ.
  • A test that an unknown slug returns 404 and never falls through to a default tenant. A silent default tenant is how data ends up in the wrong place.

Path prefix instead?

If you do not want wildcard hosts, /t/acme/... works everywhere with no DNS at all, and is simpler for custom domains you do not control. The costs are that every link must carry the prefix and cookies are shared across tenants on one host. Subdomains give better isolation by default.

Questions people ask

Does acme.localhost work without editing /etc/hosts?

In Chrome and Firefox it resolves to your own machine automatically. Some browsers and operating systems do not, and then you can use curl with a Host header or add hosts entries.

Should I trust X-Forwarded-Host to pick the tenant?

Only when the request comes from your own proxy. If clients can reach the app directly, a forged header lets them choose any tenant.

Should session cookies set a Domain attribute?

No. Host-only cookies are not sent to other subdomains, which keeps tenant sessions separate.
