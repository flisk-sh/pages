Learn AI engineering by building

How to learn AI engineering: a build-first roadmap for developers

You do not need a research degree to ship AI features. Here is a build-first order for learning: API calls, structured output, retrieval, agents, evals and shipping.

Learn AI engineering by building small projects in a fixed order: call a model API, get structured output, add retrieval, give the model tools, test it with evals, then ship it to real users. Each step is a weekend project, and each one makes the next one easier.

Start from what you already know

If you can write a web service, you can write most of an AI feature. The model is a function that takes text and returns text, with a latency and a cost. Your job is the engineering around it: inputs, outputs, error handling, testing, cost and safety. Math and training come later, if ever.

The order that works

  1. One API call. Send a prompt, read the answer. See your first LLM API call.
  2. Structured output. Make the model return JSON you can parse and validate.
  3. Retrieval. Answer from your own documents. See learn RAG by building.
  4. Tools and agents. Let the model call functions in a loop. See your first agent.
  5. Evals. Measure quality instead of trusting a demo. See learn evals first.
  6. Ship. Put it online and watch real use.

Time budget

A realistic plan is five to eight hours a week for twelve weeks. Weeks one to three: steps 1 and 2. Weeks four to six: retrieval. Weeks seven to nine: an agent with two or three tools. Weeks ten to twelve: evals, a deployment and a write-up. The write-up matters, because it becomes your portfolio (see portfolio that gets interviews).

Common traps

  • Course hopping. Watching ten courses and building nothing. After each lesson, build something with it that day.
  • Framework first. Learn the raw API before a framework, or you will not know what the framework is hiding.
  • Only toy demos. A chatbot over one PDF is a start. Move on to something with real users, even three.
  • No measurement. If you cannot say whether version two is better than version one, you are not engineering yet.

Tools you need

A laptop, Python or TypeScript, git, and a model endpoint. For a free local model, install Ollama. You can also run services, databases and agents together on your machine with the open-source Flisk CLI, which starts a stack from a service.json per service: flisk.sh/docs. More on local setups is in running AI agents locally.

Keep a learning log in a plain text file: the date, what you built, what broke and what you changed. It costs two minutes a day, and after a month it shows you which skills are growing and which ones you keep avoiding.

Questions people ask

Do I need to know machine learning first?

No. Most AI engineering uses existing models through APIs. Learning ML theory helps later but is not required to build and ship useful features.

Python or TypeScript?

Use the one you know. Python has more examples, TypeScript is fine for web products. The concepts are the same.
