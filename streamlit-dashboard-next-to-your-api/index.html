How to run a Streamlit dashboard next to your local API

Streamlit turns a Python script into a web page. Next to an API it makes a quick internal dashboard, if you get the bind address and the API address right.

A Streamlit dashboard is one Python file that calls your API and draws the result. Run it with streamlit run app.py --server.port 8501 --server.address 0.0.0.0. The bind address matters in a container: the default only accepts connections from inside, so the page would not load from your browser. Read the API address from an environment variable so the same file works on your host and in a stack.

The app

import os

import pandas as pd
import requests
import streamlit as st

API = os.environ.get("API_URL", "http://127.0.0.1:4000")

st.title("Predictions")


@st.cache_data(ttl=30)
def predict(values: tuple) -> dict:
    r = requests.post(f"{API}/predict", json={"values": list(values)}, timeout=5)
    r.raise_for_status()
    return r.json()


cols = st.columns(4)
values = tuple(c.number_input(label, value=v) for c, label, v in
               zip(cols, ["sepal l", "sepal w", "petal l", "petal w"], [5.1, 3.5, 1.4, 0.2]))

try:
    result = predict(values)
    st.metric("label", result["label"], f"{result['probability']:.0%}")
except requests.RequestException as exc:
    st.error(f"API not reachable: {exc}")

Three habits keep a dashboard dependable. Cache calls with st.cache_data and a ttl, because Streamlit reruns the whole script on every interaction. Set a timeout on every request. And catch request errors and show them on the page, so a down API looks like a message and not a stack trace. Run it on the host with pip install streamlit requests pandas and streamlit run app.py, which serves on port 8501.

In a container

FROM python:3.12-slim
WORKDIR /app
RUN pip install --no-cache-dir streamlit==1.40.2 requests pandas
COPY app.py .
EXPOSE 8501
CMD ["streamlit", "run", "app.py", "--server.port", "8501", "--server.address", "0.0.0.0", "--server.headless", "true"]

Pin the Streamlit version you tested, since its API changes between releases. --server.headless true stops it asking for an email or opening a browser. Streamlit has a health endpoint at /_stcore/health that returns ok, which is what a health check should call.

The Flisk way

Make the dashboard a bring-your-own resource built from that Dockerfile, in the same stack as the API:

flisk resource panel --type bring-your-own --stack ml --dockerfile ./Dockerfile --yes

Then edit its service.json:

{
  "appName": "panel",
  "appType": "bring-your-own",
  "stack": "ml",
  "port": 8501,
  "dockerfile": "./Dockerfile",
  "webUi": true,
  "healthCheckPath": "/_stcore/health",
  "dependsOn": ["scorer"],
  "env": { "API_URL": "http://scorer:4000" }
}

webUi: true gives the dashboard its own host name, panel.<project>.localhost, with no path prefix, which a page served from / needs. dependsOn makes it start after the API. The value of API_URL is the API's service name and port on the stack's network. Replace 4000 with the port in the API's own service.json. From a container, 127.0.0.1 is the container itself, so never use it there.

flisk config verify
flisk up ml
flisk status
flisk logs --service panel --tail 50

flisk status prints the dashboard URL. Streamlit uses a WebSocket for its live updates, and I could not check that every proxy setup passes it, so if the page loads but stays on a spinner, test the direct container port and check the flisk logs output. For the API side see serving a scikit-learn model with FastAPI, and for the layout of an API plus a UI see a FastAPI backend and React frontend locally.

Pitfalls

  • Heavy work on every rerun. Load models and data inside cached functions, or each click repeats them.
  • Not an app framework. Streamlit has one page of state per browser tab and no real login. Use it for internal views, not for a product with accounts.
  • Secrets in the script. Pass keys as environment variables, and keep them out of the repository.
  • Data from a database. If the dashboard reads a database directly, give it a read-only role, see ClickHouse for local analytics for an analytics store to read from.

When a dashboard is only for you and reads files, you may not need a stack at all, see DuckDB and Parquet.

Questions people ask

Why can't I open my Streamlit app running in Docker?

The server binds to localhost inside the container by default. Start it with --server.address 0.0.0.0 and publish the port.

How do I health check a Streamlit container?

Request /_stcore/health. It returns ok when the server is up.

Why is my Streamlit app slow after every click?

Streamlit reruns the script on each interaction. Wrap data loading and API calls in st.cache_data or st.cache_resource.
