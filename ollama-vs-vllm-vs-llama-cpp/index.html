Ollama vs vLLM vs llama.cpp: which should you use?

Three popular ways to serve open models. What each is built for, how they differ on hardware, concurrency and setup, and a simple rule for choosing.

Use Ollama for the easiest local setup, llama.cpp when you want direct control and run on modest hardware, and vLLM when you serve many concurrent users on a GPU server. All three can expose an OpenAI-compatible API.

Treat the table as a starting point, not a verdict. Features change quickly in all three projects, so check each project's documentation for hardware support and model formats before you plan around a limitation.

Ollama

A single installer with a model library and a local API. You pull a model by name and it handles the rest. Good for development, demos and personal use. You give up some control over low-level options.

ollama run llama3.2

llama.cpp

A C/C++ inference engine that runs GGUF models, including quantized ones, on CPU and many GPU backends. It includes llama-server, an HTTP server with an OpenAI-compatible API.

llama-server -m ./model-q4_k_m.gguf --port 8080 -c 4096

Check llama-server --help for the flags your build supports, including GPU offload options.

llama.cpp is also the engine behind many other local tools, so learning its flags pays off elsewhere. Its builds target different GPU backends, so pick the build that matches your hardware, and check the project's README for the current list.

vLLM

A Python serving engine built for throughput: it batches requests continuously and manages the key-value cache efficiently, so many users share one GPU well. It loads Hugging Face format weights.

pip install vllm
vllm serve <huggingface-model-id> --max-model-len 8192

It needs a supported GPU and a matching driver stack, which is the main setup cost. See how to serve an open model with an OpenAI-compatible API.

A simple rule

  • One person, one machine: Ollama.
  • Odd hardware, embedded, or you want a small binary: llama.cpp.
  • A team, a GPU, real traffic: vLLM.

Because all three speak a similar API, you can start with Ollama and change the base URL later. Benchmark with your own prompts before deciding, as in test an open model before you switch.

Do not choose by benchmark charts you saw online. Speed depends on your model, your quantization, your prompt length and how many requests arrive at once. A ten minute test on your own hardware is worth more than any chart.

Questions people ask

Can I use the same client code with all three?

Mostly yes. They offer OpenAI-compatible endpoints, so you change the base URL and model name. Check each one's docs for unsupported parameters.

Is vLLM faster than Ollama?

For many simultaneous requests on a GPU, vLLM is generally built to do better. For a single user on a laptop the difference is small and Ollama is easier.
