Docker vs gVisor vs Firecracker for agent sandboxes

Compare containers, gVisor and Firecracker microVMs on isolation, startup time, compatibility and effort, so you can pick the right one for agent code.

Use plain Docker for code you mostly trust, gVisor when you want stronger isolation without leaving the container workflow, and Firecracker microVMs when the code is hostile or from many different users. The stronger the wall, the more setup and overhead you pay.

What each one actually isolates

Docker uses Linux namespaces and cgroups. Every container makes system calls straight to the host kernel. gVisor puts a user-space kernel between the container and the host, so the app talks to gVisor, and gVisor makes a much smaller set of calls to the real kernel. Firecracker starts a lightweight virtual machine with its own guest kernel, using the host's KVM.

Exact startup and speed numbers depend on your hardware and workload, so measure them on your own jobs.

Trying gVisor with Docker

Install gVisor following its documentation, register the runsc runtime with Docker, then select it per container:

docker run --rm --runtime=runsc --network none python:3.12-slim python -c "print(1 + 1)"

The rest of your flags stay the same. That is gVisor's main appeal: the same images and commands, a different runtime.

When Firecracker is worth it

Firecracker needs Linux with KVM, a root filesystem image, a kernel image and a small API to start each VM. Most teams do not run it by hand. They use a platform built on microVMs, or a hosted sandbox service. It pays off when you run code from many untrusted users, need fast snapshot and restore, or must show a strong isolation story to customers.

A simple decision rule

  • Your own agent, your own repo, a human reviewing: hardened Docker. See the Docker recipe.
  • Agent reads the open web and runs code: gVisor or a microVM.
  • Many tenants running arbitrary code: microVMs, or a provider that runs them. See choosing a provider.

Whatever you pick, still limit network and secrets. A stronger wall does not help if you hand over the keys.

Pitfalls to plan for

With gVisor, some programs fail because a system call or a file feature is missing, so run your real jobs, not a hello world, before you commit. With Firecracker, plan for kernel and image maintenance, since you now own the guest operating system. With plain Docker, keep the host kernel and Docker itself updated, because that is what protects you from known escapes.

Questions people ask

Is gVisor slower than Docker?

It can be, especially for workloads that make many system calls or heavy file I/O. CPU-bound code is usually close to native. Benchmark your own workload.

Can Firecracker run on my laptop?

Only on a Linux host with KVM access. On a Mac you would need a Linux VM that supports nested virtualization, which is not always available.
