Windows and WSL local development

How to reach a WSL2 service from Windows, a phone or a teammate

A service in Ubuntu on WSL2 is easy to open from the same PC and hard to open from anything else. The network mode decides which.

A server listening in WSL2 is reachable from your Windows browser at http://localhost:<port> because WSL forwards localhost by default. A phone or another computer cannot reach it in the default NAT mode. To allow that, switch WSL to mirrored networking, or add a netsh portproxy rule, and then allow the port through the firewall.

Same PC: nothing to do

In the default NAT networking mode, WSL2 has its own virtual network and IP address. Microsoft's localhost forwarding relays ports that a Linux process opens on localhost to the Windows side. A dev server on port 3000 in Ubuntu opens in Edge at http://localhost:3000. Two details help:

  • The Linux process must listen on localhost or 0.0.0.0. Both are relayed. Binding to the WSL virtual IP is not.
  • If another Windows program holds the same port, Windows wins or the relay fails. Check with netstat -ano | findstr :3000 in PowerShell.

Another device: mirrored mode

On Windows 11 22H2 or later with a current WSL, mirrored networking makes WSL share the Windows network interfaces. Create or edit %UserProfile%\.wslconfig:

[wsl2]
networkingMode=mirrored

Run wsl --shutdown, reopen Ubuntu, and a service listening on 0.0.0.0 in Linux is reachable at the Windows machine's LAN address. Mirrored mode also lets Linux reach services on Windows with localhost. Two caveats: inbound connections are still filtered by the Hyper-V firewall, and Microsoft documents a command to open it for WSL, so read the current Microsoft page for Set-NetFirewallHyperVVMSetting before you change anything. Also check that your WSL version is recent with wsl --version and wsl --update.

Another device: portproxy on older setups

Without mirrored mode, forward a Windows port to the WSL address. In an administrator PowerShell:

$ip = (wsl hostname -I).Trim().Split(" ")[0]
netsh interface portproxy add v4tov4 listenport=3000 listenaddress=0.0.0.0 connectport=3000 connectaddress=$ip
netsh interface portproxy show all

The WSL address changes after a restart, so the rule goes stale. Delete and recreate it when that happens. Remove one with netsh interface portproxy delete v4tov4 listenport=3000 listenaddress=0.0.0.0.

Either way, Windows Defender Firewall must allow inbound TCP on that port, and only on the Private profile if you can. Opening a dev server to a coffee shop network is how credentials leak.

What Flisk does by default

Flisk binds the ports it publishes, the Traefik gateway and Postgres, to 127.0.0.1 by default. That means they are reachable from the same machine only, which is the safe default. When you do want a phone to test a page, the environment variable FLISK_BIND_ADDRESS=0.0.0.0 widens the bind. Flisk's cheat sheet lists it for exactly this use. flisk doctor warns when it sees a wildcard bind address, with the advice to unset it and keep dev ports on 127.0.0.1 unless you test from another device on purpose. In that case treat the warning as a reminder, and unset the variable when you are done.

FLISK_BIND_ADDRESS=0.0.0.0 flisk up

One limit to plan for. The gateway chooses a service by hostname, as in api.myproject.localhost. A phone does not resolve .localhost names to your PC, so a routed URL will not work from it as it stands. An app whose URL does not depend on the hostname is easier to test from a phone, and Flisk has no documented setting that rewrites the route hostnames, so do not count on one.

Pitfalls

  • Binding to 127.0.0.1 inside Linux in mirrored mode keeps the service private to the machine. Bind to 0.0.0.0 if you want the LAN.
  • VPN software. It can break NAT forwarding or mirrored mode. Disconnect to test.
  • Security. Anyone on the same network can reach an open dev port. Do not expose databases.

Next step: if you can reach the service but names fail, see the hosts file guide. If WSL is eating memory while you test, read limiting WSL2 memory.

Questions people ask

Why can my browser open a WSL service but my phone cannot?

In NAT mode WSL only forwards localhost to the Windows host. Other devices need mirrored networking or a netsh portproxy rule, plus a firewall rule.

Where do I turn on mirrored networking?

In %UserProfile%\.wslconfig under [wsl2] set networkingMode=mirrored, then run wsl --shutdown. It needs Windows 11 22H2 or later.

Does Flisk expose ports to the network?

No. It binds published ports to 127.0.0.1 by default. FLISK_BIND_ADDRESS can widen that, and flisk doctor warns when it does.
