Tilt vs Docker Compose for local development: how to choose

Compose describes what runs. Tilt watches your code and updates what runs. You can use either alone or both together.

Use Docker Compose when you want to describe a set of containers and start them. Add Tilt when you want a live dashboard, per-service rebuilds and code sync into running containers as you edit. They are not strict rivals: Tilt can drive an existing Compose file, so you can adopt it without rewriting anything.

What each tool is

Docker Compose reads a compose.yaml and creates containers, networks and volumes from it. It ships with Docker, every developer already knows it, and the file is plain YAML. Recent Compose versions also have docker compose watch, which can sync files into a container or rebuild an image when files change.

Tilt is a development orchestrator. You write a Tiltfile in Starlark (a Python dialect). Tilt builds images, starts them, watches your files and shows every service and its logs in a web UI, by default on http://localhost:10350. Its live_update feature copies changed files into a running container and can run a command there, so you often skip a full image rebuild. Tilt can deploy to Docker Compose or to Kubernetes.

Using Tilt on top of an existing Compose file

If you already have a compose.yaml, a Tiltfile can be three lines:

docker_compose('./compose.yaml')

# optional: sync source into the api container instead of rebuilding
docker_build('myorg/api', './api',
  live_update=[sync('./api/src', '/app/src')])

Then run tilt up. Compose still owns the service definitions. Tilt adds the dashboard and the live update. Check the Tilt docs for the exact image name matching rule between docker_build and your Compose image: field, because that is where first attempts usually go wrong.

When plain Compose is the better choice

  • You have two to five services and each already has a Dockerfile.
  • Nobody on the team wants to learn Starlark or install another binary.
  • compose watch is enough for your hot reload needs. See Docker Compose hot reload for how it behaves.
  • The same Compose file also runs on a VPS or in CI, and you want one file for all of them.

When Tilt is worth it

  • You have enough services that a dashboard with per-service status saves real time.
  • You develop against Kubernetes and want the same tool for the local loop. Tilt supports this directly, and it is the main reason many teams pick it.
  • You need to mix containers with host commands, for example a database in a container and a frontend dev server on the host.
  • Your team already has someone who maintains Starlark happily.

Where Flisk fits

Flisk sits one layer above both. On its Docker path it generates the Compose files and the Tiltfile from a small service.json per service, then runs Tilt for you. That removes the hand-written Tiltfile, but it also means you work in Flisk's conventions, and it needs Docker, Tilt, Node.js 22.12 or newer and Bun 1.2 or newer on the machine. Run flisk doctor to see what is missing.

If you outgrow it, flisk eject writes an EJECTED.md that explains how to run the generated Tiltfile with plain Tilt. It copies nothing, so the generated files stay where Flisk put them. Treat it as a map, not an exit script. If you already like writing your own Tiltfile, you do not need Flisk. If you do not, see the decision guide.

Pitfalls

  • Tilt does not replace Compose features such as depends_on health ordering. With docker_compose(), Compose semantics still apply.
  • Live update only helps when your container runs a process that reloads on file changes. Otherwise add a restart step.
  • Two sources of truth is the real risk of the combined setup. Keep service definitions in Compose and only build logic in the Tiltfile.

Questions people ask

Can Tilt run a docker-compose.yml?

Yes. Call docker_compose('./compose.yaml') in a Tiltfile and run tilt up. Compose keeps defining the services and Tilt adds the dashboard and live update.

Does Tilt replace Docker Compose?

Not necessarily. Tilt can use Compose as its backend, or deploy to Kubernetes instead. It is an orchestrator for the dev loop, not a file format for containers.

Is docker compose watch the same as Tilt live_update?

They overlap. Both sync files into a running container. Tilt adds a web UI, host commands and Kubernetes support. Compose watch needs no extra tool.
