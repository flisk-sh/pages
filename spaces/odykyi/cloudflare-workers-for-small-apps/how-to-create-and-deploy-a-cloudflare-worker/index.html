How to create and deploy a Cloudflare Worker

From an empty folder to a live Worker URL: scaffold, run locally, log in and deploy with Wrangler, and what the config file does.

Run npm create cloudflare@latest, pick a Worker template, test it with npx wrangler dev, then ship it with npx wrangler deploy. You get a workers.dev URL you can call immediately.

Scaffold the project

npm create cloudflare@latest my-worker
cd my-worker

The prompts ask for a template and language. Choose a plain Worker with TypeScript or JavaScript. You can also write the files by hand, as a Worker is just a module with a fetch handler.

The smallest Worker

export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    if (url.pathname === "/health") {
      return Response.json({ ok: true });
    }
    return new Response("Hello from a Worker");
  },
};

The handler gets a standard Request and must return a Response. env holds your bindings and secrets. ctx.waitUntil lets work continue after the response is sent.

The config file

# wrangler.toml
name = "my-worker"
main = "src/index.js"
compatibility_date = "2025-01-01"

compatibility_date pins runtime behaviour so updates do not change your app silently. Set it to the date you create the project. Bindings for databases and storage are added to this file too, see using D1.

Run locally, then deploy

npx wrangler dev
curl http://localhost:8787/health

npx wrangler login
npx wrangler deploy

The first deploy asks you to register a workers.dev subdomain. After that the Worker is live at my-worker.YOUR-SUBDOMAIN.workers.dev. Local behaviour is covered in developing locally.

Routes and custom domains

By default a Worker answers on a workers.dev address. To serve it on your own domain, add the domain to Cloudflare and attach a route or custom domain in the dashboard or config.

routes = [
  { pattern = "api.example.com", custom_domain = true }
]

Check the Workers docs for the current routing options, as the config keys evolve. Keep the workers.dev address while you test, then switch.

After the first deploy, read the output carefully. It prints the URL, the version ID and the bindings it attached. Open the URL, then run npx wrangler tail in another terminal and refresh, to confirm requests reach the new version and to see any errors as they happen.

When a Worker is the wrong tool

  • You need a long-running process or a native binary. Workers have execution limits and a restricted runtime.
  • You need lots of Node-only libraries. Many work, some do not.
  • You want a static site only. A static host is simpler, see publishing small apps.

Questions people ask

Is there a free plan for Workers?

Yes, with daily request and CPU time limits. See the limits article in this series and check Cloudflare's current limits page.

Do I have to use TypeScript?

No. JavaScript works. TypeScript is supported and Wrangler can generate types for your bindings.
