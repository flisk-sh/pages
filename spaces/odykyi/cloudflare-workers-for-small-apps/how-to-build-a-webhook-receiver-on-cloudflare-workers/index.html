How to build a webhook receiver on Cloudflare Workers

Accept webhooks from GitHub, Stripe or a bot platform: verify the HMAC signature, respond fast, and process the event without blocking.

Read the raw request body, compute an HMAC of it with your shared secret, compare it to the signature header in constant time, and only then act on the event. Respond quickly and do slow work after the response.

Why verify

A webhook URL is public. Without a signature check, anyone who finds it can send fake events. Providers sign each request with a shared secret so you can prove it came from them. Store that secret as a Worker secret.

Verify an HMAC signature

This example matches the common pattern of a hex SHA-256 HMAC in a header. Providers differ in header name and format, such as a sha256= prefix, so read your provider's docs.

async function verify(secret, body, signatureHex) {
  const enc = new TextEncoder();
  const key = await crypto.subtle.importKey(
    "raw", enc.encode(secret),
    { name: "HMAC", hash: "SHA-256" }, false, ["verify"]
  );
  const sig = Uint8Array.from(
    signatureHex.match(/../g).map((h) => parseInt(h, 16))
  );
  return crypto.subtle.verify("HMAC", key, sig, enc.encode(body));
}

crypto.subtle.verify compares in constant time, which a plain string comparison does not.

The handler

export default {
  async fetch(request, env, ctx) {
    if (request.method !== "POST") return new Response(null, { status: 405 });
    const body = await request.text();
    const header = request.headers.get("x-signature") || "";
    if (!/^[0-9a-f]+$/i.test(header) || header.length % 2 !== 0 ||
        !(await verify(env.WEBHOOK_SECRET, body, header))) {
      return new Response("invalid signature", { status: 401 });
    }
    const event = JSON.parse(body);
    ctx.waitUntil(handle(event, env));
    return new Response("ok");
  },
};

Read the body as text once, and verify that exact string. Parsing and re-serialising JSON changes the bytes and breaks the check.

Respond fast, process later

Providers retry if you are slow or return an error. Return 200 quickly and use ctx.waitUntil for light work. For heavy or must-not-lose work, write the event to a queue or a D1 table first, then process it from there.

Test with a signed request

Generate a valid signature with the same secret and send it with curl to check both the happy path and rejection.

BODY='{"id":"evt_1","type":"ping"}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $NF}')
curl -i -X POST http://localhost:8787 -H "x-signature: $SIG" -d "$BODY"
curl -i -X POST http://localhost:8787 -H "x-signature: 00" -d "$BODY"

The first call should return 200 and the second 401.

Handle duplicates and replays

  • Store the event ID and skip IDs you have seen, because providers can deliver the same event more than once.
  • If the provider sends a timestamp, reject events that are too old.
  • Log the event type and ID, never the full body if it holds personal data.

For the end-to-end build see creating a Worker and test locally with wrangler dev using a tunnel or a recorded request.

Questions people ask

Why does my signature check always fail?

Usually the body was modified before hashing, the wrong secret was used, or the header format differs from what you assumed. Hash the raw text and read your provider's docs.

Can I process the webhook in the same request?

Only if it is quick. Otherwise acknowledge first and process in the background so the provider does not time out and retry.
