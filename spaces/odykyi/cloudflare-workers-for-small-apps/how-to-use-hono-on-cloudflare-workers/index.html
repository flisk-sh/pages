How to use Hono on Cloudflare Workers

Add routing, middleware and JSON handling to a Worker with Hono, a small web framework, instead of hand-written URL checks.

Install Hono with npm i hono, create an app with routes, and export it as the default export of your Worker. It gives you routing, middleware and helpers while staying small enough for the edge.

Install and write routes

npm i hono
import { Hono } from "hono";

const app = new Hono();

app.get("/health", (c) => c.json({ ok: true }));

app.get("/notes/:id", async (c) => {
  const row = await c.env.DB
    .prepare("SELECT * FROM notes WHERE id = ?")
    .bind(c.req.param("id"))
    .first();
  return row ? c.json(row) : c.json({ error: "not found" }, 404);
});

export default app;

Hono's app object has a fetch method, so exporting it works as a Worker. Bindings arrive as c.env.

Middleware

import { cors } from "hono/cors";

app.use("/api/*", cors({ origin: "https://example.com" }));

app.use("/api/*", async (c, next) => {
  const key = c.req.header("authorization");
  if (key !== "Bearer " + c.env.API_TOKEN) {
    return c.json({ error: "unauthorized" }, 401);
  }
  await next();
});

Do not set CORS origin to a wildcard on endpoints that use credentials or are expensive.

Validate input

Never trust a request body. Parse it and check the fields before use.

app.post("/notes", async (c) => {
  const body = await c.req.json().catch(() => null);
  if (!body || typeof body.text !== "string" || body.text.length > 2000) {
    return c.json({ error: "bad input" }, 400);
  }
  await c.env.DB.prepare("INSERT INTO notes (body) VALUES (?)").bind(body.text).run();
  return c.body(null, 201);
});

Hono also has validator middleware that works with schema libraries like Zod.

Organise a growing app

Split routes into files and mount them on the main app, which keeps each file short and testable.

// notes.js
import { Hono } from "hono";
export const notes = new Hono();
notes.get("/", (c) => c.json([]));

// index.js
import { Hono } from "hono";
import { notes } from "./notes.js";
const app = new Hono();
app.route("/api/notes", notes);
export default app;

Handle errors in one place with app.onError so every failure returns a consistent JSON shape.

Keep an eye on bundle size after adding middleware packages. Run npx wrangler deploy --dry-run --outdir dist to see the bundled output size without deploying, and drop anything you do not use.

Pitfalls

  • Typing c.env: pass your bindings type as a generic, new Hono<{ Bindings: Env }>().
  • Middleware order matters. Register auth before the routes it protects.
  • A framework adds bundle size. For three routes, plain fetch may be simpler. Compare with the minimal version in creating a Worker.

Questions people ask

Do I need a framework on Workers?

No. A plain fetch handler is enough for small APIs. A framework helps when routes, middleware and validation start to pile up.

Does Hono work outside Cloudflare?

Yes, it runs on other runtimes such as Node, Deno and Bun, which keeps your code portable.
