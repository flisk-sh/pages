How to avoid port clashes between apps in a monorepo

Five apps default to 3000 and the second one to start loses. A short port convention removes the whole class of problem.

Give every app a fixed port, read it from the PORT environment variable, and keep the list in one file. Frameworks default to 3000, 5173 or 8080, so two apps started together fight for the same number, and the loser exits or silently moves to another port that nothing else knows about.

Why it goes wrong

Vite tries 5173 and, if it is taken, moves to 5174 unless strictPort is set. Next.js defaults to 3000 and, in dev, picks the next free port if 3000 is busy. A Node server that hard-codes 3000 throws EADDRINUSE. The result is that the URL your other service has in its config is wrong, and the failure shows up as a connection error rather than a port message. For the basic "address already in use" fix, see how to fix "port already in use".

A convention that holds

  1. Pick ranges by role. For example 3000 to 3099 for websites, 4000 to 4099 for APIs, 6000 to 6099 for workers or admin tools. Within a range, assign numbers once.
  2. Read PORT. Every dev script takes its port from the environment: const port = Number(process.env.PORT ?? 4000). Do not hard-code it twice.
  3. Fail instead of drift. For Vite set server.strictPort: true so it errors rather than moving. For Next.js use next dev -p $PORT or --port.
  4. Keep one list. A table in the root README or a single ports.json that scripts read. Two copies will disagree.
  5. Use names for cross-service calls. Reference API_URL from an env var that is built from the same list.
// vite.config.ts
export default defineConfig({
  server: {
    port: Number(process.env.PORT ?? 3000),
    strictPort: true,
  },
})

What Flisk does

Each service.json carries its port. For containers, Flisk uses ranges by type: backends 4000 to 4999, frontends 3000 to 3999, workers 6000 to 6999 when set, and 4000 to 5999 for MCP and bring-your-own services. When you scaffold with flisk resource, it picks the next free port in the type's range unless you pass --port:

flisk resource api --type backend --stack main
flisk resource web --type frontend --stack main --port 3010
flisk resources --ports

flisk resources --ports prints every assignment so you can see the whole list at once. Checks you get for free:

  • flisk doctor reports a declared port that is invalid and two routed resources that use the same port.
  • For services that run as local processes, flisk up passes the port as PORT, refuses to start when two services share a port, and when a port is already in use it names the process that holds it.

The Docker ranges do not apply to local processes, so for those you choose the numbers. A service in apps/web/service.json then looks like:

{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "web",
  "appType": "frontend",
  "command": "pnpm dev",
  "port": 3000,
  "dependsOn": ["api"],
  "env": { "API_URL": "http://localhost:4000" }
}

If you run several Flisk container projects at once, Traefik and Postgres host ports also move to a free port when the default is taken; the layout guide describes the ranges Flisk uses. That is a separate matter from your own service ports.

Pitfalls

  • Old processes. A dev server that was killed badly keeps its port. Find it with lsof -i :4000 on macOS and Linux.
  • Ports below 1024. They need privileges on Linux and macOS; stay above.
  • Docker published ports. A container that publishes 5432 collides with a Postgres installed on the host. Choose another host port.
  • The port inside versus outside a container. The number in your browser URL is the host port, the number the app listens on is the container port. They need not match.

Related: where to keep the variables that hold URLs, and using *.localhost URLs instead of port numbers if you would rather stop remembering numbers.

Questions people ask

Why did my Vite app start on a different port?

Vite moves to the next free port when the default is busy. Set server.strictPort to true so it fails instead.

How do I list all ports in a Flisk project?

Run flisk resources --ports. It prints each resource with its assigned port.

Which ports should services avoid?

Ports below 1024, and common defaults used by tools on your machine such as 5432 for Postgres, 6379 for Redis and 3306 for MySQL.
