Vibe coding without the mess

How to run a vibe-coded app locally and share it safely

Get an AI-built app running on your own machine with its database and services, then put a page online for others to see, without exposing secrets or private data.

Run the app locally first, with its database and any other services started by one command, then share only what is safe to be public. A static page can go to a free public link in one command, while an app with a backend needs real hosting and a security pass.

Start locally with one command

Apps built by an agent often need a database, a queue or a second service. Setting those up by hand is where many projects stall. The open-source Flisk CLI is a local development tool for this: each service gets a service.json, and flisk up starts the stack. Services with a command run as local processes, others run on Docker.

npx @flisk-sh/flisk demo          # see it work first
flisk resource api --type backend  # create a service
flisk up                           # start the stack
flisk status --json                # check what is running
flisk doctor                       # check your environment

It is a local tool, not a production orchestrator. See the docs for details. If you would rather describe the app in words and get the commands back, Build Me an App does that.

Check it like a user

Open every URL yourself. Create an account, add data, reload, sign out and sign in again. Look at the terminal for errors you did not see in the browser. This is cheap and catches what the agent said was done but is not.

Write down the three things you checked and the one thing that surprised you. If nothing surprised you, you probably did not click around enough. Real users do odd things: back buttons, empty fields, double clicks.

Decide what is safe to share

  • Static pages and Markdown. Safe if they contain nothing private. Check the page source for keys and internal URLs.
  • Apps with a backend. Only share after the security checklist.
  • Local-only tools. Keep them local.

A good habit is to share the smallest thing that answers your question. If you want feedback on the look of a screen, a static export or a screenshot is enough, and it avoids exposing a running backend with real accounts and data behind it.

Put a page online

For a static page the agent built, Pages publishes it to a free public link:

npx -y @flisk-sh/pages publish page.html --wait

Remember the link is public, not private. Do not publish anything you would not put on a billboard. For apps that need a server, read publish pages and host small apps.

Pitfalls

  • Sharing a tunnel URL to your laptop while debug mode is on.
  • Real customer data in a demo database.
  • Hard-coded localhost URLs that break for other people.

Keep secrets in environment variables and out of commits (see the git steps).

Questions people ask

Do I need Docker to run an AI-built app locally?

Not always. Services that have a start command can run as plain local processes. Docker is needed for databases and other container-based services unless you install them yourself.

Is a free public link fine for a prototype?

Yes, for something you are happy to make public. Do not use it for private or customer data.

Try it

Run the app you just built, with its database, on your own machine.

Flisk is an open-source CLI that starts your services, databases and agents locally from one service.json per service. It is a local development tool, not a production orchestrator.
