Vibe coding without the mess

Why your AI-built app keeps breaking, and how to stop it

When each new prompt breaks an old feature, the cause is usually missing tests, big prompts and lost context. Here is how to diagnose it and get back to steady progress.

An AI-built app keeps breaking because nothing checks old behaviour, each prompt changes too much, and the agent forgets earlier decisions. Fix it by adding tests, shrinking the steps, and writing the project's rules down in a file the agent reads every session.

Cause 1: nothing guards old behaviour

If a feature worked yesterday and is broken today, you need a test that would have said so. Start with a regression test for the exact bug before you ask for a fix. That way the fix is proven and the bug cannot come back silently. See adding tests.

Cause 2: prompts that change too much

"Redesign the dashboard and add export" touches many files. Break it down. Use git diff --stat after each step; if a prompt about a button changed the database code, restore and ask again with tighter scope: "Only edit src/ui/Dashboard.tsx."

It also helps to say what must stay the same: "existing tests must still pass and the public routes must not change". Agents optimise for the instruction in front of them, so a stated invariant is one more thing they will try to respect.

Cause 3: the agent forgets or contradicts itself

Models work from the context in front of them. In a long session, early decisions drop out. Duplicate functions, two ways to fetch data, and renamed fields are the signs. Put the decisions in a short file such as AGENTS.md or CLAUDE.md at the repo root:

# Project rules
- Stack: Node 20, Express, SQLite via better-sqlite3.
- All data access goes through src/db.js. Do not query elsewhere.
- Run `npm test` after every change and fix failures.
- Do not add dependencies without asking.
- Keep changes to the files named in the task.

Most coding agents read a file like this at the start of a session. Check your tool's docs for the file name it expects.

Cause 4: fixing symptoms in a loop

If the same error survives three attempts, stop prompting "fix it". Paste the full error, the relevant file, and ask the agent to explain the cause before changing anything. Then check the explanation against the code. Often the real problem is a wrong assumption, such as a field name or an environment variable.

When to start a new session

If the agent is looping or the conversation is very long, commit what works, open a fresh session, and give it the spec and rules file. A clean context often beats a long argument. For longer projects, see agent memory and context engineering.

Before you close the old session, ask it for a short summary of the decisions made, the files involved, and what is still broken. Review that summary and paste the useful parts into the new session. It is quicker than rediscovering them.

Questions people ask

Should I rewrite the app from scratch?

Rarely. First add tests around what works, then refactor in small steps. A rewrite by an agent without tests tends to reproduce the same problems.

Why does the agent keep ignoring my instructions?

Instructions buried in a long chat get lost. Put rules in a file the tool loads at session start, keep it short, and repeat the critical rule in the task itself.
