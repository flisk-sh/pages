What an agent sandbox costs and how to keep it low

Where sandbox cost comes from, how to estimate cost per agent run, and the habits that cut it: short lifetimes, snapshots, warm pools and strict limits.

Sandbox cost is mostly time multiplied by size, plus anything you store. To keep it low, give every sandbox a short time limit, delete idle ones, size them small by default, and track cost per agent run so surprises show up early. Check your provider's current price list, since rates change.

Where the money goes

  • Compute time: CPU and memory for each second the sandbox exists, running or idle.
  • Size: more CPUs and memory cost more per second.
  • Storage: volumes, images and snapshots that stay after the run.
  • Network: outbound data, on some providers.
  • Your own host: if you self-host, the machine runs even when no agent does.

A simple estimate

Estimate per run with a formula you can fill in from your provider's rates:

cost_per_run = (seconds_alive * rate_per_second_for_size) + storage_kept + network_out

Then multiply by runs per agent task. An agent that runs tests five times per task, each 90 seconds, uses 450 sandbox seconds. Measure real numbers from a week of logs, not guesses, and look at the 95th percentile, not only the average.

Habits that cut cost

  1. Time to live: every sandbox gets a hard maximum life, and an idle timeout of a few minutes.
  2. Small defaults: use a small size and a named bigger profile for builds. See resource limits.
  3. Reuse over recreate: keep a warm pool or restore from a snapshot instead of installing packages on every run. See snapshots.
  4. Batch commands: let the agent run several commands in one sandbox session instead of starting a new one per command.
  5. Run cheap checks first: lint locally before spending a sandbox on tests.

Per-run budgets

Give each agent task a budget in sandbox-seconds and a maximum number of sandbox starts. When the budget is spent, stop and report. Without one, a model stuck in a retry loop will happily run for hours.

Use one account for several providers

If you compare providers, separate accounts and bills make cost tracking hard. Fleet offers agent sandboxes from several providers behind one API key and one balance. It is in early beta, so check its current limits and prices on the site and try it with a small job before depending on it.

Pitfalls

The usual surprises are idle sandboxes that nobody destroyed, retries that start a new sandbox each time, and large images pulled on every run. Add a nightly job that lists every sandbox older than your maximum life and deletes it. Check the list by hand after the first week of real use.

Questions people ask

Is self-hosting sandboxes cheaper?

It can be at steady high volume, but you pay for idle capacity and for the time you spend maintaining isolation. For occasional use, pay-per-second hosted sandboxes are usually simpler.

How do I find a runaway agent early?

Alert on sandbox starts per session and on total sandbox-seconds per task, with a hard stop at a limit you choose.

Run it in a sandbox
