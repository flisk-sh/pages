AI sandboxes for agents

What is an AI agent sandbox and why do you need one?

An agent sandbox is an isolated place where model-written code runs with limited files, network and resources. Learn what it protects, what it does not, and when you can skip it.

An AI agent sandbox is an isolated environment where code written by a model runs with strict limits on files, network, CPU, memory and time. You need one as soon as an agent can execute code, because a model can be wrong, or be tricked by text it reads, and that code would otherwise run with your permissions.

What a sandbox protects

Think about three things an agent-written script can reach if you run it directly on your machine: your files, your credentials and your network. A sandbox puts a wall around each.

  • Files: the code sees a scratch directory, not your home folder or your .ssh keys.
  • Network: the code can reach only hosts you allow, so it cannot send data elsewhere.
  • Resources: CPU, memory, process count and wall-clock time are capped, so a loop or a fork bomb cannot take down the host.

Why a model needs one

Models make plain mistakes: a wrong path in rm -rf, a script that installs a bad package, a loop that never ends. Those are accidents. The second risk is prompt injection: the agent reads a web page or an issue that contains instructions, and follows them. The code it then writes is, in effect, written by the attacker.

You cannot fix this by asking the model to be careful. You fix it by making the environment safe to be wrong in.

The layers of a sandbox

MicroVMSeparate kernel per sandboxFirecracker

Stronger isolation costs more startup time and setup effort. See Docker vs gVisor vs Firecracker for the trade-offs.

What a sandbox does not fix

A sandbox limits damage. It does not make the agent correct. If you give a sandbox a real API token and open network access, the code can still use that token. Secrets and network rules matter as much as the container itself, so read how to handle secrets before you wire one up.

When you can skip it

If an agent only calls tools you wrote, such as a fixed set of read-only API functions, there is no arbitrary code to isolate. You can also skip a sandbox for a coding agent that edits files in a throwaway checkout with human review before anything runs. The moment the agent runs shell commands or code it generated, add a sandbox.

Questions to ask before you build one

Before choosing tools, answer four questions. What can the code read? Where can it send data? How long and how much can it run? What happens to its output? Write the answers down as a short policy, even three lines. It will guide every later choice, from the container flags to the provider you pick, and it makes reviews easier because you can check the setup against the policy.

Questions people ask

Is a Docker container a sandbox?

Partly. A container isolates files and processes, but it shares the host kernel, so for hostile code you should add limits, drop capabilities, or use gVisor or a microVM.

Do I need a sandbox for a coding agent on my laptop?

If you review every command, you can run without one. If the agent runs unattended, use a container or a disposable VM with no access to your home directory.
