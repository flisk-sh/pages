Dockerfiles for development

Write Dockerfiles that build fast and reload well in development: layer caching, multi-stage builds, bind mounts and non-root users.

  1. Alpine or Debian slim for a development Docker imageSmaller is not always faster. For many Python and Node projects, a slim Debian image builds sooner and fails less.
    3 min
  2. How to bind mount source code into a container for developmentThe image has your code baked in, so every edit needs a rebuild. A bind mount replaces the baked-in copy with your live folder.
    3 min
  3. Docker BuildKit cache mounts for npm, pip and Go modulesAdd one package and the whole install layer reruns from scratch. A cache mount keeps the downloads so only the new package is fetched.
    4 min
  4. Docker ARG vs ENV: which one to use at build time and run timeBoth set a variable, but one disappears after the build and the other ships with the image. Picking wrong leaks data or breaks the app.
    4 min
  5. How to write a Dockerfile HEALTHCHECK that works in devSlim images often lack curl, so a copied HEALTHCHECK fails forever. Write one that matches what is in your image.
    3 min
  6. What to put in .dockerignore (and why builds get slow without it)If docker build starts with a long 'transferring context' step, the fix is usually a ten-line file.
    3 min
  7. Docker ENTRYPOINT vs CMD: how to override them in devOne line in a Dockerfile decides whether docker run image bash gives you a shell or passes the word bash to your app.
    4 min
  8. Multi-stage Dockerfile with separate dev and production stagesProduction images should not carry compilers or test tools, and dev images should not run a minified build. Stages let one file serve both.
    3 min
  9. How to run a Docker container as a non-root userContainers run as root unless you say otherwise. Changing that takes four lines, plus a plan for the files the app writes.
    4 min
  10. How to speed up Docker builds with layer cachingEvery code edit triggers a full npm install or pip install. The fix is the order of five lines in your Dockerfile, not a faster machine.
    4 min
