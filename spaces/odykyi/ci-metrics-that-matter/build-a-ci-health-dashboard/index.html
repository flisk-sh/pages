How to Build a Simple CI Health Dashboard for GitHub Repos

Collect run data on a schedule, compute pass rate, median, p90 and flips per workflow, publish a small report, or use a ready public dashboard. What each option can and cannot do.

A basic CI health dashboard needs a scheduled job that pulls recent runs with the gh CLI, computes a few numbers per workflow, and writes a report. You can have a working version in under an hour, or skip it with a public dashboard for public repos.

The scheduled collector

name: CI health
on:
  schedule:
    - cron: '0 6 * * *'
  workflow_dispatch:

permissions:
  actions: read
  contents: read

jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: node scripts/ci-health.mjs >> "$GITHUB_STEP_SUMMARY"
        env:
          GH_TOKEN: ${{ github.token }}

The summary shows up on the run page as Markdown, so you get a free report page with history of runs.

The script

// scripts/ci-health.mjs
import { execSync } from 'node:child_process';
const out = execSync('gh run list --branch main --limit 100 --json workflowName,conclusion,createdAt,startedAt,updatedAt', { encoding: 'utf8' });
const runs = JSON.parse(out).filter(r => r.conclusion === 'success' || r.conclusion === 'failure');
const by = {};
for (const r of runs) (by[r.workflowName] ||= []).push(r);
console.log('| workflow | runs | pass % | flips |\n|---|---|---|---|');
for (const [name, rs] of Object.entries(by)) {
  rs.sort((a, b) => a.createdAt < b.createdAt ? -1 : 1);
  const ok = rs.filter(r => r.conclusion === 'success').length;
  let flips = 0;
  for (let i = 1; i < rs.length; i++) if (rs[i].conclusion !== rs[i-1].conclusion) flips++;
  console.log('| ' + name + ' | ' + rs.length + ' | ' + (100 * ok / rs.length).toFixed(0) + ' | ' + flips + ' |');
}

Extend it with median and p90 from the earlier guide on run time.

Publish the report

If you want a shareable page, write the report as HTML or Markdown and publish it. Pages publishes a page or Markdown file to a free public link with npx -y @flisk-sh/pages publish report.md --wait. Remember the link is public, so do not publish data about private repos.

Or use a ready dashboard

For public repos you do not need to build anything. Cilytics is a public CI health dashboard, no account needed. It shows an org or one repo (?repo=owner/name) with a pass rate trend, red workflows, per-repo pass rate and median run time, flaky and slow workflows, an open-source hygiene score out of 100 and an AI-readiness view. Limits: default-branch runs only, last 100 runs, hourly snapshot, repos inactive for 90 days are left out. For private repos or per-test data, build your own.

Keep it small

Start with five numbers from the short list, per workflow, with the sample size. Add a number only when someone asks a question it answers. For many repositories at once, read org-wide CI visibility.

Test the script on a repo with a long history first, and compare its pass rate with what you see in the Actions tab for the same workflow. If they disagree, the usual cause is how cancelled and skipped runs are counted. Fix the definition once and note it at the top of the report.

Questions people ask

How often should the collector run?

Once a day is enough for trends. Run it more often only if you plan to alert on it.

Where do I store the history?

The step summary is easy but short-lived. For long history, commit a small JSON file or upload it as an artifact each run.

See the numbers

Look at the CI metrics of any public GitHub repo, no account needed.

Cilytics shows pass rate trend, red workflows, median and p90 run time, flaky and slow workflows for an org or a single public repo. It uses default-branch runs from the last 100 runs and an hourly snapshot.
