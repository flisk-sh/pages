Median vs p90 Run Time: Which CI Duration Number to Use

Why the average run time misleads, what median and p90 each show, and how to compute both from workflow run data in a few lines of code.

Use the median to describe a typical CI run and the p90 to describe a slow one. Avoid the average: a few very long runs pull it up, and a few cache hits pull it down, so it describes no run that actually happened.

What each number means

  • Median (p50): half of runs are faster, half slower. It is the normal experience.
  • p90: nine in ten runs are faster than this. It is what developers feel on a bad day.
  • Max: usually an outlier like a hung job. Ignore it for trends.

Example: median 8 minutes and p90 25 minutes means most pushes are fine but one in ten waits three times longer. That gap is the problem to chase.

Compute it

gh run list --workflow ci.yml --branch main --limit 100 \
  --json conclusion,startedAt,updatedAt > runs.json

node -e '
const r=require("./runs.json").filter(x=>x.conclusion==="success");
const m=r.map(x=>(new Date(x.updatedAt)-new Date(x.startedAt))/60000).sort((a,b)=>a-b);
const q=p=>m[Math.min(m.length-1,Math.floor(p*m.length))];
console.log("n="+m.length,"p50="+q(0.5).toFixed(1),"p90="+q(0.9).toFixed(1));
'

Use only successful runs for timing. Failed ones often stop early, which makes the numbers look better than they are.

What a big gap tells you

When p90 is much larger than the median, look for variance, not for a slow step. Common causes: cold versus warm cache, queue time when runners are busy, retried network steps, or a suite that sometimes runs extra tests. Compare the fastest and slowest run side by side in the Actions UI, step by step.

Report it per workflow

One median across all workflows hides the slow one. Keep one pair of numbers per workflow. Cilytics shows median and p90 per workflow and flags slow ones, for an org or a public repo, from default-branch runs in an hourly snapshot. It does not break runs into queue time and execution time, so use your own script if you need that split.

Choosing the percentile with few runs

With 100 runs, the p90 is the tenth slowest run. That is stable enough to watch. With 20 runs it is the second slowest and moves a lot, so combine a longer window or report the range. Always print the number of runs next to the percentile. If runs are rare, say fewer than one a day, use the median and the slowest run, and look at those runs individually in the Actions UI instead of leaning on a statistic.

Watch the trend, not the value

A median of 12 minutes is neither good nor bad by itself. A median that was 7 minutes last quarter is a signal. Plot weekly medians and look for steps up after specific merges. Then use the speed-up checklist to bring it down.

Questions people ask

Is p95 better than p90?

Either works. With only 100 runs, p95 depends on five runs and is noisy, so p90 is steadier for small samples.

Why not use the average?

Outliers skew it, so it can describe a run time nobody experiences. Median and p90 are closer to real waits.
