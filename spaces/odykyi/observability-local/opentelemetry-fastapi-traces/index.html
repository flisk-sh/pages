Logs, traces and metrics locally

OpenTelemetry traces for FastAPI with Jaeger

Automatic instrumentation covers requests and clients; a manual span covers your own code.

Install opentelemetry-distro and opentelemetry-exporter-otlp, run opentelemetry-bootstrap -a install to add instrumentation for the libraries you use, and start the app with opentelemetry-instrument uvicorn main:app. Set OTEL_SERVICE_NAME and an OTLP endpoint in the environment. No application code changes are needed for a first trace.

Install the packages

pip install opentelemetry-distro opentelemetry-exporter-otlp
opentelemetry-bootstrap -a install

The distro bundles the SDK and the opentelemetry-instrument launcher. The exporter package sends spans over OTLP. opentelemetry-bootstrap looks at what is installed in your environment (FastAPI, requests, httpx, SQLAlchemy, psycopg and so on) and installs the matching instrumentation packages. Run it again after adding a new library, and keep the result in your requirements file so everyone gets the same set.

Configure through the environment

Python's OTLP exporter uses gRPC by default. Port 4318 speaks HTTP, so say so explicitly, or you get connection errors that look like a network problem:

export OTEL_SERVICE_NAME=catalog
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_TRACES_EXPORTER=otlp
export OTEL_METRICS_EXPORTER=none
export OTEL_LOGS_EXPORTER=none

opentelemetry-instrument uvicorn main:app --port 4000

The last two exporter lines switch off metrics and log export while you only want traces. The metrics exporter defaults to OTLP, so without them the launcher also tries to send metrics to the same endpoint, and a backend that takes only traces can answer with errors that fill your terminal.

A minimal app to try it on:

# main.py
import httpx
from fastapi import FastAPI

app = FastAPI()

@app.get("/health")
def health():
    return {"status": "ok"}

@app.get("/items/{item_id}")
async def item(item_id: int):
    async with httpx.AsyncClient() as client:
        price = await client.get(f"http://localhost:4001/prices/{item_id}")
    return {"id": item_id, "price": price.json()}

A request to /items/7 produces a server span for the route and a client span for the httpx call. If the price service is also traced, its spans join the same trace through the traceparent header.

Add your own spans

Auto-instrumentation sees the edges of your service. For work inside it, such as a ranking function, add a manual span:

from opentelemetry import trace

tracer = trace.get_tracer(__name__)

def rank(items):
    with tracer.start_as_current_span("rank-items") as span:
        span.set_attribute("items.count", len(items))
        return sorted(items, key=lambda i: i["score"])

Attributes are the useful part: they let you search for slow traces by a value. Keep them small and avoid personal data.

Run it with Flisk

Flisk runs a Python service as a local process when its service.json has a command. Put the instrumented command and the environment there, and the process gets the same configuration on every machine:

{
  "schemaVersion": 1,
  "appName": "catalog",
  "appType": "backend",
  "command": "opentelemetry-instrument uvicorn main:app --port 4000",
  "port": 4000,
  "healthCheckPath": "/health",
  "toolchain": "python@3.12",
  "dependsOn": ["jaeger"],
  "env": {
    "OTEL_SERVICE_NAME": "catalog",
    "OTEL_EXPORTER_OTLP_ENDPOINT": "http://localhost:4318",
    "OTEL_EXPORTER_OTLP_PROTOCOL": "http/protobuf",
    "OTEL_METRICS_EXPORTER": "none",
    "OTEL_LOGS_EXPORTER": "none"
  }
}

The jaeger entry is a bring-your-own resource described in sending OpenTelemetry traces from Node.js to Jaeger: an image with the UI on 16686 and OTLP on 4317 and 4318 published to localhost. The same backend takes spans from Node and Python services at once, which is the point of OTLP. Flisk does not install the Python packages. Create the virtual environment yourself, and make sure the command finds opentelemetry-instrument on the PATH the process inherits. The setup for a FastAPI and React pair is in running FastAPI and React locally.

Pitfalls

  • Reload mode. uvicorn --reload starts the app in a child process, and instrumentation set up by the launcher may not reach it. If spans are missing, test without --reload first, then decide whether you need it.
  • Wrong protocol or port. gRPC is 4317, HTTP is 4318. A mismatch gives timeouts or "failed to export" lines in the service output.
  • Libraries installed after bootstrap. If a new database driver shows no spans, run opentelemetry-bootstrap -a install again.
  • Several workers. With --workers each process exports on its own. That works, but check that your backend shows one service, not several.
  • Do not trace everything in production by default. Sampling at 100 percent is fine for your laptop; set a sampler such as OTEL_TRACES_SAMPLER=parentbased_traceidratio with OTEL_TRACES_SAMPLER_ARG=0.1 when traffic grows.

If you want to look at, filter or duplicate the data before it reaches a backend, put a collector in the middle: run an OpenTelemetry Collector locally.

A last check before you move on: make one request, open Jaeger, and confirm that the service name matches OTEL_SERVICE_NAME and that the span tree has the shape you expect. If the root span is there but your manual span is not, the code path was not reached. If nothing is there at all, look at the exporter endpoint first, since a wrong host or port fails quietly. Keeping this short loop of request, look, adjust makes tracing a habit, instead of something you set up once and never open again.

Questions people ask

Do I need to change my FastAPI code?

Not for basic tracing. The opentelemetry-instrument wrapper patches FastAPI and common clients at startup. Add manual spans only for your own logic.

Why are traces missing with uvicorn --reload?

The reloader runs the app in a child process, which can bypass the instrumentation. Try running without --reload to confirm.

Which exporter protocol should I pick?

http/protobuf to port 4318 is the simplest choice for a local Jaeger.
