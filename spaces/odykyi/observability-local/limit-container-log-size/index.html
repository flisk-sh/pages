Limit Docker container log size with log rotation

Docker keeps every log line by default. Two options put a ceiling on it.

Docker's default json-file log driver keeps every line a container writes until the container is removed, with no size limit. Set max-size and max-file on the logging options, per container in Compose or for every container in daemon.json, and old lines rotate away. A service that logs in a tight loop can otherwise fill your disk in an afternoon.

Find out whether logs are the problem

Before changing anything, look at the size of the logs you have. For one container, ask Docker where its log file is and how big it is:

docker inspect --format '{{.LogPath}}' my-container
docker ps -q | xargs docker inspect --format '{{.Name}} {{.LogPath}}' | head

On Linux you can run ls -lh on those paths with sudo. On macOS and Windows the files live inside the Docker virtual machine, not on your normal file system, so you will not see them in Finder. What you will see is the virtual disk growing, and docker system df will not show it, because that report does not count container log files. The guide on Docker disk full covers cleanup in general.

The usual cause is one service in a retry loop printing an error many times a second. Fix that first. Rotation protects the disk, but a service that prints a million identical lines is still broken. See why a container keeps restarting for the related case.

Limit logs for one service in Compose

services:
  api:
    image: my-api
    logging:
      driver: json-file
      options:
        max-size: "5m"
        max-file: "3"

Docker writes up to 5 MB to the current file, then rotates it, and keeps three files, so the cap per container is about 15 MB. Quote the values to keep them strings. The container must be recreated for new options to apply, and restarting it is not enough.

Limit logs for every container

Put the same options in the Docker daemon's configuration so every new container gets them, including ones started by tools that never mention logging:

{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}

On Linux this is /etc/docker/daemon.json, followed by a daemon restart. In Docker Desktop it is Settings, then Docker Engine. In Colima, the docker section of colima.yaml holds the daemon configuration, and you edit it with colima start --edit. The new defaults apply to containers created afterwards, not to existing ones.

Where Flisk fits

For a bring-your-own resource, Flisk's service.json has a logging field that is written into the generated Compose file as the Compose logging key:

{
  "schemaVersion": 1,
  "appName": "legacy-api",
  "appType": "bring-your-own",
  "stack": "shop",
  "port": 4500,
  "image": "my-api",
  "logging": {
    "driver": "json-file",
    "options": { "max-size": "5m", "max-file": "3" }
  }
}

The option values are strings, as in Compose, and flisk config verify checks the shape. This field is documented for bring-your-own resources only. For services Flisk generates from a template, such as a backend, use the daemon setting above, which covers them without any per-service entry.

When a stack runs as local processes (a command in service.json), there is no Docker log file. Flisk's documentation says each line is written, with a timestamp, to .flisk/native/logs/<service>.log, which is what flisk logs reads. That folder is inside the project and the documentation does not describe rotation for it, so check its size now and then if a service is very noisy.

du -sh .flisk/native/logs/*

To read just the lines you need without scrolling, use flisk logs --service api --since 5m --tail 100. It prints a bounded snapshot, so it never dumps a huge file to your terminal.

Pitfalls

  • Rotation loses old lines. That is the point, but if you need history to debug an overnight problem, raise max-file or send logs elsewhere.
  • Quoting. In Flisk's service.json the option values must be strings, so write "3", not 3.
  • Other drivers. The local driver rotates by default and stores logs more compactly than json-file. The catch is that it uses its own file format, so tools that read the log file directly will not understand it.
  • Logs in the container. A service that writes its own log file inside the container grows the container layer instead, and none of this applies. Log to stdout.

Smaller logs help, but structure helps more once you read them. Structured JSON logs in Node.js shows how to make each line searchable.

Questions people ask

What is the default Docker log size limit?

With the json-file driver there is no limit unless you set max-size and max-file.

Do new log options apply to running containers?

No. The container must be recreated, and daemon.json defaults apply only to containers created afterwards.

Where do Flisk local process logs go?

Flisk writes them to .flisk/native/logs/<service>.log, and flisk logs reads them.
