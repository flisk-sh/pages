Agent frameworks on your laptop

How to use the Vercel AI SDK inside a Flisk agent's runTurn

The Vercel AI SDK is stateless. The Flisk agent resource already stores sessions. Put the SDK call in the one function that is left for you.

The Vercel AI SDK does not store conversations: each generateText call gets the messages you pass and returns text. A Flisk agent resource is the other half. It is an HTTP service that loads a session checkpoint, calls one function named runTurn, and saves the result. Fill runTurn with an AI SDK call and you have an agent with durable sessions in a few lines.

Who owns what

With the AI SDK you keep the message array yourself, in a database, a cookie or memory. In a chat route this is boilerplate you rewrite per project: load history, append the user message, call the model, append the reply, save. The Flisk agent scaffold does all of that around runTurn(checkpoint, input). Its source says the function should be replaced with "your model call and tools", and it already appended the new user message to checkpoint.messages before calling you.

The scaffold is TypeScript on Bun and runs in a container, so this path needs Docker and uses Flisk's gateway. If you want a plain local process instead, an AI SDK route in your own Node or Bun server is simpler; see running local services without Docker.

Create the agent

npm install -g @flisk-sh/flisk
flisk project --yes
flisk resource bot --type agent --stack shop --yes
cd services/shop/bot
bun add ai @ai-sdk/anthropic

The generated service.json declares "appType": "agent" with "agent": { "runtime": "custom", "durability": "files" }, and package.json starts with no runtime dependencies, which is why you add the SDK yourself. Use another provider package if you prefer; the shape of the call does not change.

Fill in runTurn

The checkpoint stores messages with the roles user and agent. The SDK wants user and assistant, so map them:

import { generateText, stepCountIs } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';

async function runTurn(checkpoint: Checkpoint, input: string): Promise<string> {
  const { text } = await generateText({
    model: anthropic('YOUR_MODEL_ID'),
    system: 'You are a concise assistant.',
    messages: checkpoint.messages.map((m) => ({
      role: m.role === 'agent' ? ('assistant' as const) : ('user' as const),
      content: m.content,
    })),
    stopWhen: stepCountIs(5),
  });
  return text;
}

Do not append input again: it is already the last item of checkpoint.messages. The stopWhen line caps how many tool steps one turn may take. Add your tools under tools and the cap keeps a confused model from looping; the same idea for other frameworks is in step limits across frameworks. Step-limit options differ between AI SDK major versions, so match the call to the version you installed.

The provider package reads its key from an environment variable of its own name (ANTHROPIC_API_KEY for this one). Declare it by name in service.json and keep the value in the git-ignored project .env:

"secrets": { "required": ["ANTHROPIC_API_KEY"] }

A required secret that is missing makes Docker Compose refuse to start the resource and name the missing variable. The full picture is in keeping LLM API keys out of git.

Start it and hold a conversation

flisk up shop
curl -X POST http://api.shop.localhost/api/bot/turn \
  -H 'x-session-id: demo' -H 'content-type: application/json' \
  -d '{"input":"My favourite colour is green."}'
curl -X POST http://api.shop.localhost/api/bot/turn \
  -H 'x-session-id: demo' -H 'content-type: application/json' \
  -d '{"input":"What is my favourite colour?"}'
flisk agent sessions bot

The URL shape is the one Flisk documents for agents (api.<stack>.localhost/api/<name>). The last command lists stored sessions; see inspecting agent sessions. Checkpoints live on a named Docker volume, so they survive flisk down.

Pitfalls

  • The drain window is short. On SIGTERM the generated service waits up to 10 seconds (DRAIN_TIMEOUT_MS) for turns in flight. A model call that runs longer is cut off when you restart, and the checkpoint for that turn is not written. Keep turns short or raise the constant in src/index.ts.
  • Whole history every turn. The mapping above sends every stored message each time. Trim or summarise old messages before conversations get long.
  • Streaming. The scaffold's turn endpoint returns one JSON reply, so streamText would need changes to the HTTP handler, not just runTurn.
  • Did the image get the new packages? Check flisk logs after the first start. A missing module error means the dependency did not reach the image.

For what the checkpoint format guarantees across restarts, read durable agent sessions and checkpoints.

Questions people ask

Why map the role agent to assistant?

The checkpoint written by the Flisk agent scaffold uses user and agent as roles, while the Vercel AI SDK message format uses user and assistant.

Can I run this without Docker?

The agent scaffold is a container resource. For a plain local process, write an AI SDK route in your own Node or Bun server and add a command to its service.json.

Does the AI SDK need a server framework?

No. generateText is a function call. It works inside runTurn, a Hono route, a Next.js route handler or a script.
