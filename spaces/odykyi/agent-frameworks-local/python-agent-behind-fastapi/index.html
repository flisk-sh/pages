Agent frameworks on your laptop

How to put a Python agent behind a FastAPI endpoint

Agent libraries are blocking Python functions. A web endpoint is not. The mismatch causes most of the first-day problems.

To serve a Python agent over HTTP with FastAPI, declare the handler as a plain def if the agent call is blocking, use an async def only when the framework gives you an awaitable, and stream tokens with StreamingResponse if the call takes more than a few seconds. Getting this wrong stalls the whole server: one slow request blocks every other.

The blocking trap

FastAPI runs async def handlers on the event loop. If one of them calls a blocking function, such as a framework's synchronous run that waits on a model for twenty seconds, the loop is frozen for that time. Health checks time out, and other requests wait. FastAPI runs a plain def handler in a thread pool instead, so a blocking call there only occupies one thread.

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class In(BaseModel):
    message: str


@app.post("/chat")
def chat(body: In) -> dict[str, str]:   # plain def: runs in a worker thread
    reply = my_agent.run_sync(body.message)  # a blocking framework call
    return {"reply": reply}

When the framework offers an async API (most do), use it with async def and await. Do not mix: calling asyncio.run inside a running handler fails, and wrapping every blocking call in a new thread by hand is rarely needed. If an async handler must call something blocking, use await asyncio.to_thread(fn, arg).

Stream the answer

For chat, users want text as it arrives. Server-sent events are the simplest way over plain HTTP. Return a generator wrapped in StreamingResponse with the text/event-stream type and one data: line per chunk:

import json
from fastapi.responses import StreamingResponse


@app.post("/chat/stream")
def chat_stream(body: In) -> StreamingResponse:
    def events():
        for chunk in my_agent.stream(body.message):  # your framework's stream
            yield f"data: {json.dumps({'text': chunk})}\n\n"
        yield "data: [DONE]\n\n"

    return StreamingResponse(events(), media_type="text/event-stream")

Test it with curl -N, which turns off curl's own buffering. If the text appears in one block at the end, something between you and the client is buffering, and a reverse proxy is the usual cause. Calling the service directly on its port first tells you whether the proxy is the problem.

Runs that take minutes

Streaming helps up to a point. Multi-agent crews and research jobs can run for minutes, and clients and proxies close idle connections. For those, start the job and return an id, then let the client poll. The CrewAI article shows a complete start-and-poll wrapper.

Run it with Flisk, no Docker

Flisk scaffolds this service for you. Install it (npm install -g @flisk-sh/flisk) and run:

flisk project --yes
flisk resource agent-api --type backend --language python --local --stack agents --yes

You get a FastAPI app with a /health route, CORS set for *.localhost origins so a frontend on its own local host name can call it, a pyproject.toml with pinned FastAPI and uvicorn versions, a pytest setup, and a service.json with a command. That command is a uvicorn line bound to localhost that reads PORT and runs with --reload. Add your agent library to pyproject.toml, install the dependencies into your environment, and run flisk up. Flisk starts the process, waits for /health, prefixes its logs with the service name and restarts it if it crashes.

Keep /health cheap. It should say the process is alive and not call the model. Why a readiness check is separate is explained in health versus readiness endpoints for an AI agent.

Pitfalls

  • Reload restarts the process. While --reload is on, saving a file in the watched folder kills runs in flight and any in-memory state.
  • One worker. uvicorn with --reload runs one process. State kept in a Python dict is not shared if you later run several workers, so keep sessions in a database or file.
  • Request size and time. Set a timeout on your model client. A hung model call otherwise holds a thread forever.
  • Bind address. The scaffold listens on localhost only, which is right for development. Do not bind 0.0.0.0 with a real key in the environment on a shared network.

To check the endpoint without a real model, use a scripted one, as in testing an agent without calling a model. For a larger Python and Node layout, see running Python and Node services in one repo.

Questions people ask

Should an agent endpoint be async def or def?

Use def when the agent call blocks, because FastAPI then runs it in a thread pool. Use async def only with awaitable calls, or you freeze the event loop.

Why does my streamed response arrive all at once?

Some layer is buffering it. Test the service directly with curl -N to rule out a proxy, and make sure the generator yields as chunks arrive.

Does Flisk work with frameworks other than FastAPI for Python?

The Python scaffold uses FastAPI. Any process you can start with a command works as a local Flisk service, so another server is fine if you write its command and health path.
