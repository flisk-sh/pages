How to stop an AI agent from looping forever: step limits

An agent that keeps calling tools never crashes, so no restart policy will save you. The cap has to be in the code, and you should set it yourself.

An agent loops when each model answer asks for another tool call and none of them ever produces a final reply. To stop it, set a step limit in the framework, a wall-clock timeout around the whole run, and a token or request budget. Every popular framework has the first one, with a different name and a different default, so set the value yourself instead of relying on it.

Why a loop is a cost problem, not a crash

A looping agent is healthy by every measure a process supervisor has. It answers its health check, uses little CPU, and makes a network request every few seconds. The only visible symptom is a growing bill and a request that never returns. So limits belong in the agent code, and monitoring should watch the number of model calls per run, not just uptime.

Common causes: a tool returns an error the model does not understand and it retries the same call, a tool returns an empty result and the model asks again, or two agents hand a task back and forth. A cap does not fix these, but it turns an unbounded run into a bounded one with a clear error you can log.

Where to set the limit

The names below are the documented options at the time of writing. Defaults vary by version, so read yours and write the number down in your code.

# LangGraph: raises GraphRecursionError when exceeded
graph.invoke(inputs, {"recursion_limit": 10})

# OpenAI Agents SDK: raises MaxTurnsExceeded
await Runner.run(agent, "task", max_turns=6)

# Pydantic AI: raises UsageLimitExceeded
from pydantic_ai import UsageLimits
agent.run_sync("task", usage_limits=UsageLimits(request_limit=6))

# CrewAI: per-agent limits on an Agent
Agent(role="...", goal="...", backstory="...", max_iter=8, max_execution_time=120)

// Vercel AI SDK: stop after a number of steps
generateText({ model, tools, prompt, stopWhen: stepCountIs(6) })

Each of these counts a different thing. LangGraph counts graph steps, which can be several per model call. The Agents SDK counts turns of the agent loop. Pydantic AI can count requests to the model (and, in recent releases, tokens). CrewAI counts iterations of one agent on one task. The AI SDK counts model steps. A limit of six means very different amounts of work, so test the number against a task that really needs tools.

What to do when the limit fires

The framework raises an exception or returns a partial result. Decide what the caller should see:

  • Log the run input, the number of steps and the last tool call. The last call usually shows the loop.
  • Return an explicit failure to the caller, such as status: "failed" with a short reason, not an empty answer that looks like a success.
  • Do not retry automatically with the same input. The same input loops the same way. Retry only when the failure was a network error.

Also put an outer timeout on the whole run, for example with asyncio.wait_for in Python or an AbortSignal in JavaScript. A step limit does not help when one model call hangs. And make tools with side effects idempotent, so a run cut off by a limit that is then repeated does not send two emails.

Finding a loop in a local stack

With Flisk the loop shows up in the logs, not in flisk status, because the service stays healthy. Read recent output, merged across services:

flisk logs --service agent --tail 50
flisk logs --service agent --since 5m

If one tool name repeats down the list, you have found it. To end a run that is stuck right now, restart that resource (flisk restart agent). Flisk's local-process runner also restarts a crashed process after 1, 2, 4 and 8 seconds and stops after five quick exits, but that only applies to crashes, not to loops. For reading logs from several services, see how to read logs from every service in a local stack.

Pitfalls

  • A limit that is too low breaks legitimate work. Measure a normal run first, then set the limit to about double.
  • Counting the wrong thing. A step limit does not bound tokens. A single step with a huge prompt can still be expensive, so add a token budget where the framework supports it.
  • Local models loop more. Small models often fail to produce the tool call format and retry. See running agent frameworks against a local model before you tune limits upward.

If a run does hit the limit, the next question is what state it left behind. That is what where agent frameworks keep state compares.

Questions people ask

What is a safe default step limit?

There is no universal number. Run your real task once, note how many steps it needs, and set the limit to roughly twice that. Write the value in code so a framework upgrade cannot change it silently.

Does a restart policy stop a looping agent?

No. A loop is not a crash, so the process stays up and healthy. Only limits in the code, a timeout, or a manual restart end it.

Should I retry a run that hit the limit?

Not with the same input, because it will loop again. Change the prompt or the tools, or return a failure to the caller.
