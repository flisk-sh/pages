Local LLMs for development

How to switch between a local LLM and a hosted API

Calling a hosted model on every dev change is slow and costs money. Calling only a local one hides production differences. Make the choice a setting.

Put three values in configuration: the base URL, the API key and the model name. In development they point at a local server such as Ollama. In production they point at the hosted API. Application code reads them from the environment and never mentions a provider.

What goes in configuration

LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=llama3.2

Production uses the provider's URL, a real key and a hosted model name. Nothing else differs, as long as your provider offers an OpenAI-compatible route. If it does not, put a thin adapter in your code behind one interface, so the rest of the app calls complete(messages) and does not know which SDK sits under it. Use the name LLM_* or your own prefix rather than OPENAI_* when the provider is not OpenAI, so nobody is confused later.

Two rules keep this honest:

  • Defaults point at local. A fresh clone runs with no key and no cost. Production sets the variables explicitly.
  • Keys never get a default. The local dummy is fine to commit. A real key lives in a git-ignored .env or your secrets manager.

The Flisk way

In service.json, the env block accepts ${VAR} and ${VAR:-default}. For a container service, Compose resolves them from your shell and the project .env. For a local process, Flisk resolves them in this order: your shell, the project .env, the service's own .env, then the default. A first match wins.

"env": {
  "LLM_BASE_URL": "${LLM_BASE_URL:-http://brain:11434/v1}",
  "LLM_API_KEY": "${LLM_API_KEY:-ollama}",
  "LLM_MODEL": "${LLM_MODEL:-llama3.2}"
}

With no .env entries, the service calls the brain resource in the same stack, which you created with flisk resource brain --type inference --stack llm. To use a hosted model for one session, put the three variables in the project .env, restart the service with flisk restart chat-api, and delete them when done. No code change, and no edit to service.json. The .env file stays out of git, as Flisk's guidance requires, so your key is not committed.

Put the real key in .env only. Flisk's doctor warns about env values that point outside the local stack, such as a URL whose host is not local. It prints the service, variable, host and file, but never the value. If a remote host is intended, add it to allowedHosts in .flisk/project.json to silence the warning. Read the full behavior in the Flisk docs before you rely on it, since flisk doctor --strict makes the warning fail the check.

If the variable does not seem to arrive, flisk run chat-api -- printenv LLM_BASE_URL shows what the service actually sees. For the debugging steps see environment variable not loaded in a local service.

Keep the dev and production gap visible

  • Quality. A small local model is not the production model. Run your prompt tests against the real one before you ship, on a schedule rather than on every save.
  • Features. Tool calling, JSON mode, vision and long context differ. Write down which features your app needs, and check them against both.
  • Rate limits and errors. A local server never returns 429. Test your retry logic with a fake, as in mocking an LLM API in tests.
  • Cost. A loop that calls the model on every keystroke is free locally and expensive hosted. Add a per-request budget log early.
  • Data. Local is the right place for prompts that contain customer data you should not send out. Decide that on purpose.

When not to do this

If you only ever use one provider and its SDK-specific features, such as a provider's own tools or caching, a compatibility layer hides what you rely on. Use the provider's SDK in production code, and use a mock server for local runs instead. The abstraction should serve a real need, not exist for its own sake.

A minimal wrapper

If you want one place to log, time and budget calls, wrap the client in a single function and keep the configuration reading inside it. Return the text and the usage counts, and throw a typed error for rate limits so callers can retry. The wrapper is also where you add a fake in tests. It stays small: reading three variables and forwarding a request. Resist adding provider branches to it. If you find yourself writing if provider == ... in many places, you have outgrown the compatibility route and should model the providers explicitly.

To set up the local half, see pointing the OpenAI SDK at Ollama.

Questions people ask

How do I use Ollama in development and OpenAI in production?

Read the base URL, API key and model name from environment variables. Default them to Ollama locally and set the hosted values in production.

Where should the API key for the hosted model live?

In a git-ignored .env file locally and in your secrets manager in production. Only the local dummy value may have a committed default.

Why does flisk doctor warn about my LLM URL?

It warns about env values whose host is not local. If the remote host is intended, add it to allowedHosts in .flisk/project.json.
