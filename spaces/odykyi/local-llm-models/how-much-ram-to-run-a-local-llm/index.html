Local LLMs for development

How much RAM do you need to run a local LLM?

A model that does not fit in memory swaps or fails to load. You can estimate the fit with arithmetic before you download anything.

A model needs about its parameter count times the bytes per weight, plus room for the context cache and some overhead. A 7 billion parameter model at 4-bit quantization takes roughly 4 to 5 GB. The same model in 16-bit takes about 14 GB. If the total is more than your free memory or VRAM, pick a smaller model or a stronger quantization.

The arithmetic

Weights dominate. Bytes per weight depend on the format:

PrecisionBytes per weight7B model (weights only)
16-bit (fp16 or bf16)2about 14 GB
8-bit (Q8)about 1about 7 GB
4-bit (Q4 variants)about 0.5, a little more in practiceabout 4 to 5 GB

Then add the context cache. It grows with the number of tokens in the conversation, so a long prompt costs more than a short one. Allow one to a few extra gigabytes for typical contexts, more for very long ones. Add overhead for the runtime itself. A safe rule is to leave 20 to 30 percent headroom above the weights.

These are estimates, not guarantees. Quantization schemes differ, and model families differ in how big their caches are. The model page in your runtime's library lists the real download size, which is the best number for the weights.

Where the memory has to be

  • Apple silicon. CPU and GPU share unified memory, so the limit is your total RAM minus what the system and your other apps use. A 16 GB machine is comfortable with a 3B to 8B model at 4-bit and not with much more while an IDE, a browser and a database also run.
  • NVIDIA GPU. The model runs fastest when it fits in VRAM. If it does not, the runtime places some layers in system RAM, and speed falls sharply.
  • CPU only. It works, with the model in system RAM, and generation is slow. Fine for wiring and tests.

Check what you really have free. On macOS use Activity Monitor, on Linux free -h, and on NVIDIA nvidia-smi. Then check what the model uses while loaded with ollama ps.

Containers and limits

Docker on a Mac runs inside a VM with a fixed memory size. If it is smaller than the model, the container is killed or the load fails, no matter how much RAM the Mac has. Raise the VM memory in Docker Desktop's settings, or in Colima with colima start --memory. The Colima setup is in Docker on a Mac with Colima.

In Flisk, a bring-your-own container such as the --type inference model server has no CPU or memory limit unless you set container.memory or container.cpus in its service.json. A container that Flisk builds from its own Dockerfile gets 0.5 CPU and 512M by default, so a model server is wrongly sized if you ever put it in that kind of service. Set a limit when you want a runaway model to be killed before it takes the whole laptop:

"container": { "memory": "12g" }

Other services need memory too. Running a database, a queue and several apps next to a model is the usual cause of trouble. See many services on one laptop.

Choosing a size for development

  1. For wiring, tests and demos, use the smallest model that follows your prompt format. 1B to 3B models are enough.
  2. For checking prompt quality, use the model class you will ship, on a machine that fits it, and do this less often.
  3. Keep one model loaded. Switching models forces a reload each time.

Pitfalls

  • Believing "it loaded" means "it fits". A model can load and then be unusable because it swaps. Watch tokens per second, not only whether it starts.
  • Forgetting context size. Raising the context window increases memory use. Do it only when you need it.
  • Too many loaded models. Runtimes can keep several in memory. Unload what you do not use.

Write the model name and your measured memory use in the README next to the setup steps. A teammate with a smaller machine then knows in advance which model to substitute, and you stop answering the same "why is it so slow" question every time someone joins.

If your machine is too small, a hosted API for the heavy checks and a tiny local model for everything else is a workable split. See how to switch between them.

Questions people ask

How much RAM does a 7B model need?

Roughly 4 to 5 GB at 4-bit quantization, about 7 GB at 8-bit and about 14 GB at 16-bit, plus context cache and overhead.

Is VRAM or system RAM more important?

If the model fits in VRAM it runs fastest. Layers that spill into system RAM slow generation a lot. On Apple silicon, memory is unified.

Why is my model killed inside Docker?

The Docker VM or a container memory limit is smaller than the model. Raise the VM memory or the limit.
