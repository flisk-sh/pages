How to use a GPU with Ollama in Docker (NVIDIA, Mac, WSL2)

Where the GPU is available to a container depends on your operating system. Check this before you spend an hour on flags.

Ollama in Docker uses an NVIDIA GPU when the host has the NVIDIA Container Toolkit and the container is started with GPU access, for example docker run --gpus=all. Docker on macOS cannot reach the Apple GPU, so on a Mac the container runs on the CPU. There, run Ollama natively and let your other services call it.

What works where

HostOllama in a containerWhat to do
Linux with an NVIDIA GPUGPU works with the container toolkitInstall the driver and toolkit, start with GPU access
Windows with WSL2 and an NVIDIA GPUGPU works through Docker Desktop's WSL2 backend or Docker inside WSL2Keep the Windows driver current, test with a one-line check
macOS, Apple siliconCPU onlyRun the native Ollama app for Metal

Check the host first

Do this before touching Compose or Flisk. If the host cannot pass a GPU into a plain container, no configuration will fix it:

nvidia-smi
docker run --rm --gpus all ubuntu nvidia-smi

If the second command prints the same table as the first, the toolkit works. If Docker says it could not select a device driver, the NVIDIA Container Toolkit is missing or Docker was not restarted after you installed it.

Plain Docker and Compose

docker run -d --gpus=all \
  -v ollama-models:/root/.ollama \
  -p 11434:11434 ollama/ollama

In Compose, the GPU is a device reservation:

services:
  ollama:
    image: ollama/ollama
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]

The Flisk way

A bring-your-own container, which is what flisk resource brain --type inference creates, has no CPU or memory limit unless you set one. GPU access goes in the container block of service.json:

"container": {
  "gpus": "all",
  "cpus": 8,
  "memory": "32g",
  "shmSize": "16g"
}

Flisk turns gpus into an NVIDIA device reservation (deploy.resources.reservations.devices with driver: nvidia and capabilities: [gpu]). gpus takes "all" or a count. cpus and memory set limits, and ipc accepts host, private, shareable or none. Ollama itself does not need shmSize or ipc. Servers such as vLLM do, because PyTorch uses shared memory. Leave those out for Ollama and add them only when an engine asks for them.

The host needs an NVIDIA GPU and the NVIDIA Container Toolkit. Without them, Docker refuses to start the container. That is the correct failure: it tells you the host is wrong, rather than silently running on the CPU. Flisk's own tests check that the generated Compose file passes docker compose config, but the live GPU check runs only on a host with the NVIDIA runtime, so verify with flisk run brain -- nvidia-smi on your machine after flisk up llm.

You can also confirm Ollama is using the GPU: run flisk run brain -- ollama ps while a model is loaded. The processor column shows whether it sits on the GPU or the CPU.

On a Mac

Do not try to force it. Docker Desktop, Colima and Podman all run containers in a Linux VM with no Metal access. The practical setup is the native Ollama app on the host and your services calling it. Flisk's documentation suggests the same: for Metal speed, run the model server on the host, either by hand or as a service with a top-level command. The container side of that is covered in calling a host Ollama from a container. For the VM choice itself, see Docker Desktop vs Colima vs Podman.

Pitfalls

  • Model larger than VRAM. Ollama splits the model between GPU and CPU, and speed falls toward CPU speed. Pick a model that fits, using the memory rule of thumb.
  • AMD and Intel GPUs. They need other images and device settings. Follow the Ollama documentation for your card. Flisk's container.gpus writes an NVIDIA reservation only, so for other vendors you would run the model server on the host instead.
  • CI. Hosted CI runners usually have no GPU. Use a tiny model or a mock there.

Sizing the container

A model server in a container with no limits can take most of the machine's memory while a model loads. If other services share the laptop, set cpus and memory next to gpus so that a large model fails inside its own limit and not by slowing everything down. Choose a limit above the model's size from the memory estimate, with headroom for the context cache.

If a GPU is not an option, a smaller quantized model on the CPU is still fine for wiring work. Save the big model for the manual checks.

Questions people ask

Can Ollama use my Mac GPU in Docker?

No. Containers on macOS run in a Linux VM with no access to Metal. Run the native Ollama app on the host for GPU speed.

What do I need for an NVIDIA GPU in Docker?

The NVIDIA driver and the NVIDIA Container Toolkit on the host, then start the container with GPU access, such as --gpus all.

How do I give a Flisk resource a GPU?

Set container.gpus to all or a count in its service.json. The host still needs an NVIDIA GPU and the container toolkit.
