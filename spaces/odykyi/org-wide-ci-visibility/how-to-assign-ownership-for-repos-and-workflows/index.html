How to Assign Owners to Repos and Workflows

A red workflow nobody owns stays red. Use CODEOWNERS, repository topics and a small registry file so every failure has a team name next to it.

Give every repository one owning team in a single place and look it up when you report a failure. Visibility without ownership produces dashboards everyone reads and nobody acts on.

Owners are teams, not people

People leave and change teams. Name a team with a group mailbox or channel instead. If a repository has no owner, that is itself a finding worth listing, and an honest one to show in your weekly review.

Three places to record it

  • CODEOWNERS: the catch-all line * @your-org/team-name names a default owning team for the whole repository and routes reviews.
  • Repository topics: a topic such as team-payments is searchable from the org page and the API.
  • A registry file: one YAML file in a central repo mapping repository to team, plus a channel for alerts.

Pick one as the source of truth and generate the others if you need them.

A minimal registry

# owners.yaml
repos:
  payments-api:
    team: payments
    channel: '#payments-ci'
  web-app:
    team: frontend
    channel: '#frontend-ci'

The report script reads this file and appends the team to each red or flaky workflow. Unlisted repos are printed under an "unowned" heading.

Read topics from the CLI

gh repo list your-org --limit 300 --json name,repositoryTopics \
  --jq '.[] | "\(.name)\t\([.repositoryTopics[]?.name] | join(","))"'

Combine this with the red list from listing red workflows so each line carries its owner.

Decide what happens to orphans

Set a rule: a repository with no owner and no activity for a period is archived; one with activity gets an owner assigned in the weekly review. See running a weekly CI review for the meeting that enforces it.

Keeping ownership current

Ownership data rots when teams reorganise. Add a check that fails when a repository is missing from the registry, or lists a team that no longer exists. Run it weekly and post the output to the same channel as the CI report, so stale owners are visible without anyone having to look.

Make the registry cheap to update. A pull request that changes one line should be enough, and the team that takes a repository over should be the one to change it. Do not centralise approval; the point is to keep the file true, not to control it.

When a team is renamed or dissolved, search CODEOWNERS files across the org for the old name. gh search code can find them, though search results can be incomplete on large orgs, so confirm with a local clone for important repos. Treat a failing CI report for an unowned repository as the signal to fix the registry, not the build. Ownership first, then repair.

Questions people ask

Is CODEOWNERS enough?

It works for review routing, but its syntax is awkward to query across repos. A central registry or topics are easier to report on.

Who owns shared workflows?

The team that maintains the reusable workflow repository. Callers still own their own failing runs.
