Docker Desktop vs Colima vs Podman for local development

The runtime you pick decides your disk, ports and licence terms. This is a plain comparison, with the Flisk-specific notes you need.

Pick Docker Desktop if you want the easiest install and a GUI, and your company's licence terms allow it. Pick Colima on a Mac or Linux machine if you want a free, command-line Docker engine in a lightweight VM. Pick Podman if you need rootless, daemonless containers. Flisk's documentation names Docker Desktop, OrbStack and Colima. Whether a whole Flisk stack runs on Podman has not been checked, so this article does not claim it.

What each one is

Docker Desktop is Docker's application for macOS, Windows and Linux. It bundles the engine, the docker CLI and Compose, and it manages a VM for you. It has a graphical dashboard. Docker's subscription terms require a paid plan for larger companies, so read the current terms before you roll it out to a team.

Colima is an open-source tool for macOS and Linux that runs a small Linux VM through Lima and exposes a Docker socket. You install the docker and docker-compose CLIs yourself. It is started from the terminal with colima start, and you can set CPU, memory and disk size when you create the VM.

OrbStack is a macOS app that runs Docker containers and is an alternative to Docker Desktop. Flisk's messages and docs list it next to the other two.

Podman is a container engine without a central daemon that can run rootless. On macOS and Windows it runs through a VM managed by podman machine. It can emulate the Docker API through a socket, and has podman compose, but compatibility with Compose files and tools that assume the Docker socket varies.

How to choose

You wantLikely choice
Fewest steps, a GUI, works on WindowsDocker Desktop
Free and scriptable on a Mac or Linux laptopColima
An alternative Mac app to Docker DesktopOrbStack
Rootless containers, no daemonPodman

Do not choose by benchmark posts. Memory and file-sharing behaviour depend on your project, your Mac and your versions. Try the candidate on your real project for a day.

What Flisk expects

The container path needs a running Docker-compatible engine (Engine 25 or newer, Compose 2.20.2 or newer, per the README) plus Tilt, Node 22.12 or newer and Bun 1.2 or newer. If Docker is not reachable, flisk doctor tells you: its fix text says to start Docker Desktop, OrbStack or Colima. If Docker is down and Podman answers, the check prints "Podman is running", which shows Flisk sees it. That does not mean everything in a stack works on it.

flisk doctor
flisk doctor --json

The JSON output reports the host kind (local, wsl2, devcontainer, codespaces, webcontainer or native-windows) and whether the container runtime is reachable.

If you want no engine at all, run services without Docker. Native Windows uses that mode, while the Docker path on Windows needs WSL2 with the project inside the Ubuntu home directory, not under /mnt/c.

Colima notes

  • Bind mounts. Colima shares your home directory with the VM by default, so a project under $HOME works. A project under /private/tmp cannot be mounted, which trips up scratch-folder tests.
  • Disk. flisk doctor has a Colima Disk check. flisk down --prune-cache trims the VM and reports how much space went back to the Mac.
  • Stalled port forwarding. If URLs stop answering, colima restart is the usual fix. A stopped VM shows up as a clear message from flisk doctor with colima start as the fix.
  • Free space. Under 5 GiB free, flisk up stops. Under 15 GiB it warns. A full disk can damage the image store and the repair deletes volumes.

The longer walkthrough is in Mac local dev with Colima, and the disk cases are in Docker disk full.

Pitfalls

  • Switching engines changes where images and volumes live. Your old volumes do not move. Export data you need first.
  • Only one engine should own the docker context at a time. Check with docker context ls.
  • Resource limits on the VM are real. A stack that works on Docker Desktop with 8 GB may fail on a Colima VM created with less.
  • Do not assume tools that mount /var/run/docker.sock work the same under Podman.

Whichever you choose, run flisk doctor before the first flisk up. For the cases where the choice causes a port error, see fixing "port already in use".

Questions people ask

Does Flisk work with Podman?

Flisk's doctor recognises a running Podman, but whether a whole Flisk stack runs on it has not been checked. Its docs name Docker Desktop, OrbStack and Colima.

What does Flisk require from the container engine?

Docker Engine 25 or newer and Compose 2.20.2 or newer, plus Tilt, Node 22.12 or newer and Bun 1.2 or newer for the container path.

Do I need Docker at all with Flisk?

No. Services with a command in service.json run as local processes with no Docker. A project cannot mix those with Dockerfile builds.
