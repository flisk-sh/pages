Docker on Mac: speed and resources

Colima settings for speed: vz, VirtioFS and Rosetta

The defaults work, but three start flags change how fast Colima feels on an M-series Mac. They are fixed when the VM is created.

For a faster Colima on Apple Silicon, create the VM with --vm-type vz (Apple's Virtualization framework), --mount-type virtiofs for shared folders and, if you need amd64 images, --vz-rosetta. These settings are chosen when the VM is created, so an existing VM must be deleted and recreated to use them.

The command

colima start --vm-type vz --mount-type virtiofs --vz-rosetta \
  --cpu 4 --memory 8 --disk 60

What each flag does:

FlagEffect
--vm-type vzUses Apple's Virtualization framework instead of QEMU. It needs a recent macOS and is usually quicker for CPU and disk.
--mount-type virtiofsShares your Mac folders with the VM through VirtioFS, which is faster than the alternatives for many small files. It requires vz.
--vz-rosettaLets the VM run amd64 containers through Rosetta, which is generally faster than QEMU emulation. It requires vz on Apple Silicon.
--cpu, --memory, --diskCPUs, memory in GiB and disk in GiB of the VM. The disk can be grown later but not shrunk.

Run colima start --help to see the flags your installed version supports, since options change between releases.

Change an existing VM

CPU and memory can be changed by stopping and starting with new flags. The VM type and mount type cannot. To move an existing QEMU VM to vz:

  1. Dump anything you need from volumes, for example with pg_dump from your databases.
  2. Stop and remove the instance: colima stop then colima delete. This deletes the VM's images, containers and volumes.
  3. Start again with the new flags.
  4. Check with colima status and docker info --format '{{.OperatingSystem}} {{.Architecture}}'.

To keep the choice in a file instead of remembering flags, run colima template. It opens the default configuration in your editor, and Colima uses it for new VMs.

Check that file sharing works

A fast mount that does not reach your project is useless. Test with a bind mount:

docker run --rm -v "$PWD":/work -w /work alpine ls

If it lists nothing, the folder is not shared with the VM. Colima shares your home directory by default, so a project in a temporary folder or on an external disk is the usual cause. Move the project under your home folder, or share the extra folder by starting Colima with --mount for that path. Flisk has a check for exactly this: flisk doctor runs a Docker File Sharing check that tries a bind mount of the project folder and, on failure, suggests colima start --mount <folder>. Flisk also detects a Colima VM that is stopped and tells you to run colima start.

Wrong Lima on Apple Silicon

If Homebrew runs under Rosetta, you can end up with an Intel build of Lima, and the VM will not start or cannot be seen. Flisk's Colima check detects a Rosetta limactl and suggests brew reinstall lima, or putting a native limactl first on your PATH. Confirm with file $(which limactl), which should say arm64. The longer setup walk through is in Docker on a Mac with Colima.

Sizing the VM

Do not copy a number. Start with 4 CPUs and 8 GiB, run your real services, and check docker stats. How much memory and CPU to give Docker shows how to choose from measurements. Remember that a Colima VM keeps its memory reserved from the host while it runs, so stop it when you finish for the day with colima stop.

Pitfalls

  • Old macOS. vz, VirtioFS and Rosetta need a macOS version that supports them. If the VM refuses to start, remove one flag at a time to find which one.
  • Two runtimes. Docker Desktop and Colima can both define a docker context. Check docker context ls and use docker context use colima if the wrong one is active.
  • Disk file that never shrinks. Pruning inside the VM does not give space back to macOS until the VM trims. Run colima ssh -- sudo fstrim -av after a large cleanup.
  • Rosetta is not magic. A native arm64 image is still faster. See why amd64 images are slow on Apple Silicon.

After the VM is set up, measure again rather than assume. Time the slow command from the bind mount article before and after, and keep the setting that actually helps your project.

Questions people ask

Can I change Colima's vm-type without losing data?

No. The VM type and mount type are fixed when the VM is created. Dump your data, delete the instance and start a new one with the flags you want.

How do I make Colima use more memory?

Run colima stop, then colima start with a larger --memory value, such as --memory 8. CPU and memory can be changed this way without deleting the VM.

What does --vz-rosetta do?

It lets a vz virtual machine on Apple Silicon run amd64 containers through Rosetta, which is generally faster than QEMU emulation.
