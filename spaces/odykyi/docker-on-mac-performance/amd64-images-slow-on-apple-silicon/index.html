Docker on Mac: speed and resources

Why amd64 Docker images are slow on Apple Silicon, and what to do

Emulation works, but every instruction is translated. Know when you are paying for it and how to reduce it.

An amd64 image on an Apple Silicon Mac runs through CPU emulation, which is slower than native and sometimes less stable. The best fix is a native arm64 image. When you cannot get one, turn on Rosetta for amd64 emulation in Docker Desktop or Colima, because it is generally faster than the default QEMU emulation.

How to tell that you are emulating

Ask Docker which platform an image has, and what a running container reports about itself:

docker image inspect --format '{{.Os}}/{{.Architecture}}' postgres:17
docker exec <container> uname -m

uname -m prints x86_64 when the process is amd64 and aarch64 when it is native (the container needs a shell with uname). Other signs are a warning at pull time about a platform mismatch, and high CPU use for work that should be cheap. If nothing runs at all and you only see exec format error, start with fix exec format error on Apple Silicon.

Step 1: prefer a native image

Most popular images publish arm64 variants: Postgres, Redis, Node, Python, nginx and many more. Check with docker buildx imagetools inspect <image>. If an arm64 entry exists and you still get amd64, you have a stale pin: a platform: linux/amd64 line in a Compose file, a FROM --platform in a Dockerfile, or DOCKER_DEFAULT_PLATFORM in your shell. Remove it, then pull again, because the old amd64 copy stays cached under the same tag.

For your own images, build for the native platform during development and for amd64 in CI, where the server architecture matters. A multi platform build can produce both: docker buildx build --platform linux/amd64,linux/arm64 --push.

Step 2: turn on Rosetta when you must keep amd64

Some images are amd64 only, often older vendor images. Apple's Rosetta translation is generally faster than QEMU for these, and it works when the VM uses Apple's Virtualization framework.

  • Docker Desktop: in Settings, General, enable the option to use Rosetta for x86_64/amd64 emulation on Apple Silicon. It needs a recent macOS and Docker Desktop, and the wording can differ between releases.
  • Colima: create the VM with the Virtualization framework and Rosetta: colima start --vm-type vz --vz-rosetta. The Colima settings article has the full command and explains why an older VM must be deleted first.

With Rosetta enabled, docker run --platform linux/amd64 ... uses it. Without it, Docker falls back to QEMU user mode emulation.

Step 3: limit what you emulate

Emulation costs most for CPU heavy work and for programs with a JIT (a just in time compiler), because the generated machine code has to be translated too. A database doing heavy queries, or a Java or Node program under load, suffers more than a static web server. Keep the emulated part small:

  • Run only the amd64 service in an emulated container, and the rest natively or as arm64 images.
  • Give the emulated container an explicit memory limit, because emulation can use more memory.
  • Run its tests and heavy builds in CI on real amd64 hardware, not on your laptop.

Do not trust a speed multiplier from a blog post. Time your own job with and without the platform pin, on your Mac, with the same data.

In a multi service project

Compose projects often contain one legacy image that is amd64 only. In a Flisk project that container is a bring-your-own resource with an image, and the rest of the stack can stay native. Docker still decides the platform, so after the first run check what it pulled with docker image inspect, and set the platform where Docker reads it, such as DOCKER_DEFAULT_PLATFORM in the shell that starts the stack.

Pitfalls

  • Rosetta and some software. A few programs that use unusual CPU instructions fail under Rosetta. Turn Rosetta off for that case and fall back to QEMU.
  • Memory. Re-check with docker stats as described in how much memory and CPU to give Docker.
  • Timeouts. A healthcheck tuned on a fast machine may fail while an emulated service boots. Raise its start period before you blame the service.

Emulation is a cost you can often remove by finding or building an arm64 image. If a service cannot be moved, ask whether it needs a container at all, which the native or Docker decision article covers.

Questions people ask

Is Rosetta faster than QEMU for Docker on a Mac?

It is generally faster for amd64 containers, and it needs a VM that uses the Apple Virtualization framework. Time your own workload, because results vary by program.

How do I run an amd64 container on an M1 Mac?

Use docker run --platform linux/amd64 <image>. Docker emulates the CPU, with Rosetta if you enabled it and with QEMU otherwise.

Why does my database feel slow in Docker on an M-series Mac?

Check whether it is running as amd64. If the image has an arm64 variant, remove any platform pin and pull again so it runs natively.
