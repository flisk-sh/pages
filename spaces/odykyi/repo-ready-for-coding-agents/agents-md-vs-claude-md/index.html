AGENTS.md vs CLAUDE.md: Which One Should You Keep?

Different coding agents read different instruction files. Here is how to keep one source of truth and avoid two files that drift apart.

Keep one real instruction file and make the others point to it. AGENTS.md is a tool-neutral convention that several agents read, while CLAUDE.md is the file Claude Code looks for, so the simplest setup is AGENTS.md as the source and a one-line CLAUDE.md that imports it.

Why there are several files

Each agent tool picked its own file name before a common one existed. AGENTS.md is an open, tool-neutral name that a growing number of agents read. Claude Code reads CLAUDE.md. Other editors have their own rule folders. If your team mixes tools, you can end up with three files saying slightly different things.

The one-source setup

Write the real content in AGENTS.md. Then make CLAUDE.md a thin file that pulls it in. Claude Code supports importing another file with an @ path inside CLAUDE.md.

@AGENTS.md

## Claude Code only
- Prefer the plan step for changes touching more than three files.

Anything that applies to every agent lives in AGENTS.md. Anything specific to one tool goes in that tool's file. If your tool does not support imports, a symbolic link from CLAUDE.md to AGENTS.md also works on macOS and Linux, though it behaves badly on some Windows setups.

What belongs in the tool-specific file

Very little. Good candidates are permission settings, hook configuration and notes about a tool's own features. Project facts such as commands, layout and rules do not belong there, because then they diverge.

ContentWhere
Build and test commandsAGENTS.md
Repo map and rulesAGENTS.md
Tool permissions and hooksTool settings files
Personal preferencesUser-level file, not the repo

Catch drift in CI

Two files will drift unless something checks them. A tiny CI step can fail when CLAUDE.md contains more than an import and a few lines, or when a command named in AGENTS.md no longer exists in package.json.

test "$(wc -l < CLAUDE.md)" -le 20 || { echo 'CLAUDE.md is too long, move content to AGENTS.md'; exit 1; }

It is crude, but it keeps the single-source rule honest. For what to put in the main file, read how to write an AGENTS.md.

Migrating from several files

If you already have CLAUDE.md, Cursor rules and a copilot instruction file, do the merge in one pull request. Read all of them side by side, keep the lines that are true, and delete duplicates and contradictions. Contradictions are common: one file says to use pnpm and another says npm, because the project switched and only one file was updated. Run each remaining command once to confirm it works.

Then move the shared content into AGENTS.md and shrink each tool file to the import or pointer plus its tool-specific lines. Mention the new layout in the contributing guide so people edit the right file. After a month, check the tool files again; if someone has pasted shared rules back into them, move the rules and explain why in the review. Treat the shared file as the only place a project fact may live, and the tool files as thin adapters.

Questions people ask

Do I need both files?

Only if you use tools that read different names. If your whole team uses one agent, one file is enough.

Can the files live in subfolders?

Many agents read a nested file when working in that folder, which is useful in monorepos. Check your tool's documentation for the exact lookup rules.

Give your agent a repo it can run on the first try.
