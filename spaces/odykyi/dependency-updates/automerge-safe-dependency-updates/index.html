Dependency Updates Without Chaos

How to Automerge Dependency Updates Safely

Merge patch updates and trusted dev tools without a human, behind required checks and branch protection, and keep majors and production runtime changes for review.

Automerge only what a green CI run can really prove: patch updates and dev-tool updates, with required status checks and branch protection in place. Keep major versions and runtime dependencies that change behaviour for a person. Automerge without good tests is a fast way to ship broken code.

Prerequisites

Before you automerge anything, check three things. First, the default branch is protected and requires the checks that matter (tests, build, lint). Second, those checks are reliable: a flaky suite makes automerge either stall or merge on luck, see Flaky Tests and Flaky CI. Third, your tests cover what a dependency can break. If they do not, fix that first.

Automerge with Dependabot and GitHub Actions

Dependabot does not merge by itself. A common pattern is a workflow that reads the update type with the dependabot/fetch-metadata action and enables auto-merge on the pull request when it is a patch. GitHub then merges it once required checks pass.

name: Dependabot automerge
on: pull_request

permissions:
  contents: write
  pull-requests: write

jobs:
  automerge:
    if: github.actor == 'dependabot[bot]'
    runs-on: ubuntu-latest
    steps:
      - id: meta
        uses: dependabot/fetch-metadata@v2
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
      - if: steps.meta.outputs.update-type == 'version-update:semver-patch'
        run: gh pr merge --auto --squash "$PR_URL"
        env:
          PR_URL: ${{ github.event.pull_request.html_url }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

Allow auto-merge in the repository settings first, or the command fails. Pin the metadata action by SHA if you want to be strict, see keeping Actions up to date.

Automerge with Renovate

Renovate has this built in as a rule:

{
  "packageRules": [
    {
      "matchUpdateTypes": ["patch"],
      "automerge": true
    },
    {
      "matchDepTypes": ["devDependencies"],
      "matchUpdateTypes": ["minor", "patch"],
      "automerge": true
    }
  ]
}

Renovate can wait for status checks, and it can add a minimum release age so brand new versions have a few days to prove themselves. Check the current option names in the Renovate docs before copying.

What to leave for review

  • Major version updates of anything.
  • Runtime dependencies that touch security, authentication, parsing or payments.
  • Updates of the build toolchain or compiler, when they change output.
  • Any package with a new maintainer or a sudden unusual release.

A small time delay before merging patch releases is cheap protection against a compromised or yanked release. The supply chain risk is real, so automerge is a trade-off between speed and exposure.

Start small and widen

Begin with one narrow rule, such as patch updates of dev dependencies, for two weeks. Count how many were merged and whether any broke the branch. If none did, widen to minor updates of dev tools, then to patch updates of runtime packages. Keep a written list of what is allowed to automerge. Widening in steps builds evidence for each decision and gives you a clear point to stop.

Watch what gets merged

Automerged does not mean unseen. Review the merged list weekly. If a bad update slips through, revert it, add a test that would have caught it, and tighten the rule. Track how often automerged PRs break the default branch: if it is more than rarely, the safety net is too thin. Pair this with a fast path for security fixes, which should merge even faster.

Questions people ask

Is automerge for dependencies a good idea?

Yes for patch updates and dev tools when your tests are reliable and branch protection requires them. No for major updates or critical runtime packages.

Why does gh pr merge --auto fail?

Auto-merge must be allowed in the repository settings, and the branch needs at least one required check or protection rule for it to wait on.
