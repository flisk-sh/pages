Renovate Config Basics: A renovate.json You Can Start With

Start from the recommended preset, add a schedule, group related packages with packageRules and enable a dependency dashboard, in under thirty lines.

Create renovate.json in the repository root with extends: ['config:recommended'], then add a schedule and a few packageRules. The recommended preset already sets sensible defaults, so start small and add rules only when a specific pull request annoys you.

A starting config

{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["config:recommended"],
  "schedule": ["before 6am on monday"],
  "timezone": "UTC",
  "prConcurrentLimit": 5,
  "labels": ["dependencies"],
  "packageRules": [
    {
      "matchUpdateTypes": ["minor", "patch"],
      "matchDepTypes": ["devDependencies"],
      "groupName": "dev dependencies"
    }
  ]
}

The schema line gives editor validation. The schedule and the concurrency limit keep the volume predictable. The rule groups minor and patch updates of dev dependencies into one pull request.

How packageRules work

Each rule has matchers and effects. Matchers select updates by package name, update type (major, minor, patch), dependency type, manager or file path. Effects change what Renovate does: group, label, set a schedule, delay, or enable automerge. Rules are applied in order, and later rules override earlier ones for the same update. That lets you write a broad rule first and exceptions after it.

{
  "matchPackageNames": ["react", "react-dom"],
  "groupName": "react"
}

The dependency dashboard

The recommended preset can create an issue that lists all detected updates, which ones are open, which are waiting for the schedule or rate limits, and lets you tick a box to trigger one. It is the best place to see why Renovate has not yet opened a particular update. Read it once a week with your triage, or turn it off if you do not want an extra issue.

Shared presets for many repositories

If you manage several repositories, move your rules into a preset that lives in one repo and extend it everywhere. Each repo then needs a two-line config, and a policy change happens in one place. The Renovate documentation describes the preset naming and hosting, so follow it for the exact reference format. This is the main reason teams with many repos pick Renovate over Dependabot.

Common first rules

  • Pause updates for a package: set enabled to false in a rule that matches it.
  • Separate majors: label them with a rule on matchUpdateTypes and keep them off the schedule of minors.
  • Pin to one Node major: restrict the allowed versions for the runtime package.
  • Keep lockfiles fresh: use the lockfile maintenance feature on a monthly schedule.

Look up each option name in the Renovate documentation before use.

Test your config before you merge it

A broken config means no updates and no loud error. Run the config validator that ships with Renovate on the file, for example npx --yes --package renovate -- renovate-config-validator, and read the first onboarding pull request carefully. Then wire up automerge only for safe cases, see automerge for safe dependency updates, and make sure CI proves each update, see CI checks for dependency PRs.

Questions people ask

What is config:recommended?

A built-in Renovate preset with common defaults, such as the dependency dashboard and sensible grouping. It is the usual starting point in the Renovate documentation.

How do I limit how many PRs Renovate opens?

Set prConcurrentLimit and prHourlyLimit, and use a schedule so updates arrive on defined days.
