Email and notifications in local dev

How to send email from Python and Django to a local inbox

Django has three email backends and Python has a built-in SMTP client. Each fits a different moment in development, and a local catcher covers the one that matters most.

To send email from Python or Django to a local inbox, run a catcher such as Mailpit on port 1025 and set your SMTP host to localhost with port 1025, no username and no TLS. In Django that is four settings. In plain Python it is smtplib.SMTP("localhost", 1025). Read the values from the environment so production can override them.

Plain Python with smtplib

The standard library is enough to prove that mail leaves your code and arrives in the inbox:

import os
import smtplib
from email.message import EmailMessage

msg = EmailMessage()
msg["From"] = "app@example.test"
msg["To"] = "ada@example.test"
msg["Subject"] = "Welcome"
msg.set_content("Plain text body")
msg.add_alternative("<p>HTML body</p>", subtype="html")

host = os.environ.get("SMTP_HOST", "localhost")
port = int(os.environ.get("SMTP_PORT", "1025"))

with smtplib.SMTP(host, port, timeout=10) as smtp:
    smtp.send_message(msg)

Use smtplib.SMTP for plain connections and for STARTTLS (port 587, followed by smtp.starttls()). Use smtplib.SMTP_SSL only for implicit TLS on port 465. For a local catcher, plain SMTP is right. Always set a timeout, otherwise a wrong host can block your request for a long time.

Django settings

Django's SMTP backend reads these settings. Put them in the settings module and drive them from the environment:

import os

EMAIL_BACKEND = "django.core.mail.backends.smtp.EmailBackend"
EMAIL_HOST = os.environ.get("SMTP_HOST", "localhost")
EMAIL_PORT = int(os.environ.get("SMTP_PORT", "1025"))
EMAIL_USE_TLS = os.environ.get("SMTP_TLS", "off") == "on"
EMAIL_HOST_USER = os.environ.get("SMTP_USER", "")
EMAIL_HOST_PASSWORD = os.environ.get("SMTP_PASS", "")
DEFAULT_FROM_EMAIL = "App <no-reply@example.test>"

Then send_mail("Subject", "Body", None, ["ada@example.test"]) from a view or a shell sends it to the catcher. Django has two other backends worth knowing. The console backend (django.core.mail.backends.console.EmailBackend) prints the message to the terminal, which is fine for a quick look but never opens an SMTP connection. The locmem backend stores messages in django.core.mail.outbox, and Django's test runner switches to it automatically, so unit tests can assert on mail.outbox without any server.

A good split: locmem for unit tests, SMTP to a catcher for development and end-to-end tests, and the console backend only when you cannot run a catcher at all.

A unit test with locmem looks like this:

from django.core import mail
from django.test import TestCase

class SignupMailTest(TestCase):
    def test_welcome_mail_is_sent(self):
        self.client.post("/signup/", {"email": "ada@example.test"})
        self.assertEqual(len(mail.outbox), 1)
        self.assertEqual(mail.outbox[0].to, ["ada@example.test"])
        self.assertIn("Welcome", mail.outbox[0].subject)

This test is fast and needs no server. It cannot catch a wrong SMTP host or a TLS mistake, which is why you also send real mail to a catcher by hand or in an end-to-end test.

Flask and other frameworks

Flask-Mail uses MAIL_SERVER, MAIL_PORT, MAIL_USE_TLS and MAIL_USE_SSL. Set MAIL_SERVER=localhost, MAIL_PORT=1025 and both TLS flags to false. FastAPI has no built-in mail layer; use smtplib as above, or a library such as aiosmtplib if you need async sending. The pattern is identical: host and port from environment variables, nothing hard-coded.

No Docker at hand? Python's aiosmtpd package can act as a throwaway SMTP server that prints messages to the terminal: pip install aiosmtpd then python -m aiosmtpd -n -l localhost:1025. It has no inbox UI, so it is a stopgap, not a replacement for Mailpit.

With Flisk

Flisk can run a Python API as a backend resource and Mailpit next to it. Create the API:

flisk resource api --type backend --language python --stack main --yes

Add the Mailpit resource from the Mailpit article and list it in the API's dependsOn. The API container then gets SMTP_HOST and SMTP_PORT from the mail resource, which is why the settings above read those names. Check the result with flisk logs --service api and open the inbox on http://127.0.0.1:8025. If you run the Django development server on your host instead, use localhost and the published port.

Pitfalls

  • Django fails with a certificate or TLS error. EMAIL_USE_TLS is true, but the catcher offers no TLS. Turn it off for local development.
  • Mail sent in a request thread. A slow SMTP server makes your page slow. Move it to a job queue; a Python worker next to your API is one way to do it.
  • Non-ASCII subjects. EmailMessage and Django encode them correctly. Hand-built headers do not, so send a message with an accented name once and read it in the inbox.

Next step

When the mail arrives, check how the HTML looks: preview HTML email templates, and make sure no environment can reach real users with these safeguards.

Questions people ask

Which Django email backend should I use in development?

Use the SMTP backend pointed at a local catcher such as Mailpit. The console backend is a quick fallback, and the test runner already uses locmem for unit tests.

Why does Django say the connection was refused?

Nothing is listening on the host and port you set. Start the catcher, and remember that inside a container localhost means the container, not your laptop.

Can I run a fake SMTP server with only Python?

Yes. Install aiosmtpd and run python -m aiosmtpd -n -l localhost:1025. It prints messages to the terminal but has no web inbox.
