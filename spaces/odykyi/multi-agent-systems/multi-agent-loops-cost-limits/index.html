How to put limits on agent loops, steps and cost

Every agent loop needs a step cap, a token budget, a time limit and a clear stop condition. Here is how to add them in a few lines.

Give every agent run four limits: a maximum number of steps, a token or money budget, a wall-clock timeout and an explicit stop condition. Enforce them in your code, not in the prompt, because a model that is stuck will not reliably stop itself.

The four limits

  • Max steps: the number of model calls or tool calls in one run, for example 20.
  • Token budget: total input plus output tokens across the run.
  • Timeout: wall-clock time, so a hung tool does not block forever.
  • Stop condition: a check that says the goal is met, such as tests passing or a valid result schema.

Pick numbers from real runs. Look at the 95th percentile of a normal run and set the cap a little above it.

A guard around the loop

import time

class Budget:
    def __init__(self, steps=20, tokens=200_000, seconds=300):
        self.steps, self.tokens = steps, tokens
        self.deadline = time.monotonic() + seconds

    def spend(self, used_tokens):
        self.steps -= 1
        self.tokens -= used_tokens
        if self.steps < 0 or self.tokens < 0 or time.monotonic() > self.deadline:
            raise RuntimeError("budget exceeded")

budget = Budget()
while not done(state):
    reply = call_model(state)
    budget.spend(reply.usage_total)
    state = apply(reply, state)

Read the usage numbers from your provider's response. Field names differ between providers, so check the client docs.

Share the budget across agents

In a multi-agent run, one budget object should cover the whole job, not each agent. Pass a shared counter, or divide the budget when the orchestrator creates tasks: if the run has 200,000 tokens and 5 tasks, each worker gets a slice and the orchestrator keeps a reserve for merging.

Put a hop counter in each message too, as in the handoff guide, so handoff loops stop.

What to do when a limit hits

Do not just crash. Return what you have, mark the result as partial, and say which limit stopped it. For long jobs, save a checkpoint so a person or a retry can continue from there rather than start over.

  • Log every limit hit. A rise in hits means prompts or tools have drifted.
  • Alert on unusual spend per run, not only on the monthly total.

Add a per-run cost line to your logs: model, tokens in, tokens out, and the estimated money using the price from your provider's current price page. Review the most expensive runs each week. They almost always show one of three things: a loop, an oversized context, or a retry storm.

Pitfalls

Retries hide cost. A call that fails and retries three times is four calls, so count attempts, not just successes. Do not set limits so tight that a normal run is cut off, since a half-finished run often costs more than a finished one. For wider cost tactics see cutting LLM cost and latency.

Questions people ask

Can I just tell the agent to stop after 10 steps in the prompt?

No. Prompts are advice. Enforce the limit in code, where a stuck model cannot ignore it.

What is a good default step limit?

Measure normal runs and set the cap slightly above the 95th percentile. Many tasks finish well under 20 steps.
