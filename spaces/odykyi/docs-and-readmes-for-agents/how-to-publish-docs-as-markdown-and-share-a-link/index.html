How to publish docs as Markdown and share a link

Markdown is the format both people and agents read best. Learn how to serve docs as .md next to HTML, share a quick page for review and check what you publish.

Keep your docs in Markdown, serve the raw .md files alongside any rendered HTML, and link to them from your README. Plain Markdown is the cheapest format for a model to read, and it is easy for a person to review in a pull request.

Why Markdown

It is plain text, so it diffs cleanly in git, it renders on GitHub, and a model reads it without stripping scripts or navigation. A rendered HTML page costs more tokens and extracts worse.

The trade-off is layout. Markdown has no rich design. For docs, that is usually fine.

Serve both forms

Most static site generators can emit HTML. Make sure the source files are also reachable at a stable URL. Two simple ways:

  • Link to the raw files on GitHub, using the repository's raw content URLs.
  • Copy the .md files into your site's output folder so each page has an HTML and a .md version at matching paths.

Then list the Markdown URLs in an llms.txt file so agents find them.

Share a draft for review

Sometimes you want a reviewer or a teammate to read a page without cloning a repository. Pages publishes an HTML or Markdown file to a free public link with one command.

npx -y @flisk-sh/pages publish README.md --wait

The link is public, so anyone who has it can read it. Do not publish anything private, and do not use it for pages that need access control.

Keep one page per topic

Short, single-topic pages work better for retrieval than one giant file. A model or search tool can pull the page about authentication without loading the whole manual. Give each page a descriptive title, a one-line summary directly under it and headings that match the questions people ask, such as "How to rotate an API key".

Avoid pages that only make sense after reading the previous one. Link to prerequisites instead of assuming them.

Check before you publish

  • No keys, tokens or internal hostnames in examples. Search for them: grep -rniE 'api[_-]?key|secret|token' docs/
  • No private customer data in screenshots or sample output.
  • All links resolve.
  • Every code block runs as written.

Public pages are cached and copied, so removing a leaked secret later does not undo the leak. Rotate the key.

Keep it findable

Give each page a clear title and a one-line summary at the top, since that is what search tools and agents show first. Run a check that AI search can reach the page, for example with Citable. For more on hosting small pages, see Publish pages and host small apps.

Questions people ask

Is Markdown better than HTML for AI readers?

Usually yes. It carries the same content with less markup, so a model reads it faster and with fewer errors.

Is a Pages link private?

No. It is public. Anyone with the link can open it, so publish only what you are happy to share.

Check your README

Find out which sections your README is missing.

README Score gives a GitHub README a score out of 100 with the sections found and missing. It uses fixed rules and no AI, so the same README gets the same score. Free to try.

npx -y @flisk-sh/pages publish README.md --wait
