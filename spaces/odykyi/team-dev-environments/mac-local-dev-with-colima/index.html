Docker on a Mac with Colima for local development

Colima is a light Docker runtime for a Mac, and two of its failure modes are common enough that a doctor check exists for each.

On a Mac you can use Docker Desktop, OrbStack or Colima as the Docker runtime. Colima is free and runs a small Linux VM through Lima. Start it with colima start, size it for your services, and watch two traps: a Lima that was installed for the wrong CPU architecture, and VM disk space that pruning does not give back.

Which runtime to choose

All three work for Flisk, which needs Docker Engine 25 or newer, Compose 2.20.2 or newer and Tilt 0.25 or newer. Docker Desktop has a graphical interface and its own license terms, which you should read if your company is large. OrbStack is a separate commercial product. Colima is open source and command-line only, which suits people who already live in a terminal. A fair comparison is in Docker Desktop vs Colima vs Podman. Use what your company already licenses.

Set it up

  1. Install the pieces: brew install colima docker docker-compose tilt. If you use the Flisk installer, curl -fsSL https://flisk.sh/install.sh | sh adds the CLI.
  2. Start the VM with enough room: colima start --cpu 4 --memory 8 --disk 60. Pick numbers from what your services use, as in running many services on one laptop. You can change them later by stopping and starting with new flags.
  3. Run flisk doctor. It reports the VM state and the checks below.

The Compose plugin must be discoverable by the docker CLI. Check it with docker compose version, and compare the result with the versions above. If a version is too old, doctor reports it as a failed check, so read its message before you search the web.

Trap 1: the wrong Lima on Apple Silicon

If Homebrew runs under Rosetta, or you copied an Intel installation to a new Mac, Lima can be an x86_64 build on an Apple Silicon machine. In that case the VM cannot start. Flisk's Colima check detects it and suggests brew reinstall lima, or putting a native limactl first on your PATH. The check also reports when the VM is not running, with the fix colima start, and when a VM is running that the colima command cannot see.

Trap 2: disk space that never comes back

You delete images and volumes, docker system df shows a small number, and your Mac still reports a full disk. The VM disk file only grows, unless the Linux side tells the host which blocks are free. Pruning frees space inside the VM; a trim hands it back to macOS.

Flisk's Colima Disk check warns when the disk file is at least three times what Docker actually uses, and the gap is at least 5 GiB. The fixes:

flisk doctor --fix
colima ssh -- sudo fstrim -av

The second command trims the filesystem directly. flisk down --prune-cache also trims. If the disk is full to the point that Docker's own store is damaged, you may have to delete and recreate the VM, which removes images and volumes. Dump any database you care about first.

Trap 3: file sharing

Flisk also runs a Docker File Sharing check, a bind-mount probe. It fails when a folder on your Mac cannot be mounted into a container. Keep projects in a normal folder under your home directory. In my own tests, Colima could not mount /private/tmp, so do not run a project from a temporary folder.

Pitfalls and when to choose something else

  • Starting Colima and Docker Desktop together. Two runtimes share the same docker command and the active context decides which one you talk to. Check with docker context ls and stop the one you are not using.
  • Too small a VM. Containers get killed for memory with no clear error. If services vanish, raise --memory.
  • Corporate restrictions. Some companies require a managed runtime. Follow that policy first.

If you do not want to manage a VM at all, and your services can run as plain processes, Flisk can run a project with no Docker, which removes this whole page from your day. Otherwise, next step: run flisk doctor now, and schedule colima ssh -- sudo fstrim -av into your monthly routine. Questions people ask

Why is my Mac disk still full after docker system prune?

Pruning frees space inside the Colima VM only. Run colima ssh -- sudo fstrim -av, or flisk doctor --fix, to return the space to macOS.

Colima will not start on my M-series Mac. Why?

Lima may be installed as an x86_64 build. Run brew reinstall lima, or put a native limactl first on your PATH. flisk doctor detects this.

How do I give Colima more memory?

Stop it and start it with new flags, for example colima start --cpu 4 --memory 8 --disk 60.
