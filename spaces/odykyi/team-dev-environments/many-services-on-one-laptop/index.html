How to run many services on one laptop without running out of RAM

A laptop does not need to run the whole system. It needs to run the slice you are working on, and to tell you when it is short of disk.

To run many services on one laptop, stop trying to run all of them. Start the slice you are working on, group the rest into profiles or stacks, give Docker enough CPU and memory for that slice, and measure the result on your own machine. Flisk helps with --only, --profile and stacks, and it guards your disk. It does not publish a safe service count for a 16 GB laptop, because nobody measured one.

Start less

The biggest saving is not tuning, it is not starting things. Three options in Flisk do this:

  • flisk up --only api,db starts only the services you name.
  • --profile starts a named group. Give a service a profiles list in its service.json, for example ["checkout"], and start the group with flisk up --profile checkout.
  • Stacks split a large project into parts. flisk up payments starts one stack. A project has one Postgres that its stacks share, so a second stack does not add a second database.

The matching idea in plain Compose is profiles and service names on the command line. See one command dev environment for how the pieces fit together.

Services that declare a command run as local processes with no Docker at all. That removes the VM and its memory reservation, but a project cannot mix local processes and containers yet, so it is a choice per project.

What memory does it use

The only figure the project has measured is for its restaurant demo: six services idle at 202.6 MiB in total, split into 133.9 MiB of infrastructure and 68.7 MiB of application containers, across eight containers. That was on macOS with Docker given 4 CPUs and 7.7 GiB. Your services are not that demo. A JVM service or an ML model can use many times more than a small Node API.

So do not extrapolate from a number you read. Measure:

  1. Start the slice you actually use and let it settle for a few minutes.
  2. Look at per-container memory with your container tool, or use the repository's own scripts/benchmark/memory-footprint.mjs or scripts/pilot-scorecard.sh.
  3. Write the total down, add headroom for your editor and browser, and set the Docker VM size above it.

With Colima, the VM size is a flag: colima start --cpu 4 --memory 8 --disk 60. Docker Desktop has the same settings in its Resources panel.

Watch disk and ports as well

Laptops usually fail on disk before memory. flisk up refuses to start with under 5 GiB free and warns under 15 GiB. You can change the limits with FLISK_DISK_MIN_GIB and FLISK_DISK_WARN_GIB. The build cache is trimmed to 20 GiB by default; FLISK_BUILD_CACHE_MAX_GIB changes that, and 0 turns the trimming off.

Ports are allocated per project from fixed ranges: HTTP 8080 to 8180, HTTPS 8443 to 8543 and Postgres 15432 to 15532. That allows about 101 projects at once, which you will not reach. But two projects with the same hard-coded port in their own config will still collide, and flisk doctor warns when two routed resources declare the same one. Run flisk networks to see what each project received.

Pitfalls

  • Everything always on. A shared up alias that starts the whole system makes every laptop pay for services the developer never touches.
  • Forgetting stopped stacks. Running flisk status before you start something new shows what is already using memory.
  • Pruning without trimming. On Colima, deleting images frees space only inside the VM until it is trimmed. flisk down --prune-cache also trims it.
  • Purging by habit. flisk down --purge deletes the project's Docker volumes, so your local database disappears. Use it on purpose.

When a laptop is not enough

If the slice a developer needs does not fit even after trimming, the options are a bigger machine, mocking the far-away services, or a shared remote environment. Each costs something: a mock can drift from the real service, and a shared environment brings back the waiting and the stepping on each other that local development avoided. Choose by what your team can maintain.

Next step: pick the three services you touch most, start only those with --only, and record their memory use. That number, not a guess, tells you what to ask for in a hardware request. Disk and Docker problems on a specific OS are covered in the Windows, Mac and Linux guides in this space, starting with Docker on a Mac with Colima.

Questions people ask

How much RAM does Flisk need?

The only measured figure is for the six service restaurant demo, which idles at 202.6 MiB. Your own services will differ, so measure them with the repository's memory footprint script.

Can I start part of a project?

Yes. Use flisk up --only, flisk up --profile with profiles in service.json, or start a single stack by name.

What stops me from filling the disk?

flisk up stops under 5 GiB free and warns under 15 GiB. The Docker build cache is trimmed to 20 GiB by default.
