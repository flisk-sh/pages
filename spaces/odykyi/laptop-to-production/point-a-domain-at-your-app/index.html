How to point a domain at your app: DNS records and HTTPS

Your app works at a long platform address. Here is how a short domain name ends up pointing at it, with HTTPS.

To point a domain at your app, add a DNS record at your registrar or DNS host. Use a CNAME for a subdomain such as app.example.com pointing to the host's address, and an A record (or an ALIAS or ANAME record) for the bare domain. Then wait for DNS to update, check it with dig, and let the platform or a proxy issue the HTTPS certificate.

Which record to use

RecordMaps a name toUse it for
AAn IPv4 addressA server with a fixed IP, or the apex domain when the host gives you an IP
AAAAAn IPv6 addressThe same, for IPv6
CNAMEAnother hostnameSubdomains that point to a platform address such as myapp.example-host.com
ALIAS or ANAMEAnother hostname, resolved by your DNS providerThe bare domain, when the host gives a hostname and not an IP

The classic trap: a standard DNS rule forbids a CNAME on the bare domain (example.com), because the apex also carries records such as MX for email. Some DNS providers offer ALIAS, ANAME or a flattened CNAME to get around it. If yours does not, use the A record values your host publishes, or put the app on a www or app subdomain and redirect the bare domain to it.

Steps

  1. Add the domain in your host's dashboard first. It tells you the exact record to create and starts waiting to verify it.
  2. Create the record at your DNS provider with the name and value the host gave you. Copy the value exactly, with no extra https:// and no stray spaces.
  3. Lower the TTL beforehand if you are replacing an existing record. The TTL is how long resolvers may cache the old answer. Changing it to a few minutes a day before a switch makes the cutover quick.
  4. Check from the command line, not only the browser, which caches: 
    dig +short app.example.com CNAME
dig +short example.com A
dig +short @1.1.1.1 app.example.com
    The last form asks a specific public resolver, which shows what the rest of the internet sees.
  5. Wait for the certificate. Most platforms issue one automatically with Let's Encrypt or a similar authority once DNS points to them. It can take minutes.
  6. Test HTTPS and the redirect from HTTP: curl -I http://app.example.com then curl -I https://app.example.com.

On your own server

With a VPS, point an A record at the server's IP and put a reverse proxy in front of the app. Caddy requests and renews certificates on its own when ports 80 and 443 reach it and the DNS record is correct. A two-line Caddyfile such as app.example.com { reverse_proxy 127.0.0.1:4000 } is enough to start. The full flow is in deploy a standalone Compose file to a VPS. If certificate issuance fails, the usual causes are a wrong or not yet propagated record, a blocked port 80, or a proxy listening on the wrong host.

Where Flisk fits

Flisk's exporters stop at files. They never create DNS records and never call a cloud API. For Cloudflare Workers, flisk export wrangler --resource <name> --route app.example.com writes a custom-domain route into wrangler.toml (wildcard patterns are refused), and you still deploy with wrangler. The domain's DNS has to be on Cloudflare for that route type to work, which is a Cloudflare requirement, so check their documentation. Details are in generating a wrangler.toml from service.json. Locally you do not need a real domain at all, since a name ending in .localhost resolves to your machine in most browsers. See custom local domain instead of localhost if you want a nicer local name.

After the domain works

  • Update everything that still says the old address: OAuth redirect URIs, webhook endpoints, CORS origins, email links and the public URL variable. See why localhost URLs break in production.
  • Set cookies with the right Domain and Secure flags.
  • Keep the platform address working or redirect it, so old links do not break.
  • Add CAA records if you want to limit which authorities may issue certificates, and make sure your platform's authority is allowed.

Common failures

  • Changes do not show. DNS caches for the TTL. Query the authoritative name servers or a public resolver, and wait.
  • Certificate stays pending. A proxy such as Cloudflare in front can interfere with validation depending on the mode. Read the host's note on it.
  • Email stops working. You replaced the apex records and removed MX or TXT entries. Add them back.

Questions people ask

How long does DNS take to update?

Usually minutes, sometimes up to the TTL of the old record, which can be hours or a day. Lowering the TTL before a change shortens the wait.

Why can't I use a CNAME on my root domain?

The DNS standard does not allow a CNAME to share a name with other records, and the root carries NS and SOA. Use an A record, or an ALIAS or ANAME record if your DNS provider supports it.

Do I need to buy an HTTPS certificate?

Not for a typical app. Most platforms and reverse proxies such as Caddy issue and renew free certificates automatically once the DNS record is correct.
