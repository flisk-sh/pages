How to run an LLM in Docker with GPU support

Run Ollama or vLLM in a container with an NVIDIA GPU: the toolkit you need, the exact docker run commands, model storage and common errors.

Install the NVIDIA driver and the NVIDIA Container Toolkit on the host, then start the container with --gpus all. Mount a volume for model files so you do not download them again every time the container is recreated.

Host setup

On a Linux host with an NVIDIA GPU you need the driver and the NVIDIA Container Toolkit, which lets Docker pass the GPU into containers. Follow NVIDIA's install guide for your distribution, then check:

nvidia-smi
docker run --rm --gpus all ubuntu nvidia-smi

If the second command prints your GPU, containers can use it. Docker Desktop on Mac cannot pass an Apple GPU into a Linux container, so run Ollama natively there.

Reboot or restart the Docker service after installing the toolkit, and configure Docker to use it as the toolkit's guide describes. Skipping that step is the most common reason the GPU is not visible inside a container.

Ollama in Docker

docker run -d --gpus=all \
  -v ollama:/root/.ollama \
  -p 11434:11434 \
  --name ollama ollama/ollama

docker exec -it ollama ollama run llama3.2

The ollama volume keeps downloaded models between runs.

vLLM in Docker

docker run --runtime nvidia --gpus all \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  -p 8000:8000 --ipc=host \
  vllm/vllm-openai:latest \
  --model <huggingface-model-id> --max-model-len 8192

The mounted cache folder avoids re-downloading weights. Some models need a Hugging Face token passed as the HF_TOKEN environment variable. Pin the image to a specific tag in real deployments, not latest.

Pin versions of both the image and the model name in your notes. When something works, you want to be able to rebuild it exactly, not hope that a new image behaves the same.

Compose for repeatability

services:
  ollama:
    image: ollama/ollama
    ports: ["11434:11434"]
    volumes: ["ollama:/root/.ollama"]
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
volumes:
  ollama:

The model server then sits next to your app in one stack. To run such a stack locally with the rest of your services, the open-source Flisk CLI can start them together. It is a local development tool, not a production orchestrator.

Common errors

  • could not select device driver nvidia: the Container Toolkit is missing or Docker was not restarted after install.
  • Out of memory: lower --max-model-len or use a smaller or more quantized model (VRAM guide).
  • Slow first start: weights are downloading.

When something fails, start with the logs: docker logs ollama or docker logs <container>. The first error line usually names the real cause, such as a missing driver, a gated model, or not enough memory.

Questions people ask

Can I run GPU containers on a Mac?

Not with the Apple GPU inside a Linux container. Run Ollama natively on macOS to use it, and use containers for CPU-only workloads.

Should I use the latest image tag?

For experiments, yes. For anything you rely on, pin a version so an update does not change behaviour overnight.
