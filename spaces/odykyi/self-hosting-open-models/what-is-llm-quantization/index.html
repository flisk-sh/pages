What is LLM quantization? GGUF, Q4 and what to pick

Quantization stores a model's weights in fewer bits so it fits in less memory and runs faster, at some quality cost. What the labels mean and how to choose.

Quantization stores a model's weights with fewer bits, for example 4 instead of 16, so the model needs about a quarter of the memory and often runs faster. The cost is a small, usually modest, loss in output quality that grows as you go lower.

What it does

Trained weights are usually 16-bit numbers. Quantization maps them to smaller ones, in groups, with scaling factors to keep the range. The model has the same architecture but a smaller file. Memory is the main limit for local inference, so this is what lets large models run on ordinary hardware.

Think of it like image compression. A heavily compressed photo is still recognisable, but fine detail suffers. A model compressed to 4 bits still answers most questions well, but rare facts and careful reasoning can slip first.

Formats and labels

  • GGUF. The file format used by llama.cpp and Ollama. One file holds weights and metadata.
  • Q8, Q6, Q5, Q4, Q3, Q2. The rough bits per weight. Higher numbers keep more quality and need more memory.
  • K variants such as Q4_K_M. Mixed-precision schemes that keep the more sensitive parts at higher precision. The letters S, M, L mean small, medium and large variants.
  • GPTQ, AWQ. Other methods, often used with GPU servers such as vLLM. Check your server's docs for what it supports.

Which should you pick

A widely used default is a 4-bit K variant such as Q4_K_M: a good balance of size and quality. If you have spare memory, go up to 5 or 6 bits or 8-bit. Below 4 bits, quality drops faster and small models suffer most. A larger model at 4-bit often beats a smaller model at 8-bit in the same memory, but test with your own prompts to confirm.

If your task is strict, such as extracting fields into a fixed JSON shape, run the same test set at two quantization levels and compare. The extra memory is sometimes worth it, and sometimes it changes nothing.

How to see the quantization in Ollama

ollama show llama3.2
ollama pull llama3.2:<tag>    # tags select size and quantization; see the library page

Each model's page on the Ollama library lists the available tags.

Pitfalls

  • Quantization hurts tasks like exact arithmetic and strict JSON more than casual chat. Test those.
  • Different files with the same label can differ by who made them. Prefer reputable publishers.
  • Memory use also depends on the context cache, not only the file. See how much VRAM you need.

Questions people ask

Does quantization make a model worse?

Slightly, and more so at lower bit counts. At 8-bit the difference is usually hard to notice, and at 4-bit it is often acceptable. Test on your own tasks.

Can I quantize a model myself?

Yes. llama.cpp includes conversion and quantization tools, and other projects exist for GPU formats. Check their documentation for the current commands.
