How to run an open LLM locally with Ollama

Install Ollama, pull a model, chat with it and call it from code. The shortest path to a local language model, with the commands and the limits.

Install Ollama, run ollama run <model> to download and chat with a model, and call it from code at http://localhost:11434. The first run downloads the weights, so allow time and disk space.

Install and first run

Get Ollama from ollama.com for macOS, Windows or Linux. Then, in a terminal:

ollama pull llama3.2        # download a model (name from the Ollama library)
ollama run llama3.2         # chat in the terminal
ollama list                 # models on disk
ollama ps                   # models loaded in memory
ollama rm llama3.2          # delete one

Model names come from the Ollama library page. Check it for current names and sizes, since they change.

After the download, the model loads into memory on first use, so the first answer is slower than later ones. If the download seems stuck, check your free disk space: models are large files, often several gigabytes each.

Call it from code

Ollama exposes a local HTTP API and an OpenAI-compatible endpoint under /v1.

curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.2",
    "messages": [{"role": "user", "content": "Say hi in five words."}]
  }'

With an OpenAI client library, set the base URL to http://localhost:11434/v1, pass any non-empty string as the API key, and use the Ollama model name as the model. More in local LLM models.

The same server also has its own native API, for example /api/chat, with a few extra options. If you want code that can move to another server later, use the /v1 endpoint and keep the model name in configuration rather than in code.

Pick a size that fits

The model must fit in memory, either GPU memory or system RAM on a Mac with unified memory. Smaller models, in the low single-digit billions of parameters, run on most laptops. Larger ones need a lot of memory and are slower. How much VRAM do you need explains the arithmetic.

Useful settings

  • Context length. Longer context uses more memory. Set it per request or in a Modelfile with PARAMETER num_ctx.
  • Keep alive. Models unload after a few idle minutes by default. The OLLAMA_KEEP_ALIVE environment variable changes it.
  • Network. By default it listens on localhost only. Binding it to other interfaces exposes an API with no authentication, so put a proxy with auth in front.

When Ollama is not enough

Ollama is excellent for one user or a small team. For many concurrent users on a GPU server, a dedicated server such as vLLM batches requests better. See Ollama vs vLLM vs llama.cpp.

Questions people ask

Do I need a GPU to run Ollama?

No. It runs on CPU, just more slowly. A GPU, or a Mac with Apple silicon, makes responses much faster.

Is the Ollama API safe to expose to the internet?

No. It has no authentication of its own. Keep it on localhost or put it behind a reverse proxy that requires a key.
