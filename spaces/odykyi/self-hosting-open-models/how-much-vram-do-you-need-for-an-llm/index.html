How much VRAM do you need to run an LLM?

A rule of thumb for estimating the memory a model needs from its parameter count and quantization, plus the extra for context, and what to do when it does not fit.

Memory for weights is roughly the parameter count times the bytes per weight, plus room for the context cache and overhead. A 7 billion parameter model at 4-bit needs around 4 to 5 GB for weights, and at 16-bit around 14 GB.

The arithmetic

Each parameter is stored in some number of bits. 16-bit is 2 bytes, 8-bit is 1 byte, 4-bit is half a byte.

weights_GB = parameters_in_billions * bytes_per_weight

7B  at 16-bit: 7 * 2.0 = 14 GB
7B  at  8-bit: 7 * 1.0 =  7 GB
7B  at  4-bit: 7 * 0.5 = 3.5 GB (about 4 to 5 GB in practice)
70B at  4-bit: 70 * 0.5 = 35 GB (more in practice)

Real files are a bit larger than the formula because some layers stay at higher precision and the file holds extra data.

A quick sanity check: the download size of a quantized model file is close to the memory its weights will need. If a file is 4.7 GB, plan for a little over that before the context cache.

Add the context cache

While generating, the model stores attention keys and values for every token in the context. This KV cache grows with context length and with the number of concurrent requests. A long context or a busy server can use several more GB. If memory runs out, reduce the context length first.

Two ways to keep the cache small are shorter prompts and fewer simultaneous requests. Some servers can also store the cache at lower precision. Check your server's docs for that option and test quality afterwards.

Add overhead

Leave headroom for the runtime, the driver and your desktop. A common habit is to keep 10 to 20 percent free. On servers, vLLM has a --gpu-memory-utilization option to cap how much GPU memory it claims.

Unified memory and CPU

On Apple silicon the GPU shares system memory, so total RAM is the limit, minus what the system needs. On CPU-only machines the model sits in RAM and runs slowly but works. Partial offload, where some layers live on the GPU and the rest on CPU, is supported by llama.cpp and Ollama and lets a model run that does not fully fit, at lower speed.

When it does not fit

  1. Use a more aggressive quantization (what is quantization).
  2. Pick a smaller model.
  3. Shorten the context.
  4. Rent a bigger GPU for the job, or use a hosted API (self-host vs hosted).

Check the model card for the exact file sizes. They beat any estimate.

Questions people ask

Does a 16 GB GPU run a 13B model?

At 4-bit quantization, usually yes with a moderate context, since the weights are around 7 to 9 GB. At 16-bit, no.

Is system RAM a substitute for VRAM?

It works but is much slower. Models can run from RAM on CPU, which is fine for testing and poor for real traffic.
