How to point the AWS SDK at a local S3 endpoint (Node, Python)

Four settings decide whether the SDK talks to your local server or fails with a DNS error. Here they are for Node and Python.

To point the AWS SDK at a local S3 server, set four things: the endpoint URL, a region (any value, but it must be set), path-style addressing, and the access key pair. In the JavaScript SDK v3 that is endpoint, region and forcePathStyle: true. In boto3 it is endpoint_url, region_name and an addressing style of path.

Why the defaults fail locally

By default the SDK builds the host name from the bucket: mybucket.s3.us-east-1.amazonaws.com. With a custom endpoint like http://localhost:9000 and virtual-hosted style, it would try mybucket.localhost:9000 or, inside Docker, mybucket.store:9000, and neither name resolves. Path-style puts the bucket in the path instead: http://localhost:9000/mybucket/key. Every S3-compatible server accepts that form.

The region matters even though your server ignores it. The SDK needs one to sign requests, and without it you get an error about a missing region. us-east-1 is the conventional dummy value.

Node: AWS SDK for JavaScript v3

import { S3Client, CreateBucketCommand, PutObjectCommand } from "@aws-sdk/client-s3";

export const s3 = new S3Client({
  region: process.env.AWS_REGION ?? "us-east-1",
  endpoint: process.env.AWS_ENDPOINT_URL_S3,   // undefined in production: real S3
  forcePathStyle: Boolean(process.env.AWS_ENDPOINT_URL_S3),
});

export async function ensureBucket(name) {
  try {
    await s3.send(new CreateBucketCommand({ Bucket: name }));
  } catch (err) {
    if (err.name !== "BucketAlreadyOwnedByYou") throw err;
  }
}

await ensureBucket("uploads");
await s3.send(new PutObjectCommand({
  Bucket: "uploads", Key: "hello.txt", Body: "hi", ContentType: "text/plain",
}));

Credentials come from the standard environment variables AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY, so the code needs no key handling. The trick is that the same file works in production: when AWS_ENDPOINT_URL_S3 is not set, the client talks to real S3 with virtual-hosted style.

Python: boto3

import os, boto3
from botocore.config import Config

endpoint = os.environ.get("AWS_ENDPOINT_URL_S3")
s3 = boto3.client(
    "s3",
    endpoint_url=endpoint,
    region_name=os.environ.get("AWS_REGION", "us-east-1"),
    config=Config(s3={"addressing_style": "path"} if endpoint else {}),
)

try:
    s3.create_bucket(Bucket="uploads")
except s3.exceptions.BucketAlreadyOwnedByYou:
    pass

s3.put_object(Bucket="uploads", Key="hello.txt", Body=b"hi", ContentType="text/plain")

Recent SDKs read the endpoint variable themselves

AWS_ENDPOINT_URL_S3 is a standard SDK setting for a service-specific endpoint, and current versions of the AWS SDKs and CLI pick it up with no code. Older versions ignore it. Passing it explicitly as above works everywhere, and it keeps the intent visible in the code. You still need path-style: the variable sets the endpoint, not the addressing style.

Where the variables come from with Flisk

The Flisk MinIO resource lists AWS_ENDPOINT_URL_S3, AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY in its provides block (see how to run MinIO locally). Any service that lists the store in dependsOn gets them in its generated env file, so the snippets above run unchanged:

"appName": "api",
"dependsOn": ["store"]

You can check what the service sees without starting a shell by running flisk run api -- printenv AWS_ENDPOINT_URL_S3 in a running stack. flisk run gives the command the environment that service has. The value inside the stack is http://store:9000.

Pitfalls

  • Checksum errors on non-AWS servers. Since early 2025 the JavaScript SDK v3 adds default integrity checksums to uploads. Some S3-compatible servers reject them. If you see a checksum or signature error after upgrading the SDK, set requestChecksumCalculation: "WHEN_REQUIRED" on the client.
  • Host versus container address. A script on your laptop needs http://127.0.0.1:9000, which only works if the port is published. Inside the stack it is http://store:9000. Read the endpoint from an env var and set it per place.
  • Self-signed TLS. If you run a local S3 over https with a private certificate, the SDK rejects it. Use plain http on localhost, or add the CA to the SDK's trust store.
  • Bucket names. S3 rules apply: 3 to 63 characters, lowercase letters, digits and hyphens. A name that works on MinIO can still be invalid on S3 if it has an underscore.

When not to use this

If your code goes through an abstraction such as a storage adapter that already has a local disk driver, use the disk driver for unit tests and keep the S3 path for one integration test. You still want one test that uses a real S3 protocol, because path style, signing and headers are where the bugs are. See integration tests against the real stack.

Once reads and writes work, move to presigned upload URLs for browser uploads, or test your uploads against the real bucket.

Questions people ask

Which region should I use for a local S3 server?

Any value works, because the server ignores it, but the SDK needs one to sign requests. us-east-1 is the usual dummy value.

Why do I get a DNS error for mybucket.localhost?

The SDK used virtual-hosted style, which puts the bucket in the host name. Turn on path-style addressing: forcePathStyle in the JavaScript SDK, addressing_style path in boto3.

Does the AWS CLI work with MinIO?

Yes. Set AWS_ENDPOINT_URL_S3 and the key variables, or pass --endpoint-url on each command. Use a CLI version recent enough to read AWS_ENDPOINT_URL_S3.
