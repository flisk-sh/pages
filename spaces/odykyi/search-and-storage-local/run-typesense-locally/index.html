How to run Typesense locally with Docker and create a collection

Typesense insists on an API key and a data directory. Set both and you have a fast search server to develop against.

To run Typesense locally, start the typesense/typesense image with --data-dir, a made-up --api-key, and port 8108 published on 127.0.0.1. Every request must then carry the key in an X-TYPESENSE-API-KEY header. Create a collection with a schema, import documents, and search with query_by.

The plain Docker way

docker run -d --name dev-typesense \
  -p 127.0.0.1:8108:8108 \
  -v dev_typesense_data:/data \
  typesense/typesense:27.1 \
  --data-dir=/data --api-key=local-dev-key --enable-cors

Typesense will not start without an API key and a data directory. The key is yours to invent. For local work any string will do, but keep it out of any real environment. --enable-cors lets a browser page call the server directly, which you only want if a frontend talks to Typesense without a backend in between. Check with curl http://127.0.0.1:8108/health, which returns {"ok":true}.

Create a collection, add documents, search

Unlike some engines, Typesense wants a schema before documents arrive:

export TS_KEY=local-dev-key

curl -X POST 'http://127.0.0.1:8108/collections' \
  -H "X-TYPESENSE-API-KEY: $TS_KEY" -H 'Content-Type: application/json' \
  -d '{
    "name": "books",
    "fields": [
      {"name": "title", "type": "string"},
      {"name": "author", "type": "string", "facet": true},
      {"name": "year", "type": "int32"}
    ],
    "default_sorting_field": "year"
  }'

curl -X POST 'http://127.0.0.1:8108/collections/books/documents/import?action=upsert' \
  -H "X-TYPESENSE-API-KEY: $TS_KEY" -H 'Content-Type: text/plain' \
  --data-binary '{"id":"1","title":"Dune","author":"Frank Herbert","year":1965}
{"id":"2","title":"Dubliners","author":"James Joyce","year":1914}'

curl "http://127.0.0.1:8108/collections/books/documents/search?q=dnue&query_by=title" \
  -H "X-TYPESENSE-API-KEY: $TS_KEY"

The import endpoint takes JSON Lines, one document per line, and action=upsert makes it safe to run twice. Search requires query_by, the field or fields to match against. The misspelled dnue still finds "Dune" because typo tolerance is on by default.

The import response reports success per line. A 200 status does not mean every document was accepted, so read the body in scripts.

The Flisk way

Typesense is not a built-in Flisk framework, so use a bring-your-own resource. Scaffold it, then edit the file:

flisk resource ts --type bring-your-own --image typesense/typesense:27.1 --no-proxy --stack shop --yes

The CLI writes a port in the 4000 to 5999 range; change it to 8108 in services/shop/ts/service.json, and add the rest:

{
  "appName": "ts",
  "appType": "bring-your-own",
  "stack": "shop",
  "port": 8108,
  "image": "typesense/typesense:27.1",
  "exposeViaProxy": false,
  "healthCheck": { "port": 8108 },
  "extraPorts": [{ "port": 8108 }],
  "volumes": [{ "source": "ts-data", "target": "/data" }],
  "container": { "command": ["--data-dir=/data", "--api-key=local-dev-key", "--enable-cors"] },
  "provides": { "TYPESENSE_URL": "http://ts:8108", "TYPESENSE_API_KEY": "local-dev-key" }
}

container.command replaces the image's default arguments, which is how the data directory and key reach the server. The two values in provides reach every service that lists ts in dependsOn. Flisk's own docs say never to put a secret in provides, because the values land in generated files. A throwaway local key is fine there. A real key is not. flisk config verify checks the file, and flisk up shop starts it.

From a container in the stack, the client connects to ts on port 8108 with protocol http. From your laptop, the host is 127.0.0.1.

Pitfalls

  • Schema changes. You cannot change a field's type in place. Create a new collection, reindex into it and switch an alias. Typesense has collection aliases for this.
  • id is a string. Documents take an id of type string. Pass numbers as strings or leave it out and let Typesense generate one.
  • Search key versus admin key. In real deployments you give the browser a search-only key. Locally one key is enough, but code that forgets the difference will break later. Create a scoped key as part of your setup so the dev path matches production.
  • Pin the version. A data directory written by a newer release may not open with an older one.

When not to use it

If you want an engine that infers its schema from the first document, Meilisearch is lighter to start with. If your text search needs are modest, Postgres full-text search avoids a second service.

Questions people ask

Why does Typesense refuse to start?

It needs both a data directory and an API key. Pass --data-dir and --api-key as arguments to the container, and mount a volume at the data directory so the data survives restarts.

What is query_by?

It lists the fields a search matches against. Every search request must include it, for example query_by=title.

Do I need --enable-cors?

Only if a browser page calls Typesense directly. If your backend does the searching, you can leave it off.
