Local URLs, routing and HTTPS

Why redirects go to http or the wrong port behind a proxy

Your app sees the proxy, not the browser. Forwarded headers are how it learns the truth, if you tell it to believe them.

Behind a reverse proxy your app sees the proxy's connection: plain HTTP, the proxy's address, and sometimes a different host and port. The proxy reports the original values in X-Forwarded-Proto, X-Forwarded-Host, X-Forwarded-For and X-Forwarded-Prefix. You must tell your framework to trust those headers, or it builds redirects, absolute links and cookies from the wrong values.

The symptoms

  • A login redirect goes to http:// when the page is on https://, and the browser blocks it as mixed content or loops.
  • A redirect drops a port or prefix: you were at http://shop.localhost:8080/api/orders and land on http://shop.localhost/login.
  • Logs show 127.0.0.1 or a container address as every client IP.
  • OAuth providers reject the callback because the redirect URI your app built does not match the registered one.

What each header means

HeaderCarries
X-Forwarded-ForThe client address, or a chain of addresses
X-Forwarded-Protohttp or https as the browser used
X-Forwarded-HostThe original Host
X-Forwarded-PrefixA path prefix the proxy removed, for example /api/orders

Traefik sets the first three on requests it forwards, and its StripPrefix middleware adds X-Forwarded-Prefix. Caddy sets the X-Forwarded-* trio. In nginx you add them yourself with proxy_set_header.

Tell the framework to trust them

Frameworks ignore these headers by default, because any client can send them. Trust them only when the proxy is the one that sets them, and in local dev that is always true for traffic that goes through your proxy.

// Express
app.set("trust proxy", 1);   // one proxy hop

# Django settings.py
SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")
USE_X_FORWARDED_HOST = True

# Flask
from werkzeug.middleware.proxy_fix import ProxyFix
app.wsgi_app = ProxyFix(app.wsgi_app, x_for=1, x_proto=1, x_host=1, x_prefix=1)

Rails honors X-Forwarded-Proto and X-Forwarded-For through its trusted proxy list, which already includes loopback and private address ranges. Spring Boot has server.forward-headers-strategy=framework. In Go, read the header yourself or use middleware you trust.

The prefix is different. Most frameworks do not read X-Forwarded-Prefix unless asked (Flask's ProxyFix with x_prefix=1 does, as does Spring with the framework strategy). Otherwise you set a base path or root path option: root_path in FastAPI, base in Vite, basePath in Next.js.

Where Flisk fits

In the Docker path, Flisk's generated route for a backend strips the prefix with Traefik's StripPrefix middleware. The service therefore receives /orders, while the browser used http://api.<project>.localhost/api/orders. For JSON APIs that is what you want. For anything that creates absolute URLs (pagination links, OAuth redirect URIs, Swagger or OpenAPI docs) read the forwarded host, proto and prefix, or the links will leave out the /api/orders part. Flisk's own documentation notes that a frontend served under a stripped path needs its base set.

The ingress port is another part of the URL: flisk up prefers port 80, and falls back to 8080 or another port when 80 is busy. Printed URLs then include it. Check what your app sees by logging the three headers once. Everything else on this page applies unchanged, because Traefik is an ordinary reverse proxy.

For a project of local processes there is no Flisk gateway, so there is nothing to forward unless you add your own proxy.

How to check

curl -i http://api.shop.localhost/api/orders/debug -L

Add a temporary route that returns req.protocol, req.hostname and req.ip (Express names). If the protocol says http behind an HTTPS proxy, the trust setting is missing. If the IP is always the proxy's, same cause.

Pitfalls

  • Trusting too much. trust proxy: true trusts any client-sent X-Forwarded-For. Locally harmless, but copy only the narrow setting into production.
  • Two proxies. Caddy in front of Traefik gives two hops. Set the hop count to 2, or you read the inner proxy's address.
  • Relative redirects. Prefer relative Location headers where your framework allows them. They survive any front proxy.

For proxy examples that set these headers, see routing several local services through one nginx. If your problem is a rejected name instead of a wrong URL, read Invalid Host header in local dev.

Questions people ask

Why does my app redirect to http behind an HTTPS proxy?

The app sees a plain HTTP connection from the proxy. Tell it to trust X-Forwarded-Proto, for example with app.set('trust proxy', 1) in Express.

Is it safe to trust forwarded headers?

Only when the proxy sets them and clients cannot reach the app directly. Any client can send the headers, so trust the narrowest number of hops.

Does Flisk strip the path prefix?

Yes, in the Docker path the generated Traefik route for a backend strips /api/name before the request reaches your container.
