Cut LLM cost and latency

How to reduce LLM latency in a production app

Where LLM response time goes, and the changes that cut it: shorter outputs, smaller models, parallel calls, caching and streaming.

Most LLM latency comes from generating output tokens one at a time, so the biggest wins are asking for less output, using a smaller model and starting work in parallel. Network and prompt size matter too, but output length usually dominates.

Break latency into parts

Measure three numbers per call: time to first token, tokens per second, and total time. Time to first token depends on prompt size and queueing. Total time is roughly first-token time plus output tokens divided by speed.

const t0 = performance.now();
// ...stream the response...
// on first chunk: ttft = performance.now() - t0
// on end: total = performance.now() - t0

Ask for less output

Every output token adds time. Ask for a short format, use a structured field instead of prose, and set max_tokens. A classification that returns one label is far faster than one that explains itself. If you need the explanation, generate it only on demand.

Use a smaller or faster model where it fits

Smaller models generate faster. Keep a test set and move the easy steps of a pipeline to a smaller model. See model routing for how to decide per request.

Run independent calls in parallel

If a feature makes three separate model calls that do not depend on each other, start them together.

const [a, b, c] = await Promise.all([
  summarize(doc), extractEntities(doc), classify(doc)
]);

Watch your provider rate limits. Parallel calls spend them faster.

Hide the wait

Streaming does not make the model faster, but the user sees text after the first token instead of after the last. Read how to stream LLM responses. Also trim the prompt, since a long input raises time to first token, and cache the stable prefix.

Pitfalls

  • Chaining many small calls in series when one prompt would do.
  • Retry-on-timeout with a long timeout. Set a sensible timeout and fall back.
  • Calling a model from a region far from your server.

Set a timeout per call and decide the fallback in advance: a shorter answer, a cached answer or a plain error message. A slow model call that holds a web request open for a minute hurts more than a fast, slightly weaker answer. Track the 95th percentile, not just the average, since users remember the slow calls.

Finally, test from the same region as production. A fast local run can hide a slow route to the provider.

One more habit: keep a latency budget per feature, for example two seconds to first token. Write it in the ticket and check it in a dashboard. A number everyone can see is harder to let slip than a vague wish to be fast.

Questions people ask

Why is my LLM call slow even with a short prompt?

Generation time grows with output length. A long answer from a large model takes seconds regardless of how short the prompt is.

Does streaming reduce total latency?

No, total time is about the same. It reduces perceived latency because text appears after the first token.
