Cut LLM cost and latency

How to count tokens and estimate LLM cost before you ship

Count tokens in code, turn them into a per-request and monthly cost estimate, and avoid the surprises that blow up a budget.

Count input tokens with your provider's tokenizer or token-count endpoint, add an estimate for output tokens, and multiply by the per-token prices from the pricing page. Do this per feature, then multiply by expected traffic to get a monthly figure.

Tokens are not words

A token is a chunk of text, often a word piece. English averages somewhere around three to four characters per token, but code, other languages and unusual formatting change it a lot. Never estimate from word count alone when money is at stake.

Each model family has its own tokenizer, so counts differ between providers. Use the one that matches the model you call.

Count in code

Some providers expose a token-counting call. For OpenAI-style models you can also use a local tokenizer library such as tiktoken.

import tiktoken
enc = tiktoken.get_encoding('cl100k_base')
print(len(enc.encode('Summarise this text.')))

The encoding name must match your model. Check the provider docs for the right one. The authoritative number is always the usage block in the real response.

Write the cost formula

def cost(inp, out, price_in, price_out):
    # prices per million tokens, from the pricing page
    return inp / 1e6 * price_in + out / 1e6 * price_out

per_request = cost(2400, 350, PRICE_IN, PRICE_OUT)
monthly = per_request * requests_per_day * 30

Take the prices from the current pricing page. They change, so keep them in config, not in code.

Include what people forget

  • The system prompt and tool definitions count as input on every call.
  • Conversation history grows with each turn, so cost per turn rises over a long chat.
  • Retries, and every step of an agent loop, are separate paid calls.
  • Images and files are billed as tokens too.

Check estimate against reality

After a week of traffic, compare your estimate with the sum of logged usage. A gap of more than about twenty percent means a hidden cost, usually history growth or retries. Fix those first, see how to reduce LLM API costs and set budgets and rate limits.

Build a tiny cost dashboard

You do not need a product for this. One table with columns for date, feature, model, input tokens, output tokens and computed cost is enough. A daily query that sums cost by feature tells you where to look. Add a second query for the top ten users by cost, since heavy users often explain a surprise bill.

SELECT feature, SUM(cost) AS usd
FROM llm_calls
WHERE day = CURRENT_DATE
GROUP BY feature
ORDER BY usd DESC;

Questions people ask

How many tokens is 1,000 words?

Roughly 1,300 to 1,500 tokens in English, but it varies by model and text. Count with the real tokenizer if it matters.

Do output tokens cost the same as input tokens?

Usually not. Most providers price output tokens higher than input tokens. Check the pricing page for your model.
