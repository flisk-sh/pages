How to stream LLM responses to users with SSE

Send tokens to the browser as they are generated using server-sent events, with a minimal server, a client reader and the cancel and error cases people forget.

Request a streamed response from the model, forward each chunk to the browser as a server-sent event, and read it with fetch on the client. Users see the first words in a fraction of a second instead of waiting for the full answer.

Ask the provider to stream

Most provider SDKs accept a stream: true option and give you an async iterator of chunks. Each chunk holds a small piece of text. Your server loops over the chunks and writes them out.

A minimal Node server

import http from 'node:http';

http.createServer(async (req, res) => {
  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    Connection: 'keep-alive',
  });
  const ac = new AbortController();
  req.on('close', () => ac.abort());
  for await (const text of modelStream(ac.signal)) {
    res.write('data: ' + JSON.stringify(text) + '\n\n');
  }
  res.write('event: done\ndata: {}\n\n');
  res.end();
}).listen(3000);

modelStream stands for your SDK call. Encode each chunk as JSON so newlines inside the text do not break the event format.

Read it in the browser

const res = await fetch('/chat', { method: 'POST', body });
const reader = res.body.getReader();
const dec = new TextDecoder();
let buf = '';
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buf += dec.decode(value, { stream: true });
  const parts = buf.split('\n\n');
  buf = parts.pop();
  for (const p of parts) render(JSON.parse(p.replace(/^data: /, '')));
}

Use fetch rather than EventSource when you need to send a POST body or custom headers.

Handle cancel and errors

  • Abort the upstream model call when the client disconnects, or you keep paying for tokens nobody reads.
  • Send an explicit error event so the UI can show a message instead of a frozen cursor.
  • Do not buffer: a proxy or compression layer that holds chunks back will make streaming look broken. Check proxy settings if text arrives in one lump.

Trade-offs

Streaming makes output validation harder, since you show text before you have all of it. For JSON or tool calls, stream to the user only the prose part, and parse structured data after the end. For speed ideas beyond streaming, see how to reduce LLM latency.

Test it with curl

Before you write any UI, check the stream from a terminal. The -N flag turns off curl's output buffering so you see chunks as they arrive.

curl -N -X POST http://localhost:3000/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"hello"}'

If the text appears piece by piece here but not in the browser, the problem is in the client code or in a proxy in front of the page. If it arrives in one block here too, look at your server or at compression.

Questions people ask

Should I use SSE or WebSockets for LLM streaming?

SSE is simpler for one-way token streams and works over plain HTTP. Use WebSockets only if you need two-way messages on the same connection.

Why does my stream arrive all at once?

A proxy, CDN or compression middleware is buffering the response. Disable buffering for that route.
