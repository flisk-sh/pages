Node.js watch mode: node --watch instead of nodemon

Node can restart itself when a file changes. For most small and medium servers that removes a dependency.

Run node --watch server.js. Node starts your program, tracks the files it imports, and restarts the process when one of them changes. Watch mode is stable in current Node releases (Node 20.13 and later, and Node 22), so for a plain server you no longer need nodemon.

What node --watch does

It is a restart loop, not hot module replacement. Every save kills the process and starts a new one, so in-memory state is lost and the port is released and bound again. That is fine for an API that keeps its state in a database. It is annoying for a server that holds a large cache or a long WebSocket session, because every client reconnects.

{
  "scripts": {
    "dev": "node --watch src/server.js",
    "start": "node src/server.js"
  }
}

By default Node watches the entry file and the modules it loads with import or require. It does not know about files you read at runtime, such as a JSON config opened with fs.readFile, an email template or a SQL file. Name those with --watch-path:

node --watch --watch-path=./src --watch-path=./templates src/server.js

Pass the flag once per directory. Be aware that when you use --watch-path, Node watches those paths and no longer relies on the import graph alone, so list every folder you care about. If your terminal gets cleared on each restart and you lose the error, add --watch-preserve-output.

When nodemon is still the better tool

  • You want a delay. Editors and code generators can write many files in a burst. Nodemon has --delay and per-extension settings in nodemon.json. Node's flag has no debounce setting.
  • You watch non-JavaScript files and need to choose extensions (--ext js,json,graphql).
  • You must run an arbitrary command on each change, not just Node. Nodemon can restart a Python script as easily as a JavaScript one.

For TypeScript, tsx watch src/server.ts is the usual choice when you run through a loader. Newer Node versions can run .ts files directly, and the watcher works the same way. See running TypeScript in Node without a build step.

Use watch mode as a Flisk service command

A Flisk service that declares a command runs as a local process. Flisk does not add its own file watcher for these services, so the reload behaviour comes from the command you write. Flisk's own docs suggest exactly this for live reload without Docker: put node --watch (or Bun's or uvicorn's watch flag) in the command.

{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "api",
  "appType": "backend",
  "command": "node --watch src/server.js",
  "port": 4000,
  "healthCheckPath": "/health"
}

Flisk passes the port to your process as the PORT environment variable, so read process.env.PORT in the server. Start it with flisk up. When Node restarts inside the same Flisk-managed process, Flisk sees one long-running service and does not restart it. When your code crashes at startup, Node's watcher waits for the next file change, so the process stays alive. Flisk shows the output in the log lines prefixed with the service name, and you can read recent lines with flisk logs --service api --tail 50.

A process that exits is a different case. If the command ends (for example you drop --watch), Flisk starts it again after 1 second, then 2, 4 and 8, and gives up after five quick exits in a row.

Pitfalls

  • Port still in use after a restart. If your shutdown handler hangs, the new process cannot bind. See graceful shutdown for a dev server.
  • Changes to .env do not trigger a restart unless the file is in a watched path. Add it with --watch-path, or restart by hand.
  • Too many files. If you run a monorepo from the root, do not point --watch-path at .: it includes node_modules and build output. Watch the source folders only.
  • Nothing happens on save inside a container with a bind mount. Notifications may not cross the mount, which is a Docker issue and not a Node one. See hot reload not working.

Next step

If the restarted server keeps exiting with an error, attach a debugger instead of reading logs: debug Node with --inspect and VS Code works with --watch.

Questions people ask

Is node --watch stable?

Yes in current releases. It became stable in Node 20.13 and Node 22. On older versions it prints an experimental warning.

Does node --watch reload when a JSON or template file changes?

Only if that file is imported, or if you list its folder with --watch-path. Files read at runtime with fs are not tracked by default.

Does Flisk watch my files for local processes?

No. For a service with a command, Flisk starts and supervises the process. Live reload comes from the command, for example node --watch.
