Sitemaps, canonical URLs and meta tags for AI crawlers

The technical basics that help any crawler find and identify your pages: sitemap.xml, canonical links, titles, descriptions and the noindex mistakes that hide a site.

Publish a sitemap.xml that lists your public pages, give each page one canonical URL, a unique title and a meta description, and make sure no leftover noindex tag hides the page. These basics serve classic search and the crawlers behind AI answers.

A minimal sitemap

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://example.com/</loc></url>
  <url><loc>https://example.com/docs/start/</loc><lastmod>2026-03-01</lastmod></url>
</urlset>

List only canonical, public, indexable URLs that return 200. Reference the file from robots.txt with a Sitemap: line, as in the robots.txt guide. Generate it at build time so it never drifts.

Canonical URLs

The same page often loads at several addresses: with and without a trailing slash, with tracking parameters, over http and https. Tell crawlers which one is the real one.

<link rel="canonical" href="https://example.com/docs/start/" />

Use absolute URLs, one canonical per page, and make it point to a page that returns 200. Redirect the alternates with a 301 where you can.

Title and description

  • A unique <title> per page, under about 60 characters, that says what the page is.
  • A meta name="description" of one or two plain sentences.
  • One <h1> that matches the topic.

These are the first fields a parser reads, and a model often uses the title as the label for a citation, so make it readable on its own.

Open Graph tags

Open Graph tags such as og:title, og:description and og:image control how a link looks when shared in chats and social apps. They also give another short, clean description of the page. Add them in the template once.

The noindex trap

Staging builds often carry noindex in a meta tag or an X-Robots-Tag header, and it ships to production by accident. Search for it after every deploy.

curl -s https://example.com/ | grep -i 'noindex'
curl -sI https://example.com/ | grep -i 'x-robots-tag'

Both should return nothing on a public page. Put these two lines in your release check and see how to check if AI can read your site for the rest of the audit.

Submit and verify

Reference the sitemap in robots.txt and, if you use them, submit it in the search consoles of the engines you care about. Then open the sitemap in a browser and spot-check five URLs: each should load with a 200, show the same canonical in its head and carry no noindex. A sitemap full of redirects or error pages teaches crawlers to distrust it, so remove dead URLs on every build.

Questions people ask

Do I need a sitemap for a small site?

It is optional for a few well-linked pages, but it is cheap and helps discovery, so add it.

Should the sitemap include every URL?

No. Include only canonical, public pages that return 200 and that you want found.
