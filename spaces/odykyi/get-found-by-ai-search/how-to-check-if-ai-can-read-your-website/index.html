How to check if AI search can read your website

A five-minute audit: fetch the page as a bot, read the raw HTML, check robots.txt and headers, then run a checker and fix what it finds.

Fetch your page with curl using an AI bot user agent, confirm you get a 200 response with real text in the HTML, check robots.txt and headers, and then run a checker for the rest. Most problems turn up in the first two steps.

1. Fetch as a bot

curl -s -o /dev/null -w '%{http_code}\n' -A 'Mozilla/5.0 (compatible; GPTBot/1.0)' https://example.com/
curl -s -o /dev/null -w '%{http_code}\n' -A 'PerplexityBot' https://example.com/

A 200 is what you want. A 403, 429 or a redirect to a challenge page means a firewall or bot rule blocks the crawler.

2. Read the raw HTML

curl -s https://example.com/ | grep -c '<h1'
curl -s https://example.com/ | head -c 2000

Look for your headline and your main paragraph in the output. If you see only scripts and an empty container, read the JavaScript guide.

3. Check robots.txt and headers

Open /robots.txt and confirm no rule blocks the bots you want. Then look at response headers for X-Robots-Tag: noindex, which tells crawlers to skip the page even if robots.txt allows it. Also check the page has no <meta name="robots" content="noindex"> left over from a staging build.

curl -sI https://example.com/ | grep -i 'x-robots-tag'

4. Run a checker

Citable checks whether AI search and chatbots can find, read and cite a website. It also offers an MCP endpoint at https://citable.flisk.si/mcp, so a coding agent can run the check from your editor. Treat the result as a list of things to fix, not a guarantee of ranking.

5. Fix, then recheck

Fix one blocker at a time and rerun the same commands, so you know which change worked. When the basics pass, move to content quality: write content AI answers quote. Add the audit to your release checklist, because a new firewall rule or a framework upgrade can break crawlability without any visible change.

Common findings and fixes

FindingLikely fix
403 for bot user agentsRelax the firewall or bot-protection rule for named crawlers
Empty HTML bodyServer render or prerender the page
noindex headerRemove it from the production config
robots.txt is an HTML pageServe a real text file at that path

Save the commands in a small shell script in your repo and run it from CI against your staging URL. A failing exit code on a 403 or a missing headline turns this audit from a one-off chore into a guard that protects every release. Keep the script short, so anyone can read it and change the URLs it checks.

Questions people ask

What does a 403 for a bot mean?

Your server, CDN or firewall refuses that user agent. Look at bot-protection rules and allow the crawlers you want.

How often should I run the check?

After any change to hosting, firewall, robots.txt or rendering, and once a month as a routine.
