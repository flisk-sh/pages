llms.txt: what it is and how to write one

A proposed plain-text file that points language models to your best pages. Learn the format, what to put in it, and why it is cheap to add but not a ranking switch.

llms.txt is a proposed convention: a Markdown file at the root of your site that gives a model a short summary of the site and links to the pages that matter. It is cheap to add and helpful to tools that read it, but no major search product has promised to rank you for it.

What the file looks like

The proposal uses plain Markdown. A title, a one-line summary in a blockquote, then sections of links with short notes.

# Acme Billing

> Acme Billing is an open-source invoicing library for Node.

## Docs

- [Quick start](https://acme.dev/docs/start.md): install and send a first invoice
- [API reference](https://acme.dev/docs/api.md): every function and option

## Optional

- [Changelog](https://acme.dev/changelog.md)

Serve it at /llms.txt with a text content type. Check the llms.txt proposal site for the current wording of the format.

What to put in it

  • One sentence on what the product is and who it is for.
  • Links to the five to twenty pages you would hand a new engineer.
  • A short note on each link, so a model can choose.
  • Links to Markdown versions of pages when you have them, since clean text is easier to read than a styled page.

A longer variant

Some sites also publish llms-full.txt, one file holding the full text of the docs. It is useful when a coding agent should load everything in one fetch. Keep it under a size an agent can reasonably read, and generate it from your docs source so it never goes stale.

Be honest about the benefit

Do not expect traffic from this file alone. Some developer tools and agents read it, and it costs an hour. Treat it as documentation for machines. The real gains come from crawlable pages and clear writing, see how to get cited.

Keep it accurate

Every link must work and every summary must match the page. Add a check to CI that fetches each link and fails on an error status. A stale llms.txt that points to dead pages is worse than none. For the repo-level equivalent aimed at coding agents, see docs and READMEs for agents.

Generate it from your docs

Do not hand-maintain the list. If your docs live in a folder of Markdown files, write a small script that reads each file's title and first line and emits the links. Run it in the build, commit the output or publish it with the site, and fail the build when a link target is missing. That keeps the file honest with almost no ongoing effort, and it is the same idea as a sitemap generated at build time.

Questions people ask

Do ChatGPT or Google use llms.txt?

No major vendor has said it is a ranking signal. Some tools and agents do read it, so it is low cost and low risk to add.

Where does the file go?

At the root of your domain, so it loads at /llms.txt, served as plain text or Markdown.
