How to make your GitHub README easy for AI to find and cite

Your README is often the first thing an assistant reads about your project. Structure it so a model can say what the project does, how to install it and where to go next.

Put a one-sentence description at the top, then install and usage commands that run as written, then a short list of features and limits. For many open-source projects the README is the page an AI assistant reads first, so it needs to stand alone.

Open with what it is

The first lines decide whether a model, or a person, understands the project. Name it, say what it does and who it is for in one sentence. Avoid a logo wall and badges before the first sentence of text.

# acme-invoice

acme-invoice is a Node library that creates PDF invoices from JSON.

Give a copy-paste quick start

Show the install command and the smallest working example. Check it on a clean machine. Agents copy these blocks, so a broken command spreads fast.

npm install acme-invoice
node -e "require('acme-invoice').render({to:'Ann'})"

Use clear section headings

  • Install
  • Usage
  • Configuration
  • Limitations
  • Contributing and licence

Standard headings help both humans and parsers locate facts. State the licence and the supported runtime versions explicitly.

Score it

README Score gives a GitHub README a score out of 100, lists the sections found and missing, and suggests a fix for each. It uses no AI, so the same README always gets the same score, which makes it easy to use as a checklist and to rerun after edits. It has an MCP endpoint at https://readme.flisk.si/mcp too.

Help the repo as a whole

Fill in the repository description and topics on GitHub, since they are short, high-signal text. Link to your docs site from the README and make sure the docs are crawlable, see the citation checklist. For coding agents specifically, add an AGENTS.md as covered in docs and READMEs for agents.

Common mistakes

  • A README that is only a logo and a link to a docs site that blocks bots.
  • Install commands that assume a tool you never mention.
  • Screenshots that carry the only explanation, since a model cannot read an image.
  • No licence and no statement of what is not supported.

Fix these four and rerun the score. Each is quick, and together they cover most of what an assistant needs to describe your project correctly.

Keep the README honest about maturity. If the project is early or unmaintained, say so near the top. Models repeat what they read, and an accurate status line saves users from a wrong recommendation and saves you from avoidable issues.

Questions people ask

Do AI tools read the README?

Many assistants and coding agents read it when they look at a repository, so a clear README improves what they can say about your project.

Is a high score the goal?

No, a useful README is the goal. The score is a quick checklist of common sections, not a measure of quality.
