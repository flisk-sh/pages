Agent memory and context engineering

How to summarize conversation history for an LLM agent

Rolling summaries keep long sessions cheap, but they lose detail if done carelessly. A prompt, a data structure and the rules that keep exact facts safe.

Keep the last few turns verbatim, replace older turns with a short summary, and store exact values (IDs, paths, decisions) in a separate list that is never summarized. Run the compaction when history crosses a token threshold, not on every turn.

The shape of the history

Split history into three parts that you rebuild on each call:

  1. A pinned facts list: exact, structured, small.
  2. A rolling summary: prose about what happened so far.
  3. The recent turns: the last N messages as they were.

Only the summary is lossy. The other two stay exact.

A summarization prompt that works

You compress an agent session. Input: the previous summary and new turns.
Output JSON with two keys:
"summary": under 200 words. What the user wants, what was done, what is in progress.
"facts": list of exact strings to keep verbatim (IDs, file paths, URLs,
         numbers, decisions, user corrections, error messages).
Do not invent. If unsure whether something matters, put it in "facts".

Asking for JSON lets you store the two parts separately. See prompts and structured outputs for getting that output reliably.

The loop

def maybe_compact(state, count_tokens, limit=8000, keep=6):
    if count_tokens(state.messages) < limit:
        return state
    old, recent = state.messages[:-keep], state.messages[-keep:]
    out = llm_json(SUMMARY_PROMPT, prev=state.summary, turns=old)
    state.summary = out["summary"]
    state.facts = dedupe(state.facts + out["facts"])
    state.messages = recent
    return state

Never cut in the middle of a tool call and its result. Keep each pair together or the model sees a result with no question.

What to check

  • Compare answers before and after compaction on a few saved sessions. If a question that worked now fails, a fact was lost.
  • Watch the summary size. If it grows every round, tighten the word limit.
  • Summaries of summaries drift. Recompute from the facts list and the latest turns when something looks off.

When not to summarize

For short tasks, skip it. For tasks where exact wording matters (legal text, code diffs), keep the original in storage and let the agent fetch it by reference instead of summarizing it. Summaries are for conversation flow, not for source material.

See also managing the context window for the wider budget.

A small test you can run today

Pick three saved sessions of at least 30 turns. For each, write five questions whose answers appear only in the early turns, such as "which file did we decide to rename?". Ask the agent those questions with the full history, then with the compacted version. Count the matches. If compaction loses more than one answer in five, move more items into the facts list or raise the summary limit. Keep this as a regression test and rerun it each time you change the summary prompt.

Questions people ask

Which model should write the summaries?

A smaller, cheaper model is often enough for compaction, but test it on your own sessions. If key facts go missing, use the same model as the agent.

How often should I summarize?

Only when history passes a token threshold. Summarizing every turn costs extra calls and compounds information loss.
