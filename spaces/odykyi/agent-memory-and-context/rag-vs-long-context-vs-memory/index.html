Agent memory and context engineering

RAG vs long context vs memory: which should you use?

Three ways to give a model information: retrieve it per question, paste it all in, or store it as notes. A decision guide with the trade-offs of each.

Paste it all in when the material is small and the question needs all of it. Use retrieval (RAG) when the material is large and each question needs only a few parts. Use memory when the information is about the user or project and must persist across sessions.

The three options

OptionWhat it isBest for
Long contextPut the documents directly in the promptOne-off tasks on a few documents
RAGSearch an index, load the top hitsLarge, changing knowledge bases
MemorySmall notes saved from past sessionsPreferences, decisions, project facts

When long context is right

Summarizing one report, reviewing one contract, comparing two files. You skip the index, chunking and ranking, and nothing is missed because of a bad retrieval. The costs are tokens on every call and weaker attention on very long inputs. If you ask many questions of the same document, use provider-side prompt caching where it is offered, and check your provider's docs for the rules.

When RAG is right

A help center, a codebase, thousands of pages. The material does not fit, or paying for it on each call makes no sense. The risks are in retrieval: wrong chunks, missing chunks, stale index. Measure it with a set of real questions and the expected source for each. A starting point is RAG and vector databases locally.

When memory is right

The agent should remember that this user prefers short answers, that this project deploys to staging, that the last attempt failed for a known reason. These are small and personal, so they do not belong in a shared document index. See short-term vs long-term memory.

Combine them, with rules

Real agents use all three: memory notes first, retrieved passages for the question, and the current files in full. Give each a labelled section and a token budget, and tell the model which source wins in a conflict. Usually that is the freshest, most specific one: the current file beats a note, and a note beats a general document.

Do not start with the most complex option. Try long context on a small sample first. It often answers whether you need the rest.

A simple decision flow

  1. Does all the material fit comfortably, and does the question need most of it? Use long context.
  2. Is it large, but each question touches a few parts? Use RAG.
  3. Is it about this user or project, small and durable? Use memory.
  4. Not sure? Build the simplest one, run 20 real questions, and look at the failures before adding anything.

Write down the answer in your repo so the next person does not redo the debate.

Questions people ask

Is RAG dead now that context windows are large?

No. Retrieval still wins on cost, speed and scale for large or changing collections. Long context wins when the material is small and fully relevant.

Can memory replace RAG?

Not for large documents. Memory holds short facts about users and projects. Reference material needs an index.
