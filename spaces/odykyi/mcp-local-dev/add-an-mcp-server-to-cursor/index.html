How to add an MCP server to Cursor (local and remote)

Cursor reads MCP servers from a small JSON file. The only tricky part is the working directory, because that file has no cwd field.

To add an MCP server to Cursor, put an entry under mcpServers in .cursor/mcp.json in your project (or ~/.cursor/mcp.json for every project). Use command and args for a local stdio server, or a url for a server that listens on HTTP. Restart or refresh Cursor's MCP settings and check that the server shows as running.

Where the file lives

Cursor looks in two places. .cursor/mcp.json in the project holds servers for that repository and can be committed. ~/.cursor/mcp.json holds servers for every project on your machine. Put anything that depends on the repository (a path, a database, a tool that only makes sense here) in the project file, and general tools in the global one. Keep secrets out of a committed file; Cursor's stdio entries accept env and envFile for that.

A server that runs on a URL

If your server is a Streamable HTTP service, such as one running on localhost, give Cursor its address:

{
  "mcpServers": {
    "docs-mcp": { "url": "http://localhost:4000/mcp" }
  }
}

Test the URL with curl first, as described in building an MCP server locally. If tools/list works from curl and not from Cursor, the problem is in the client's settings, not your server. For a server run by Flisk, take the address from flisk networks; the route has the shape http://api.<project>.localhost/api/<name>/mcp. Flisk's own notes say a real Cursor connection to that name has not been tried, so if the name does not resolve in Cursor, use the address that flisk networks shows.

A server Cursor starts itself

A stdio server is a command Cursor launches. The documented fields are type, command, args, env and envFile. There is no cwd, so a server that depends on the project folder must set it inside the command. This is how Flisk's own control plane is wired so it finds the project:

{
  "mcpServers": {
    "flisk": {
      "type": "stdio",
      "command": "sh",
      "args": ["-c", "cd \"${workspaceFolder}\" && exec flisk mcp"]
    }
  }
}

${workspaceFolder} is the folder that holds .cursor/mcp.json. Using sh -c with exec keeps the server as the process Cursor talks to, so stdin and stdout still reach it. On Windows you will need a different shell form.

The Flisk shortcut

If you only want Flisk's tools in Cursor, you do not have to write the file:

flisk connect cursor --dry-run
flisk connect cursor

This creates .cursor/mcp.json with a flisk entry (merging into the file if it exists) and writes the Flisk skills into .agents/skills/, which Cursor reads, along with AGENTS.md. Use --global to write to ~/.cursor/mcp.json instead, without the skills. Open the folder in Cursor and the server appears in the MCP settings. Flisk also publishes a one-click link on its docs page, which is another way to add the same stdio entry.

Check that it works

  • Open Cursor's MCP settings and look for the server and a tool count. A red or empty entry means the process did not start or did not speak MCP.
  • Run the exact command and args in a terminal. A stdio server waits silently for input. That is normal. An immediate error is the real problem.
  • Ask the agent to call one tool by name, then look at the server's own log to see the request arrive.

Pitfalls

  • Cursor's PATH. A desktop app may not see the same PATH as your shell. If flisk or npx is not found, use an absolute path to the binary.
  • Too many tools. Every connected server adds tool descriptions to the model's context. Connect only what the repository needs, and remove servers you tested once.
  • Changed tool lists. After you add or rename a tool, toggle the server off and on in settings so Cursor reads the new list.
  • Project versus global. If a server appears twice or behaves oddly, check that the same name is not defined in both files.

To let the agent also run your stack, read letting your coding assistant start the stack. The same URL pattern works in Codex, covered in adding an MCP server to Codex.

For a server that runs inside a stack, the URL you paste into Cursor comes from the stack. Local URLs instead of ports explains where those host names come from.

One more habit helps: keep a short note in the repository of which servers the project expects, so a new teammate can add the same entries in a minute instead of rediscovering them. Commit the project file, and keep personal servers, the ones with your own tokens, in the global file where they are never shared by accident.

Questions people ask

Where does Cursor store MCP server configuration?

In .cursor/mcp.json inside a project for that repository only, or in ~/.cursor/mcp.json for every project.

Does Cursor's mcp.json have a working directory setting?

No. The documented stdio fields are type, command, args, env and envFile. Pin the folder by running a shell command that changes directory first, using ${workspaceFolder}.

What does flisk connect cursor write?

A flisk entry in .cursor/mcp.json and the Flisk skills in .agents/skills/. It merges with an existing file, and --dry-run shows the files without writing them.
