Windows and WSL local development

Run a multi-service app on Windows without Docker or WSL

Not every project needs containers. An API and a website that each start with one command can run on Windows with no Docker and no Linux.

On native Windows, Flisk can run an app whose services each declare a command in service.json. flisk up starts them as ordinary processes in dependency order, with no Docker, Tilt or WSL. Container stacks still need Ubuntu on WSL2, so this path is for simple apps such as an API plus a website plus maybe a worker.

The general approach

Without any tool, you open one terminal per service and start each by hand, or you write a PowerShell script or an npm script with a runner such as concurrently. That works, but you maintain start order, health waiting and log prefixes yourself, and every new teammate repeats the setup. A small manifest per service makes the layout explicit and lets one command do the rest. The same idea for other systems is in run local services without Docker.

Describe each service

Each service folder gets a service.json. For example, api/service.json:

{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "api",
  "appType": "backend",
  "command": "node server.js",
  "port": 4000,
  "healthCheckPath": "/health"
}

and web/service.json, which starts after the API and is told where to find it:

{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "web",
  "appType": "frontend",
  "command": "node server.js",
  "port": 3000,
  "dependsOn": ["api"],
  "env": { "API_URL": "http://localhost:4000" }
}

command is run from the service's own folder. Flisk passes port to the process as PORT, and waits for the health URL to answer before it starts anything that depends on the service. A service has one runtime source: a command, or a container, not both. A project cannot mix local-process services and container services yet.

Install and run

Install Flisk in PowerShell. The npm package needs Node.js 22.12 or newer:

npm install -g @flisk-sh/flisk
flisk --version

Preview first. The dry run lists the services, their commands and the start order, and starts nothing:

flisk up --dry-run

Then start for real from the project folder:

flisk up

Flisk starts api, waits until it is ready, starts web, prefixes each log line with the service name and prints http://localhost:<port> for each. Stop with Ctrl+C in that terminal, or run flisk down from another one. Logs are also written to .flisk/native/logs/<service>.log, and flisk logs --service api reads them. A process that exits is restarted after 1 second, then 2, 4 and 8; after five quick exits Flisk stops trying and says so.

Windows details that matter

  • The command runs through cmd.exe. Flisk runs the line with the platform shell, which on Windows is cmd.exe. Write commands that cmd understands: node server.js is fine, but PORT=4000 node server.js is bash syntax and does not set a variable in cmd. Use the port and env fields instead.
  • Stopping kills the tree. Flisk ends a service and everything it started with taskkill /T /F, because Windows has no process groups to signal.
  • Checks before start. It refuses to start if a command's program is not installed, a port is already in use (and names the holder), or two services share a port.
  • Doctor is cautious here. In the current source, flisk doctor on native Windows prints its Windows checks and then ends with a native Windows finding and a failing exit code, even for a local-process project. Read the individual lines instead of treating the exit code as pass or fail.
  • The demo. npx @flisk-sh/flisk demo on native Windows runs a small two-service demo this same way.

When to move to WSL2

Use Ubuntu on WSL2 when you need a database container, one gateway URL in front of every service, or the same image you deploy. Flisk has an unsupported FLISK_ALLOW_NATIVE_WINDOWS=1 switch that lets a container stack try anyway, but it is not a supported path. The Windows setup guide covers the WSL2 route, and the Docker integration guide covers its most common snag.

Next step: put the two service.json files in your repo, run flisk up --dry-run, and add the commands to your README so teammates can do the same.

Questions people ask

Can Flisk start a Docker stack on native Windows?

No. It refuses with a message pointing to Ubuntu on WSL2. Native Windows runs only services that declare a command, as local processes.

Why does PORT=4000 node server.js fail in my command?

On Windows the command runs through cmd.exe, which does not accept that bash syntax. Use the port and env fields of service.json.

Can I mix local processes and containers in one project?

Not yet. Flisk's docs say a project cannot mix both. Every service declares a command, or none does.
