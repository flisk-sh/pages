How to run Docker Engine in WSL2 without Docker Desktop

You can run containers on Windows with Docker Engine inside WSL2 and no Docker Desktop. It suits teams that cannot, or will not, license the desktop app.

You can run Docker Engine directly inside Ubuntu on WSL2: enable systemd in /etc/wsl.conf, install the engine from Docker's apt repository, add your user to the docker group and start the service. Containers then run entirely in Linux with no Docker Desktop, which also avoids its licence terms, but you lose its Windows GUI and its integration across distributions.

Why choose this

  • Licensing. Docker Desktop requires a paid subscription for larger companies. Docker Engine on Linux is free software.
  • One place. Everything lives in the distro: files, engine and tools. There is no socket bridge between Windows and Linux.
  • Scripts match servers. The setup is the same as on a Linux build agent.

The trade-off: you manage updates yourself, there is no GUI, and your other WSL distros do not get the engine unless you install it there too. For a comparison with Colima and Podman, see Docker Desktop vs Colima vs Podman.

Install it

  1. Remove the Desktop integration for this distro (Docker Desktop, Settings, Resources, WSL Integration), or uninstall Docker Desktop. Two engines in one distro cause confusing socket errors.
  2. Enable systemd. In Ubuntu, create or edit /etc/wsl.conf:
[boot]
systemd=true
  1. In PowerShell run wsl --shutdown, then reopen Ubuntu. Check with systemctl is-system-running.
  2. Install the engine. Follow Docker's current instructions for Ubuntu at docs.docker.com/engine/install/ubuntu, which add Docker's apt repository and install docker-ce, docker-ce-cli, containerd.io and the Compose and Buildx plugins. For a throwaway dev machine the convenience script is shorter, but read it before you run it:
curl -fsSL https://get.docker.com -o get-docker.sh
less get-docker.sh
sudo sh get-docker.sh
  1. Let your user run docker without sudo:
sudo usermod -aG docker $USER
newgrp docker
  1. Start it and test:
sudo systemctl enable --now docker
docker run --rm hello-world
docker compose version

Group membership gives root-equivalent power over the machine, which is normal for a developer VM but worth knowing.

Using it with Flisk

Flisk needs docker to answer in the environment where you run it, plus Tilt. It does not care which engine answers. Flisk's own WSL2 end-to-end tests run on Docker Engine installed inside the WSL2 distro, not Docker Desktop. Its docs say plainly that the recommended guide describes Docker Desktop integration and that the two paths are similar but not identical, so expect to read a few details yourself.

npm install -g @flisk-sh/flisk
flisk doctor

In WSL2, doctor's "Docker WSL integration" check passes when the docker command exists and the daemon answers from the distribution; it does not insist on Desktop. If it fails with "Docker does not answer from this WSL2 distribution", check systemctl status docker first, because the engine service is not running, rather than the Desktop settings the fix text mentions. Install Tilt in the same distro with the project's install script.

On Linux as a non-root user, the gateway cannot take port 80, so Flisk uses a port in the 8080 to 8180 range and prints URLs with the port. Use the printed URLs.

Pitfalls

  • systemd not running. If systemctl says it is not booted with systemd, the wsl.conf change was not applied. Run wsl --shutdown and try again, and check that your WSL is recent with wsl --update.
  • Engine does not start with the distro. With systemd enabled, systemctl enable docker handles it. Without systemd, you would start the daemon by hand each time, which is why we enable it.
  • Disk growth. Images pile up in the distro's virtual disk. See how to shrink it.
  • Corporate policy. Check that an engine in WSL is allowed on a managed laptop.

Next step: if you would rather keep Desktop, read turning on its WSL integration.

Questions people ask

Can I use Docker on Windows without Docker Desktop?

Yes. Install Docker Engine inside Ubuntu on WSL2, enable systemd, and add your user to the docker group.

Does Flisk work with Docker Engine in WSL2?

Flisk's own WSL2 CI runs on Docker Engine inside the distro. Its guide recommends Docker Desktop, and says the two paths are similar but not identical.

Why do I need systemd?

It lets the Docker service start with the distro and be managed with systemctl, so you do not launch the daemon by hand.
