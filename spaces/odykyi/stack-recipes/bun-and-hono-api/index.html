Bun and Hono API: local dev setup with live reload

Bun starts fast and has a built-in watcher, and Hono is a small router that fits it. This is the setup, with and without Flisk.

A Bun and Hono API needs very little: one file with a Hono app, a default export that gives Bun a port and a fetch handler, and bun run --watch src/index.ts for live reload. Flisk's default backend is exactly this combination, so flisk resource api writes a working service with health routes, tests and a lint config.

What you need for a good local loop

Four things make an API pleasant to develop. It restarts when you save. It reads its port from the environment, so a tool can assign it. It has a health route, so something can tell when it is ready. And it has a test command that you can run without starting a server. Bun gives you the first with --watch, and Hono's app.request() makes the last one easy, because you can call a route in a test without opening a socket.

The plain approach

bun init
bun add hono
// src/index.ts
import { Hono } from 'hono';

const app = new Hono();
app.get('/health', (c) => c.json({ status: 'ok' }));
app.get('/', (c) => c.json({ service: 'api' }));

const port = Number(process.env.PORT) || 3000;
export default { port, fetch: app.fetch };
bun run --watch src/index.ts

Bun reads the default export, starts the server, and restarts the process when an imported file changes. A test calls the app directly:

const res = await app.request('/health');
expect(res.status).toBe(200);

A route test with Vitest, which the scaffold already uses, stays small because it never opens a port:

import { describe, expect, it } from 'vitest';
import { app } from '../src/app';

describe('health', () => {
  it('answers 200', async () => {
    const res = await app.request('/health');
    expect(res.status).toBe(200);
  });
});

Export the Hono app from its own module so the test and the server entry file share it.

The Flisk way

Hono on Bun is the default, so the shortest command is:

npm install -g @flisk-sh/flisk
flisk resource api --stack app --yes
flisk up

The scaffold has these scripts in its package.json: dev runs bun run --watch src/index.ts, build runs tsc, start runs the compiled file with Bun, test runs Vitest, and lint runs Biome. It serves /health, /health/live, /health/ready and /. The port comes from PORT, with a fallback of 3000 when the variable is missing or invalid.

In Docker mode, flisk up runs the service in a container behind Traefik. Its service.json carries the dev command and the files to watch:

{
  "appName": "api",
  "appType": "backend",
  "healthCheckPath": "/health",
  "dev": {
    "command": "bun run dev",
    "watch": ["src/**/*"]
  }
}

Edit a file under src/ and the watcher picks it up. The URL is http://api.<project>.localhost/api/api for a service named api, so name your services after what they do (an orders-api becomes /api/orders). Run flisk networks to print the real URLs. Flisk removes the /api/<name> prefix before the request reaches Hono, so your routes stay at /health and /items.

If you do not want Docker, add --local:

flisk resource api --local --stack app --yes
flisk up

The manifest then has command: npm run dev and no Dockerfile. The dev script still calls Bun, so Bun must be installed on the machine.

Other Bun frameworks

If you prefer another router, the same command takes a framework. List the choices with the CLI and pick one:

flisk resource --frameworks --type backend
flisk resource api --framework elysia --stack app --yes

The choices are Hono, Express, Elysia, Fastify, h3, Koa and NestJS, all on Bun. A --framework cannot be combined with --language python, go, rust or node, because those have their own providers. See NestJS local dev for the one that adds the most structure.

Pitfalls

  • The Dockerfile in the resource folder is not what flisk up builds. Flisk builds a generated file under .autogenerated/. Do not expect changes to the folder's Dockerfile to change the dev image, and do not hand-edit generated files. If you need a custom image, use a bring-your-own resource.
  • Invalid PORT. The scaffold only accepts an integer from 1 to 65535. Anything else falls back to 3000, which can hide a misconfigured variable.
  • Watch does not see everything. --watch restarts for files in the import graph. A change to a JSON file read at runtime with fs will not trigger it.
  • Mixed runtimes. Do not combine a command service and a Dockerfile-built service in one project. Flisk reports MIXED_RUNTIME.

Questions people ask

How do I get live reload with Bun?

Run bun run --watch src/index.ts. Bun restarts the process when a file in the import graph changes. Use bun --hot if you want to reload code without restarting the process.

Is Hono the default Flisk backend?

Yes. flisk resource api with no flags creates a Bun and Hono service. Other frameworks like Express, Elysia, Fastify, h3, Koa and NestJS are chosen with --framework.

Does the Hono scaffold work without Docker?

Yes, with the --local flag it writes a service with command npm run dev and no Dockerfile. Bun must still be installed because the dev script uses it.
