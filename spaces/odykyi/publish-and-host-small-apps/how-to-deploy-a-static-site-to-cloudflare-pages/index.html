How to deploy a static site to Cloudflare Pages

Deploy a folder of static files to Cloudflare Pages with Wrangler, then connect Git for automatic builds and branch previews.

Run npx wrangler pages deploy ./dist --project-name my-site from your project. Wrangler asks you to log in the first time, creates the Pages project if it does not exist, and prints a pages.dev URL.

Build, then deploy

Build your site into a folder first. For plain HTML the folder is just where your index.html is.

npm run build
npx wrangler login
npx wrangler pages deploy ./dist --project-name my-site

Each deploy gets its own unique URL, and the latest one on the production branch is served at my-site.pages.dev.

Choose the production branch

Wrangler treats deploys from your current Git branch as previews unless it matches the project's production branch. To push to production from the CLI, pass the branch explicitly.

npx wrangler pages deploy ./dist --project-name my-site --branch main

Connect Git instead

In the Cloudflare dashboard you can connect a GitHub repository and set a build command and output folder, for example npm run build and dist. Every push then builds automatically, and pull requests get preview URLs. Use the CLI for quick deploys and Git for ongoing work. Mixing both on one project works but is easy to confuse.

Redirects and headers

Two plain-text files in the output folder control behaviour. A single-page app needs a rewrite so deep links load.

# _redirects
/*  /index.html  200
# _headers
/*
  X-Content-Type-Options: nosniff

Automate the deploy in CI

Once the manual deploy works, run it from a workflow so every push to the main branch publishes. Store a Cloudflare API token limited to editing Pages as a repository secret, plus your account ID.

- run: npx wrangler pages deploy dist --project-name my-site --branch main
  env:
    CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
    CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}

Do not use your global API key for this. A scoped token limits the damage if it leaks.

Before the first deploy, run ls dist and look at what will be uploaded. Remove anything that is not meant to be public, such as notes, backups or .env files. Wrangler uploads what is in the folder, so the folder is your allowlist.

Pitfalls

  • Deploying the project root instead of the build folder uploads source files, and may expose files you did not mean to publish.
  • Rewriting everything to index.html also catches missing assets and hides real 404s.
  • If you plan to add an API, read Workers for small apps before you pick a layout.

Questions people ask

Do I need a credit card for Cloudflare Pages?

Cloudflare's free plan covers static Pages projects. Check their current pricing page for limits on builds and requests.

How do I roll back a bad deploy?

In the dashboard open the project's deployments list and promote or roll back to an earlier deployment.

Try it

Put one page online in a minute.

Pages publishes an HTML or Markdown file to a free public link. It is public, so do not use it for anything private.

npx -y @flisk-sh/pages publish page.html --wait
