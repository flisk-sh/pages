How to serve a scikit-learn model with FastAPI locally

A model behind an HTTP endpoint is just a web service that loads a file. The details that bite are when you load it, which versions you pin and how callers know it is ready.

To serve a scikit-learn model with FastAPI, load the saved model once when the app starts (with a lifespan function), keep it in memory, and write a POST /predict endpoint that validates the input and calls predict. Do not load the file inside the endpoint: it would be read from disk on every request. Add a /ready route that fails until the model is loaded, so other services know when to call you.

The model file and the pins

A scikit-learn model saved with joblib is a pickle. Two consequences. First, load it only with the same scikit-learn version that saved it, otherwise you get warnings or wrong results. Pin the version in both the training and the serving environment. Second, never load a pickle from a source you do not trust: loading one can run code.

A small script makes a model for the example:

import joblib
from sklearn.datasets import load_iris
from sklearn.linear_model import LogisticRegression

X, y = load_iris(return_X_y=True)
model = LogisticRegression(max_iter=200).fit(X, y)
joblib.dump(model, "model.joblib")

The API

from contextlib import asynccontextmanager
from pathlib import Path

import joblib
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

MODEL_PATH = Path(__file__).parent / "model.joblib"
state: dict = {}


@asynccontextmanager
async def lifespan(app: FastAPI):
    state["model"] = joblib.load(MODEL_PATH)
    yield
    state.clear()


app = FastAPI(title="scorer", lifespan=lifespan)


class Features(BaseModel):
    values: list[float]


@app.get("/health")
def health():
    return {"status": "ok"}


@app.get("/ready")
def ready():
    if "model" not in state:
        raise HTTPException(status_code=503, detail="model not loaded")
    return {"status": "ready"}


@app.post("/predict")
def predict(features: Features):
    model = state["model"]
    if len(features.values) != model.n_features_in_:
        raise HTTPException(status_code=422, detail="wrong number of features")
    proba = model.predict_proba([features.values])[0]
    return {"label": int(proba.argmax()), "probability": float(proba.max())}

The route is a plain def, not async def: scikit-learn calls are blocking, and FastAPI runs a plain function in a thread pool, so one slow prediction does not freeze the event loop. Checking the feature count gives a clear 422 instead of a stack trace from deep inside the library. If the file is missing or broken, startup fails and you see the error at once, which is what you want in development.

The Flisk way

Scaffold a Python backend in a stack:

flisk resource scorer --type backend --language python --stack ml --yes

This creates services/ml/scorer with src/main.py (a FastAPI app with a /health route), a pyproject.toml with pinned fastapi and uvicorn, a test and a service.json whose dev command runs uvicorn with --reload. Do three things:

  1. Add "scikit-learn==..." and "joblib==..." to dependencies in pyproject.toml, with the versions you trained with.
  2. Replace the body of src/main.py with the code above and put model.joblib next to it. The generated pyproject.toml says that only dependencies are installed into the image and the source is synced for live reload, and service.json watches src/**/*.
  3. Keep "healthCheckPath": "/health" in service.json.
flisk config verify
flisk up ml
flisk status
flisk logs --service scorer --tail 50

flisk status prints the URL of the service. A request looks like this, with your real address:

curl -s -X POST "$SCORER_URL/predict" \
  -H "content-type: application/json" \
  -d '{"values": [5.1, 3.5, 1.4, 0.2]}'

If you do not want Docker for this service, --local scaffolds the same app as a local process: add --local to the flisk resource command, run pip install -e ".[dev]" in the service folder, and flisk up starts it with a command in service.json instead of a container. That is also the route when you want the model to use your Mac's GPU, because a container on macOS cannot reach it. A project cannot mix local processes and containers yet.

Pitfalls

  • Large models. A model of hundreds of megabytes should not be committed to Git or synced on every edit. Download it at startup from a model registry instead, see running training as a one-shot job for a registry flow.
  • Several workers. Each uvicorn worker loads its own copy. Two workers double the memory.
  • Input drift. Validate the number and the order of features. A model happily predicts on a shuffled input.

Questions people ask

Should I load the model inside the endpoint?

No. Load it once at startup and keep it in memory. Loading per request reads the file every time and makes each call slow.

Why use a plain def instead of async def for predict?

scikit-learn calls block the thread. FastAPI runs plain functions in a thread pool, so a slow prediction does not block other requests.

Is it safe to load any joblib file?

No. A joblib file is a pickle and can run code when loaded. Only load files you created or trust, with the same library versions.
