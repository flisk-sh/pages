How to keep Jupyter notebooks clean in Git

A notebook is JSON with your outputs inside. Without care, every run rewrites the file, diffs are unreadable and a data preview can reach the repository.

A .ipynb file stores code, outputs, images and execution counts in one JSON document, so a rerun changes hundreds of lines nobody wrote. There are two fixes. Strip outputs before they are committed with nbstripout, or keep the notebook as a plain Python file with jupytext and treat the .ipynb as a local artifact. Both can be set up in a few minutes, and neither depends on your editor.

Option 1: strip outputs with nbstripout

nbstripout is a Git filter. It removes outputs and execution counts when you commit, and leaves your working copy untouched, so you still see results locally.

pip install nbstripout
nbstripout --install

This writes a filter into the repository's .git/config and an entry into .git/info/attributes. Those two places are not shared, so every clone needs the install command. To make the rule travel with the repository, commit a .gitattributes file:

*.ipynb filter=nbstripout
*.ipynb diff=ipynb

and run nbstripout --install once per clone (put it in your setup script). Without the filter definition in the clone, the attributes file does nothing, and outputs get committed silently. Check that it works by committing a notebook you just ran and reading git diff --cached: you should see only your edits to code and markdown cells.

The second route is a pre-commit hook, which a team can share in a committed config file:

repos:
  - repo: https://github.com/kynan/nbstripout
    rev: 0.8.1
    hooks:
      - id: nbstripout

Pin rev to a release you have checked. After pre-commit install the hook strips outputs before each commit and fails the commit if it changed something, so you stage the clean file and commit again.

Option 2: pair the notebook with a Python file

jupytext keeps a text version of the notebook next to it, and the text file is what you review:

pip install jupytext
jupytext --set-formats ipynb,py:percent analysis.ipynb

The py:percent format marks cells with # %% lines, so the file is valid Python, diffs line by line and can be linted. When you save the notebook in Jupyter, both files update, and editing the .py file updates the notebook on reload. Then add *.ipynb to .gitignore and commit only the .py files. The cost is that notebooks with outputs are no longer in the repository, so nobody can read your results without running the code. If you want to share rendered results, publish them separately, for example as an exported HTML file.

Which one to pick

SituationUse
Notebooks are teaching material, readers want to see the shape of the codenbstripout
Notebooks are real code you review and testjupytext
Outputs are the deliverable, such as a reportKeep outputs and review them as a rendered file, not as a diff

Pitfalls

  • Data already in history. A preview of customer rows that was committed once stays in the history after you add a filter. Rewrite the history or rotate what leaked. A filter only stops new commits.
  • Secrets in cells. Stripping outputs does not remove a token you pasted into a code cell. Read keys from environment variables, as in JupyterLab next to your local database.
  • Merge conflicts. Two people editing one notebook still conflict in JSON. With jupytext they conflict in readable Python, which is far easier to resolve.
  • Metadata churn. Kernel names and Python versions in notebook metadata change between machines. Configure the tool to keep or drop metadata and apply it consistently.

Once the notebooks are clean, record experiment numbers in a tracker instead of in cell outputs, see running an MLflow tracking server locally. For analysis that has outgrown a notebook, see DuckDB and Parquet.

Questions people ask

Does nbstripout delete the outputs in my working notebook?

No. It removes them only from what is committed. Your local file keeps its outputs.

Why does nbstripout --install not apply for my teammates?

The filter is stored in each clone's local Git config. Every clone must run the install command, or you can use a shared pre-commit hook.

What is the jupytext percent format?

A plain Python file where lines starting with # %% mark cell boundaries. It diffs and lints like normal code.
