How to deploy a remote MCP server on Cloudflare Workers

Host an HTTP MCP server on Workers: what fits the runtime, how to keep state, how to store secrets and how to deploy with Wrangler.

A stateless MCP server that speaks Streamable HTTP fits well on Cloudflare Workers. Write a fetch handler, store secrets with wrangler secret put, and run npx wrangler deploy. Cloudflare also publishes agent and MCP helper libraries, so check their docs for the current recommended package before you hand-write the transport.

Decide if Workers fits

Workers run short-lived request handlers at the edge. That suits tools that call HTTP APIs, query a hosted database, or read from KV or D1. It suits poorly a tool that needs a long-running process, a big native dependency, or a local filesystem. For those, use a container host and read stdio vs Streamable HTTP first.

Remember the runtime has CPU time and memory limits that depend on your plan. Look at the current Workers limits page before you design long tool calls.

Set up the project

npm create cloudflare@latest my-mcp
cd my-mcp
npx wrangler dev

The wrangler.toml (or wrangler.jsonc) file names the Worker and binds resources:

name = "my-mcp"
main = "src/index.ts"
compatibility_date = "2026-11-01"

[[kv_namespaces]]
binding = "CACHE"
id = "YOUR_KV_ID"

Pick a compatibility_date that is today or recent, and keep it fixed until you test a newer one.

Handle the MCP endpoint

Route one path, such as /mcp, to your MCP handler, and reject everything else with 404. Check the token before parsing the body.

export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    if (url.pathname !== "/mcp") return new Response("Not found", { status: 404 });
    const auth = request.headers.get("authorization");
    if (auth !== "Bearer " + env.MCP_TOKEN)
      return new Response("Unauthorized", { status: 401,
        headers: { "WWW-Authenticate": "Bearer" } });
    return handleMcp(request, env); // your MCP SDK glue
  }
};

handleMcp is where your SDK or Cloudflare's helper library turns the request into a JSON-RPC response.

Store secrets and state correctly

  • Secrets: npx wrangler secret put MCP_TOKEN. Never put them in wrangler.toml.
  • Small shared data: KV for cached reads, D1 for relational data.
  • Per-session state: Workers instances do not share memory, so either stay stateless or use a Durable Object.

More patterns are in Cloudflare Workers for small apps.

Deploy and verify

npx wrangler deploy
curl -i https://my-mcp.YOUR-SUBDOMAIN.workers.dev/mcp

The unauthenticated call should return 401. Then connect the MCP Inspector with your token and call a tool. For a working example of remote MCP endpoints, Flisk publishes its Pages MCP at pages.flisk.si/mcp, which you can add to a client to see what a small hosted server feels like.

Questions people ask

Can a Worker keep an MCP session in memory?

Not reliably, because requests may run on different instances. Keep the server stateless or store session data in a Durable Object or external store.

Is there a free tier for this?

Cloudflare has a free Workers plan with limits that change over time. Check the current Workers pricing and limits pages before you rely on it.

Try it

Run an MCP server locally before you put it in front of users.

Flisk can scaffold an mcp service next to your database and agents, so you test the whole stack on your own machine first. It is a local development tool, not a production orchestrator.

flisk resource my-tools --type mcp
