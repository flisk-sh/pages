How to connect Claude Code to your local dev stack

Connecting Claude Code to a local stack means giving it a control plane, not just a shell. Here is the one-command setup and the manual steps behind it.

The quickest way to connect Claude Code to a Flisk project is to run flisk connect claude in the project folder. It writes a .mcp.json entry that starts flisk mcp (a stdio MCP server) and copies the Flisk skills into .claude/skills/. Start claude there, approve the project server, and check it with /mcp.

Two things people mean by this

"Connect an assistant to my local stack" can mean two different setups, and mixing them up wastes time.

  1. Control plane. The assistant gets tools to start, stop, inspect and debug the stack itself: check the machine, bring services up, read logs, restart one service. This is what flisk mcp provides.
  2. Your own tools. The assistant calls an MCP server that you built and that runs inside the stack, for example a server that queries your database. That is covered in the Claude Code testing guide.

This article is about the first one. Without any MCP server at all, Claude Code can already run shell commands, so you could simply tell it to run docker compose up and read the output. That works, and for a small project it is fine. A control plane helps when you want structured results (a service list, a readiness flag, a bounded log snapshot) instead of a model parsing terminal text, and when you want the same operations to be available to any MCP client.

The one-command setup

npm install -g @flisk-sh/flisk
cd my-project
flisk connect claude --dry-run
flisk connect claude

--dry-run prints what would be written and changes nothing. The real run merges into an existing .mcp.json (other servers stay), is safe to repeat, and reports a different existing flisk entry as kept unless you pass --force. The entry it writes is:

{ "mcpServers": { "flisk": { "command": "flisk", "args": ["mcp"] } } }

Run claude in the same folder. Claude Code asks you to approve a project-scoped server before using it. Then /mcp should list flisk as connected.

The manual way

Without flisk connect, from the project directory:

claude mcp add --scope local --transport stdio flisk -- flisk mcp
claude mcp add --scope project flisk -- flisk mcp

The first keeps the entry in your own Claude Code settings for this project. The second writes the shared .mcp.json. Pick one. For all your projects, use claude mcp add --scope user flisk -- flisk mcp.

What Claude Code can then do

The server exposes 24 tools. The ones you will use daily are doctor (what would stop a stack from starting), up (start detached), status (readiness and URLs), logs (a bounded snapshot), resource_restart and down. Try these prompts:

  • "Run Flisk doctor and tell me what would block startup. Do not start anything yet."
  • "Start the stack, then poll status until it is ready and give me the URLs."
  • "The api service is red. Read its logs and tell me why."

See letting your assistant start the stack for the safe order of calls and what each result means.

Pitfalls

  • Wrong working directory. Project tools read the folder the server was started in. If they answer Could not find project root, start Claude Code inside the project, or pass the absolute projectPath argument.
  • AGENTS.md versus CLAUDE.md. Claude Code reads AGENTS.md only when the project has no CLAUDE.md. If you have one, add the line @AGENTS.md to it so the instructions still apply. More in writing an AGENTS.md file.
  • up is not readiness. It returns when startup has begun. A first build can take minutes, so the assistant must check status before it says the stack is up.
  • Docker and Tilt. They are needed to start a container stack, not to connect the server or run doctor.

When not to bother

If you run one process with npm run dev, a control plane adds nothing. The value starts with several services, a database and a gateway, where "start it, tell me what is red" is more than one command. The server is a local process that Claude Code starts over stdio. Nothing listens on a port, and there is no hosted endpoint or account.

After the connection works, add instructions so the assistant behaves well in this repository. Start with a short AGENTS.md.

When you finish a session, stop what you started. Stop and clean up a local stack shows what each way of stopping removes.

Questions people ask

Does flisk connect claude need a Flisk project first?

No. It works in any folder. The project tools only work once the folder holds .flisk/project.json, but doctor runs without a project.

Where does flisk connect claude write its files?

It merges a flisk entry into .mcp.json and writes the Flisk skills into .claude/skills/. Use --dry-run to see the exact list before anything is written.

Can I connect Claude Code for all projects at once?

Yes. Run claude mcp add --scope user flisk -- flisk mcp. The project tools still need Claude Code to run inside a Flisk project, or the tools to receive a projectPath.
