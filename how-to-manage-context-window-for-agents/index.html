Agent memory and context engineering

How to manage the context window of an AI agent

A token budget, trimming of tool output, summaries and sub-tasks keep an agent inside its window. Concrete steps with a code sketch you can adapt.

Give every part of the prompt a token budget, trim tool output before it enters history, and compact old turns into a summary when you pass a threshold. That keeps an agent coherent over long sessions without paying for the whole history on every call.

Measure first

Count tokens for each part of the input: system prompt, tools, history, retrieved text. Use the tokenizer your provider documents, or the usage numbers returned with each response. Log them per call.

You will usually find one culprit: a tool that returns whole files, a verbose JSON blob, or a system prompt that grew over months.

Set a budget per section

SectionExample budget
System prompt and rules1,500 tokens
Tool definitions2,000 tokens
Retrieved notes3,000 tokens
Recent turns, verbatim6,000 tokens
Older turns, summarized1,500 tokens

The numbers are examples. Pick yours from your model's window and your latency target, and leave headroom for the reply.

Trim tool output at the door

The cheapest saving is not storing junk. Cut tool results before they join the history.

def clip(result, limit=4000):
    text = str(result)
    if len(text) <= limit:
        return text
    head, tail = text[: limit // 2], text[-limit // 4 :]
    return head + "\n...[clipped " + str(len(text) - limit) + " chars]...\n" + tail

Better still, make the tool smarter: return a count and the first 20 rows, with a parameter to page further.

Compact when you cross a threshold

When history passes, say, 70 percent of your budget, replace the oldest turns with a summary and keep the last few verbatim. Details of doing that well are in how to summarize conversation history.

Keep exact values (IDs, file paths, error messages) out of lossy summaries. Store them in a notes list instead.

Split big jobs

If one task needs more than the window can hold, split it. A sub-agent or a fresh call can read ten files and return a five-line answer, and only the answer enters the main context. This is often better than any compaction trick.

Pitfall: sub-tasks lose the parent's context. Pass them what they need explicitly, not "see above".

Pitfalls to watch

  • Budgets that only exist in a document. Enforce them in code and fail loudly or trim when a section goes over.
  • Counting characters instead of tokens. Code, JSON and non-English text tokenize very differently from plain English.
  • Forgetting the reply. Leave room for the model's output, or long answers get cut.
  • Trimming the wrong end. For logs the tail is usually the useful part, for documents the head. Pick per tool.

For a broader view of what belongs in the window at all, read what is context engineering.

Questions people ask

What happens when I exceed the context window?

Most APIs return an error, or silently truncate depending on the setup. Either way you lose control, so enforce your own limit below the model's maximum.

How many recent turns should I keep verbatim?

Start with the last 4 to 8 turns and adjust by testing. Keep more if the task needs exact wording from recent steps.
