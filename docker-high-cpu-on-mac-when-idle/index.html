Docker on Mac: speed and resources

Docker using high CPU on a Mac when nothing is running

The fans are loud and the stack looks idle. Start by asking Docker who is busy, because the answer is usually one container.

When Docker uses a lot of CPU on a Mac with nothing visibly running, one container or one file watcher is usually busy. Run docker stats to find it, then check for three causes: a file watcher that polls a bind mount, a container stuck in a restart loop, and a healthcheck that runs too often. Fixing that one container normally brings the whole VM back to idle.

Step 1: find the busy container

docker stats --no-stream --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}"

Sort by the CPU column. Values are per core, so 100% means one full core and a container can show 250%. Anything steady above a few percent while you do nothing deserves a look. If every container is near zero but the Mac is still hot, the cost is in the VM itself: file sharing activity or a very busy disk. Activity Monitor then shows a process such as com.apple.Virtualization.VirtualMachine (Apple's virtualization), qemu-system-aarch64 (QEMU) or Docker's own helper processes, as one large figure for the whole VM.

To see what a suspicious container does, list its processes and read its log tail:

docker top <container>
docker logs --tail 50 <container>

Cause 1: polling file watchers

Some tools cannot receive file change events across a bind mount and fall back to polling, which scans the folder every fraction of a second. Settings such as CHOKIDAR_USEPOLLING=true, webpack's watchOptions.poll or --poll flags turn this on. Polling a large tree over a shared mount is expensive. Fixes, in order of preference:

  • Stop mounting the whole project. Mount only source folders so the watcher has fewer files to scan. See why bind mounts are slow on Mac.
  • Exclude folders from the watcher: node_modules, .git and build output.
  • Raise the polling interval if you must poll, for example to one second.
  • Use a newer file sharing mode (VirtioFS), which delivers change events for many tools so polling is not needed.

Cause 2: a restart loop

docker ps -a --format "table {{.Names}}\t{{.Status}}"

A status like Restarting (1) 4 seconds ago, or an uptime that keeps resetting, means a process starts, fails and is started again. Each start can cost real CPU, such as a dependency install or a migration. Read the log of that container for the reason. The steps are in why a container keeps restarting.

Cause 3: a busy healthcheck or a busy loop

A healthcheck that runs every second and starts a heavy process, such as a full JVM or a Python interpreter, adds constant load across many containers. Raise the interval to something like 10 or 30 seconds for local work. A busy loop in your own code, for example a worker that polls a queue with no sleep, looks the same in docker stats, and only the log or a profile will tell.

What Flisk checks for you

The Flisk flisk doctor command has a Container Resource Health check. It samples the running containers of the project and flags any that use 90 percent or more of their memory limit while also using 80 percent or more CPU. The message describes the pattern as a boot time retry or download loop rather than a normal crash, and the fix text points you to the container's boot logs. The case that led to the check was a container that kept re-downloading a package on every start. The check needs the containers to be running and does not look at idle watchers.

flisk doctor
flisk status --unhealthy
flisk logs --unhealthy --tail 50

flisk status --unhealthy lists only services that are failing or still starting, and flisk logs --unhealthy prints their recent logs, so a restart loop shows up without reading every service. If you run services as plain local processes, docker stats does not see them. Use Activity Monitor, or top -o cpu in the terminal, for those.

Pitfalls

  • Judging by the Docker Desktop dashboard alone. It averages. Use docker stats for per container values.
  • Stopped but not removed. A stopped container uses no CPU, but a service that is only paused by a restart policy is still busy at each retry.
  • Emulation. An amd64 image on Apple Silicon burns more CPU for the same work. See slow amd64 images.
  • Leaving the VM on. A VM that stays up costs a little even when idle. Stop Docker or colima stop at the end of the day. Docker Desktop also has a Resource Saver mode that pauses the VM when it is unused.

When the CPU is calm, memory is the next thing to read: why Docker uses so much memory on Mac explains how to tell the VM's reservation from real container use.

Questions people ask

Why is Docker using CPU when no containers are running?

Check docker ps first. If nothing runs, the load is the VM or the Docker helper processes, and restarting Docker or stopping the Colima VM usually clears it.

What does 200% CPU mean in docker stats?

CPU is reported per core, so 200% means the container uses about two full cores.

How do I find a polling file watcher?

Look in the container's environment and config for options such as CHOKIDAR_USEPOLLING or a poll setting, and check whether the container's CPU drops when you stop the bind mount.
