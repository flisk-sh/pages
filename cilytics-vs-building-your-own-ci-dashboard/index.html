Cilytics vs Building Your Own CI Dashboard: How to Choose

An honest comparison of a free public CI dashboard and a custom one, with the limits of each and the cases where building your own is the right call.

Use a ready-made dashboard such as Cilytics when your repositories are public and the standard views are enough, and build your own when you need private repos, custom metrics or alerts. Both read the same GitHub API, so the data is the same; the difference is who maintains it.

What Cilytics gives you

Cilytics is a public CI health dashboard for GitHub that needs no account. It shows the whole org, or any public repo with ?repo=owner/name. Its sections are a trend of pass rate, red workflows, per-repo pass rate and median run time, flaky workflows, slow workflows with median and p90, an open-source hygiene score out of 100 and an AI-readiness view.

Its limits, stated plainly

  • It reads default-branch runs only.
  • It looks at the last 100 runs per workflow.
  • It is an hourly snapshot, not live.
  • Repos inactive for 90 days are left out.

These are sensible defaults for a health overview, but they rule out some uses.

When to use it

  • You want a quick look at an open-source project or a competitor's repo health.
  • You are starting out and want a first picture before investing in tooling.
  • You want a shared link for a weekly review; see running a weekly CI review.

A starting point is in building a CI dashboard with GitHub Actions.

Use both

The two are not exclusive. Many teams use a public view as a sanity check and keep a private pipeline for the numbers they alert on. Whichever you pick, agree the definitions first (red, flaky, slow) so numbers match between tools. For the metrics themselves, see CI metrics that matter.

Cost of ownership

The real cost of your own dashboard is not writing it; it is keeping it working. Tokens expire, the API changes, repos are renamed, a script breaks silently and the page shows last month's data. Budget a few hours a quarter for upkeep, and give the dashboard an owner like any other service.

The real cost of a shared public dashboard is the questions it cannot answer. Make a list of the three decisions you want the data to inform, then check whether the public view supports them. If yes, use it and move on. If not, you have the requirements for your own build.

Either way, resist adding metrics for their own sake. Pass rate, red list, flaky list and slow list cover most needs. A dashboard with twelve charts and no owner is worse than a short list reviewed every week. Choose the smallest tool that supports your weekly review and extend it only when a decision needs more data.

Questions people ask

Does Cilytics need access to my repos?

No account is needed. It reads the GitHub API for public data, so it covers public repositories and orgs.

Is Cilytics a monitoring tool?

No. It is an hourly snapshot for review, not live alerting. Use your CI's notifications for alerts.
