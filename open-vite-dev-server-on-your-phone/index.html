How to open your Vite dev server on your phone

The page loads on the laptop and times out on the phone. Four things stand in the way: the bind address, the address you type, the API URL and the firewall.

To open a Vite dev server on a phone, start it listening on the network instead of only on loopback (vite --host), find the laptop's address on the Wi-Fi, and open http://<that address>:5173 on the phone. If the page loads but its data does not, the API URL still says localhost, and on the phone localhost means the phone itself.

1. Listen on the network

By default Vite listens on localhost, which only the same machine can reach. Either pass the flag or set it in the config:

npx vite --host

// or vite.config.ts
export default defineConfig({ server: { host: true } });

host: true means all addresses (0.0.0.0). Vite then prints a Network: line with the address to use. For Next.js the equivalent is next dev -H 0.0.0.0.

This exposes the dev server to everyone on the same network, and a dev server serves your source files. Use it on a network you trust, and not on a café Wi-Fi.

2. Use the laptop's address

The phone must be on the same Wi-Fi network as the laptop, and not on a guest network that isolates clients. Take the address from Vite's Network: line, or find it yourself:

ipconfig getifaddr en0    # macOS, Wi-Fi
hostname -I               # Linux

Type http://192.168.1.23:5173 (with your address) into the phone's browser. Some routers also resolve your-laptop.local through mDNS, which survives address changes. Try it and fall back to the number.

3. Fix the API URL

This is the step people miss. If the frontend calls http://localhost:4000/api, the phone sends that to itself and fails. Two ways out:

  • Use a relative URL and a dev server proxy. The frontend calls /api/... on the address it was loaded from, and the Vite proxy forwards it to the API on the laptop. The proxy runs on the laptop, so localhost:4000 is right there. See how to proxy API requests in the Vite dev server. Nothing in the phone's requests mentions a port other than the one you typed.
  • Put the laptop's address in the env variable. Set VITE_API_URL=http://192.168.1.23:4000 and start the API on the network too. Then the API's CORS rule must allow the origin http://192.168.1.23:5173. See how to set the API URL in Vite with env variables.

The proxy is the smaller change, and it avoids CORS entirely.

4. The firewall and the host check

If the phone still times out, the laptop's firewall is blocking incoming connections to Node or the port. On macOS the first run prompts to allow incoming connections for node. If you dismissed it, allow it in System Settings, Network, Firewall. If the page loads but Vite answers Blocked request. This host is not allowed, you reached it through a name that is not allowed. An IP address is, and a custom name needs server.allowedHosts.

What Flisk does here

A frontend scaffolded with flisk resource web --type frontend --local writes host: 'localhost' in its Vite config, so it is not reachable from the phone as generated. Change that line to host: true and keep the rest. The scaffold also writes a proxy for /api to the API's port, so the data path from the phone works through the laptop without further changes. strictPort stays on, which keeps the address you typed on the phone valid across restarts. Flisk's own check of a service uses localhost on the laptop, so opening it to the network does not affect it.

In Docker mode, the frontend is served by Traefik on app.<project>.localhost. That name resolves to loopback on the laptop only, so it does not work from a phone. I did not find a Flisk option that publishes the Traefik routes on the network, so for a phone test use the local-process route above.

Pitfalls

  • HTTPS-only features. Service workers, the camera, geolocation and clipboard APIs need a secure context. http://192.168.x.x is not one, so these fail on the phone even though the page loads. Use a tunnel with HTTPS for them.
  • The address changes. DHCP can give the laptop a new address after a restart. If the phone suddenly stops, check the address first.
  • Hot reload over the network. If the page loads but never updates, see Vite HMR WebSocket failures.

Questions people ask

What does vite --host do?

It makes the dev server listen on all network addresses, not only on localhost, so another device on the same network can open it.

Why does my phone show the page but no data?

The frontend still calls localhost for the API, and on the phone that is the phone itself. Use a relative URL with a dev server proxy, or the laptop's address.

How do I start Next.js so a phone can reach it?

Run next dev -H 0.0.0.0, then open the laptop's address and port from the phone.
