Open models and self-hosted inference

Self-hosting an LLM vs a hosted API: cost and trade-offs

When running your own model makes sense, and when a hosted endpoint is cheaper, faster and less work. A decision guide with the costs people forget.

Use a hosted API unless you have a specific reason to self-host: privacy rules, steady high volume, offline use, or the need to control the model. For low or spiky traffic, a hosted API is almost always cheaper and less work than running a GPU.

Reasons to self-host

  • Data must not leave your network because of policy or contract.
  • Steady high volume that keeps a GPU busy most of the day.
  • Offline or edge use with no reliable internet.
  • Control over the exact model version, fine-tuning, and no surprise deprecations.
  • Learning and experiments where cost per call is irrelevant.

Be honest about which of these applies to you. "Privacy" is a real reason when a contract demands it, and a weak one when the data is harmless. Many hosted providers also offer data handling terms, so read them before you assume you must run your own.

Reasons to use a hosted API

  • You pay per use, not for an idle GPU.
  • No drivers, no out-of-memory errors, no on-call.
  • The largest and best models are often available only hosted.
  • Traffic spikes are the provider's problem.

Open models are also available as hosted endpoints, which gives you open weights without running the hardware. For a free way to try one, Flisk Inference is an open-beta model API with a coding-focused open model called Flisk Wolf. You sign in with GitHub and there is a daily request limit.

The costs people forget

  • GPU hours while idle, which is most hours for small apps.
  • Engineering time for setup, upgrades and monitoring.
  • Redundancy: one GPU is one point of failure.
  • Electricity and cooling if you own the hardware.

A rough check: take your monthly tokens, price them at the hosted rate, and compare against the monthly cost of the GPU plus your time. Use current prices from the providers, not numbers from an article.

Utilisation is the number that decides the comparison. A GPU that is busy ten percent of the time costs ten times more per request than one that is busy all the time. Small apps rarely keep a GPU busy.

A middle route

Run a small open model locally for development and low-risk tasks, and a hosted model for hard ones. Route by task, as covered in cutting LLM cost and latency. Keep the client OpenAI-compatible so switching is a config change (how to serve one).

Decide with a test, not a hunch

Quality matters as much as price. Run your real prompts on both options and compare (test before you switch).

Questions people ask

Is self-hosting always cheaper at scale?

Not always. It can be cheaper when a GPU stays busy, but you take on operations work. Compare real numbers, including staff time.

Can I self-host for privacy and still use hosted models for other tasks?

Yes. Route sensitive requests to your own server and the rest to a hosted API, with the same client code.

Try a hosted open model

Call an open model through an API before you buy a GPU.
