Docker on Mac: speed and resources

Why Docker uses so much memory on a Mac and how to see it

The number in Activity Monitor is the VM, not your containers. Reading the right number tells you whether to cut services or just resize the VM.

Docker looks memory hungry on a Mac because every container runs inside one Linux VM, and macOS shows that VM as a single large process. Its size is mostly the memory you allowed it, plus the cache the Linux kernel inside it keeps. To see what your containers really use, read docker stats, then decide whether to remove services or lower the VM's limit.

Three different numbers

NumberWhere you see itWhat it means
VM sizeDocker settings, docker info, colima listThe ceiling you gave the VM
VM process memoryActivity MonitorWhat macOS has handed to the VM so far, including the Linux page cache
Container memorydocker statsWhat each container's processes use, and a limit if one is set

The three are different on purpose. A container can use 300 MB while the VM process shows several gigabytes, because the Linux kernel inside the VM keeps files it has read as cache, and the VM does not always give that memory back to macOS quickly.

Read the real numbers

docker info --format '{{.MemTotal}}'
docker stats --no-stream --format "table {{.Name}}\t{{.MemUsage}}\t{{.MemPerc}}"

The first command prints the memory of the VM in bytes. The second shows each container's use against its limit; with no limit set, the percentage is against the whole VM. Add up the MemUsage column. If the total is much smaller than the VM size and Activity Monitor still shows a large process, the difference is mostly cache and reservation, not your services.

To look inside the VM, run a memory report there. With Colima, colima ssh -- free -m prints used, free and cache memory. The line to read is "available": that is memory the kernel can free on demand. Docker Desktop does not give you a shell into its VM as easily, so use docker stats and the settings page.

Reduce it in the right order

  1. Start fewer containers. This saves the most. The services you are not editing do not need to run.
  2. Lower the VM memory to what the measured total needs plus 25 to 30 percent. A smaller ceiling is a smaller worst case for macOS.
  3. Set limits on heavy containers so one service cannot take the whole VM. A database or a search engine with no limit grows into the free memory.
  4. Stop the VM when you finish. A running VM keeps its memory. In Colima, colima stop releases it. Docker Desktop has a Resource Saver mode that reduces use when it is idle.

The sizing method is in how much memory and CPU to give Docker.

What Flisk adds

Flisk gives you two ways to start less. flisk up --only api starts the services you name plus what they depend on, and flisk up --profile <name> adds services that have that name in their profiles list. Check what is already running before you start more:

flisk status
flisk up --dry-run --only api

--dry-run shows what would be started without starting it. See start only the services you need.

A project whose services all declare a command runs as local processes with no Docker VM at all, which removes the reservation entirely. That is a choice for the whole project, because a service built from a Dockerfile cannot run next to command services. A database or cache image can run next to them, started with docker run, so the VM then only holds that one container. The trade is covered in run natively or in Docker on a Mac. Flisk does not publish a safe service count for a given RAM size, so measure your own stack.

Pitfalls

  • Treating cache as a leak. Cache is reclaimed when something needs it. Look at "available", not "free".
  • Setting the VM too small. If containers are killed with exit code 137, you went too far. Raise memory a step.
  • Counting only containers. Build steps run in the same VM and can use more memory than the running services.
  • Forgetting a second runtime. Docker Desktop and Colima can both be running, each with its own VM. Check docker context ls and Activity Monitor.

If after all this the numbers still do not fit your laptop, the honest options are a smaller slice of the system, native processes for some services, or more RAM. Disk behaves in a similar way to memory in a VM, and the same "inside versus outside" confusion applies, as described in Docker disk full.

Questions people ask

Why does Activity Monitor show Docker using so much memory?

It shows the whole Linux VM as one process. That includes the memory you allowed it and the kernel's file cache, not only what containers actively use.

How do I see memory per container?

Run docker stats --no-stream. The MemUsage column is per container, and MemPerc is against the container's limit or the VM when no limit is set.

Does Docker give memory back to macOS?

Only slowly and not fully in many setups. Stopping the VM, for example with colima stop, releases it for sure.
