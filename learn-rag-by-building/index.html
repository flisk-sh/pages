Learn RAG by building: a document Q&A app, step by step

Build retrieval-augmented generation from scratch: chunk text, embed it, search by similarity, and answer with citations. Then measure whether it is any good.

RAG means retrieving relevant text from your documents and putting it in the prompt, so the model answers from facts you supplied. Build it in four steps: split documents into chunks, embed and store them, retrieve the top matches for a question, and ask the model to answer using only those chunks.

Step 1: chunk the documents

Split text into pieces of a few hundred words, with a little overlap so sentences are not cut from their context. Split on headings when you can; it keeps ideas together. Store each chunk with its source file and position, because you will need them for citations.

Step 2: embed and store

An embedding model turns text into a vector so similar meanings are close together. With Ollama you can run an embedding model locally; check the Ollama library for a current one. A simple store is a list in memory or a SQLite table for a first version, and a vector database later:

import numpy as np
from openai import OpenAI
c = OpenAI(base_url="http://localhost:11434/v1", api_key="local")

def embed(texts):
    r = c.embeddings.create(model="nomic-embed-text", input=texts)
    return np.array([d.embedding for d in r.data])

chunks = ["...", "..."]          # your text pieces
vecs = embed(chunks)

def top_k(q, k=4):
    qv = embed([q])[0]
    sims = vecs @ qv / (np.linalg.norm(vecs, axis=1) * np.linalg.norm(qv))
    return [chunks[i] for i in sims.argsort()[::-1][:k]]

Step 3: answer with the context

def answer(q):
    ctx = "\n\n".join(f"[{i+1}] {t}" for i, t in enumerate(top_k(q)))
    msgs = [
      {"role": "system", "content": "Answer only from the sources. Cite as [n]. If the sources do not contain the answer, say you do not know."},
      {"role": "user", "content": f"Sources:\n{ctx}\n\nQuestion: {q}"},
    ]
    return c.chat.completions.create(model="llama3.2", messages=msgs, temperature=0).choices[0].message.content

The line "say you do not know" is the most valuable one. Without it the model fills gaps with plausible text.

Step 4: measure it

Write twenty questions with known answers and note which chunk contains each. Check two things separately: did retrieval return the right chunk (retrieval recall), and did the answer use it correctly (answer quality). Most RAG problems are retrieval problems, so fix chunk size, overlap and the number of results first. See learn evals first and RAG and vector databases locally.

When not to use RAG

If your whole corpus fits in the context window and is read rarely, just paste it in. If questions need exact lookups, such as order numbers, use a normal database query. RAG is for fuzzy questions over text that is too large to paste. Start with the simplest thing that works, then add a vector database when the list in memory is no longer enough.

Questions people ask

How big should chunks be?

A few hundred words is a common starting point. Test two or three sizes on your own questions and keep the one that retrieves best.

Do I need a vector database?

Not for a small corpus. A list in memory or a SQLite table works until you have many thousands of chunks.
