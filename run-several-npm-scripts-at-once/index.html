How to run several npm scripts at once (API, web, worker)

npm run dev only starts one thing. Here are the ways to start three, from a one-line script to a manifest per service.

To run several npm scripts at once, use a small runner: concurrently, npm-run-all2 (run-p), or pnpm -r --parallel in a workspace. The shell trick npm run a & npm run b works on Mac and Linux but leaves orphan processes behind, so use it only for quick tests.

Option 1: concurrently

This is the most common answer, and it is a good one for two or three processes.

npm install -D concurrently
{
  "scripts": {
    "dev": "concurrently -k -n api,web,worker -c blue,green,yellow \"npm:dev:api\" \"npm:dev:web\" \"npm:dev:worker\"",
    "dev:api": "node --watch api/server.js",
    "dev:web": "vite web",
    "dev:worker": "node --watch worker/index.js"
  }
}

-n prefixes each line with a name, -c colors the prefixes, and -k kills all processes when one exits, which stops a half-running stack. The npm:dev:api shorthand runs the script with that name.

Option 2: npm-run-all2 or workspace commands

run-p from npm-run-all2 runs scripts in parallel with run-p dev:*, which picks every script that starts with dev:. In a pnpm workspace, pnpm -r --parallel dev runs the dev script in every package at once. npm's npm run dev --workspaces --if-present runs them one after the other, and since a dev server never exits, the second one never starts. Use a runner for parallel work.

What these runners do not do

  • Ordering. The web app starts at the same time as the API and may show errors until the API is up.
  • Readiness. They know that a process started, not that it is answering.
  • Restart policy. With -k one crash stops everything. Without it, a crashed process stays dead while the others run.
  • Per-service config. Ports and env vars live in several scripts and .env files.

For two services these gaps are acceptable. With five or more, they cost time.

Option 3: one manifest per service with Flisk

Give each part a service.json with a command. Flisk starts them as local processes, in order, with no Docker:

{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "web",
  "appType": "frontend",
  "command": "npm run dev",
  "port": 3000,
  "dependsOn": ["api"],
  "env": { "API_URL": "http://localhost:4000" }
}

The API manifest has "command": "node --watch server.js", "port": 4000 and a healthCheckPath such as /health. A worker can be a third manifest with "appType": "worker", no port, and "dependsOn": ["api"] if it needs the API.

flisk up --dry-run   # shows services, commands and start order
flisk up             # starts them; Ctrl+C stops them all
flisk status
flisk logs --service api --tail 50
flisk down

Flisk waits for each service to be ready before it starts the ones that depend on it (up to 60 seconds per service), prefixes every log line with the service name, restarts a crashed process after 1, 2, 4 and 8 seconds, and refuses to start when a port is taken or a program is missing. To start only part of the stack, flisk up --only web starts web and what it depends on. The full flow is in running services without Docker, and the ordering rules are in service startup order.

The cost is a file per service and one more tool to install. If a single script with concurrently does the job, keep it. Move to manifests when you need ordering, health waits or one stack that every teammate starts the same way.

Pitfalls

  • Two services on one port. Give each a unique port and read it from PORT.
  • Interleaved logs hide errors. Always name the prefixes. Search by name when something fails.
  • Windows quoting. Escaped double quotes inside package.json scripts are the portable form. Avoid single quotes.
  • Shutdown. If a process ignores SIGTERM, the port stays busy. See graceful shutdown for a dev server.

Next step

Questions people ask

How do I run two npm scripts in parallel?

Install concurrently and run it with both scripts, for example concurrently with the two scripts as separate quoted arguments. Or use run-p from npm-run-all2.

Why does npm run dev --workspaces not start every server?

It runs the workspaces one after another. A dev server never exits, so the next one never starts. Use a parallel runner.

Can Flisk start my API before my frontend?

Yes. Put the API name in dependsOn of the frontend service.json. Flisk waits until the API is ready, then starts the frontend.
