Make Your Repo Ready for Coding Agents

How to Structure a Repo So Agents Find the Right Code

Clear names, small files, a short repo map and explicit boundaries help a coding agent open the right file first instead of reading half the codebase.

Agents navigate by searching names and reading files, so a repo with predictable names, small modules and a short map in AGENTS.md is easier for them to change correctly. The same habits help new hires.

Name things for search

An agent usually searches for a word before it opens a file. Give functions and files names that match how people describe them. invoice-pdf-renderer.ts is findable; utils2.ts is not. Avoid reusing one generic name in many folders, because every search returns twenty hits.

Keep files and functions small

A 3,000-line file forces the agent to load a lot of text to change one function, and edits to it collide with other changes. Split by responsibility. You do not need a strict line limit, but if a file keeps growing, that is the signal.

Put the tests next to the code

When a test sits beside the module it covers, or follows one clear naming rule such as foo.test.ts for foo.ts, the agent finds it without help. State the rule in AGENTS.md in one line.

Write a short map

A directory listing with one sentence per folder saves many tool calls.

## Layout
src/api/      route handlers
src/domain/   business rules, no I/O
src/db/       queries and migrations
tests/e2e/    slow browser tests, run in CI only

Keep it to the top two levels. Deep maps go stale. See how to write an AGENTS.md for the full file.

Make boundaries explicit

If the domain layer must not import from the web layer, enforce it with a lint rule or an import-boundary tool, not with a sentence. Agents follow checks they can run far better than conventions they have to infer. For large repositories, also see monorepo CI for keeping checks scoped to the folder that changed.

Small changes with big payoff

You can improve agent navigation in an afternoon without moving a single module. Rename the worst files, such as helpers.ts and misc.py, to say what they hold. Add a one-line comment at the top of confusing modules saying what they are for and what they must not do. Delete dead code and old experiments, since an agent will happily read and imitate them.

Add a docs/ page for any concept that takes more than a minute to explain, such as the order lifecycle or the permission model, and link it from AGENTS.md by path. Agents read linked files when told where they are. Finally, keep one obvious example of each pattern: one route handler written the way you want all of them written, one test written the way you want all tests written. Agents copy what they find, so a clean example gets copied and a messy one gets copied too.

Questions people ask

Should I restructure my repo just for agents?

No. Make small changes that also help people: better names, a map and clearer test locations. A big reorganisation is rarely worth it for this alone.

Do comments help agents?

Short comments explaining why a surprising choice was made help. Comments that restate the code add noise.
